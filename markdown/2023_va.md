### Overview
Borderlands has an already well defined visual style. With Tiny Tinas Wonderlands, the vfx team were tasked with evolving those familiar effects into the fantasy realm in addition to guns and explosions.

### Content Summary
[TLDR]
通过建立风格指南与远程协作机制，在《小缇娜》中成功融合魔幻风格与原作美术基调。

[Background]
Gearbox 团队在制作这款《Borderlands》外传时，面临美术风格大改和全员远程开发的棘手问题。作者以首席视觉特效人员身份，复盘了如何在没有线下沟通的情况下，从零构建出一套既符合 IP 调性又有新意的魔法特效体系。

[Recaps]
先说团队这块，既然是远程作业，最怕的就是大家各玩各的瞎指挥。Gearbox 搞了每天早上的站会和双周的大评审，逼着大家把想法摆出来碰撞，这才保住了创意不跑偏。视觉上他们有个顿悟时刻，发现魔法得是夸张的剪影配上真实的质感，颜色还得亮堂、动起来带劲。为了不让不同人做出来的特效像个拼盘，他们定了一套视觉特效 (VFX) 风格指南 (Style Guide)，死磕一致性，这招对远程队特管用，保证了画面不乱。

再说这魔法到底咋分的，这里面门道不少。小缇娜自带的“创世之力”跟普通法术是分开的，像是她特有的“爆破”或者传送功能。其中灵魂能量 (Soul Energy) 负责复活和死亡特效，甚至替代了以前那种过于血腥的设定；创造魔法里有个叫魔法结构器 (Magistruct) 的东西，是用珍珠色调实现的，能凭空变东西或者瞬间传送；而反派用的则是紫色的虚空魔法 (Void Magic)，看着就邪门。玩家在游戏里用的那些火球冰冻啥的属于“世界内部魔法”，归角色自己控制，跟小缇娜没关系，这种界限划得很清，避免混淆。

最后讲玩法落地，这游戏直接把法师技能当手雷使，算是个大动作。每个法术手里都有个符文印记 (Sigil) 当作枪口，配合角色的手势动画，让玩家一眼就知道是放火还是放电。核心思路就是用鲜明的颜色和形状元素区分属性，既保留了 Borderlands 一贯的粗犷美术，又能让玩家在战斗中迅速识别技能效果，不至于看花眼。这一套下来，不仅解决了技术难题，还让美术风格真正服务于战斗体验，这才是老手该学的地方。

### Overview


### Content Summary
[TLDR]
VFX 设计绝非单纯的美术展示，必须紧扣玩法反馈与叙事氛围，团队协作才是核心生产力。

[Background]
在《Callisto Protocol》的高压开发环境下，创作者面临远程协作与恐怖战斗氛围难以平衡的痛点。这篇总结适合想做特效的玩家和开发者，分享如何用现成工具解决视觉效果与性能、玩法的实际冲突问题。

[Recaps]
这次分享的核心其实就是别光顾着“整活”，特效服务的是玩法。团队没用啥黑科技，主要还是图个方便招人，最终定在 虚幻引擎 4 (Unreal Engine 4) 上。特效方面放弃了旧版粒子系统 (Cascade)，转投更灵活且适合远程协作的 Niagara 系统 (Niagara)。这玩意儿最大的好处就是参数化，不用写代码也能改颜色大小，给设计师省了不少事，虽然学习曲线有点陡，但真香。

武器这块儿，特么教训不少。最开始电棍打环境能穿模，后来才发现是碰撞检测 (Collision) 没做好。作者通过建立数据表 (Data Table) 把不同材质（肉、金属、泥土）的撞击声音和火花对上了，这才有了那种痛快的打击感。还有枪口闪光 (Muzzle Flash) 的设计，最初为了科幻感做得太花哨，结果玩家根本看不清敌人在哪，最后不得不砍回实用风格。这就提醒咱们，别让用户被特效闪瞎了眼，画面再帅也得让位给视野清晰。

至于恐怖氛围和环境互动，体积雾 (Volumetrics) 是个好东西但很吃性能。为了省钱和优化，他们用了局部体积雾配合灯光技巧，既保留了幽闭恐惧感，又没让显卡爆缸。血腥场面也是，通过蓝图 (Blueprint) 系统直接挂钩动画事件，断肢掉血瞬间触发对应特效库，极大提升了制作效率。总之，千万别闷头画图，多跟策划聊，原型做出来再沟通，不然返工起来哭都来不及。

## Using Vertices Over Pixels: Achieving Cartoon Graphics on Standalone VR
- **Speaker:** Stefan Hell (Salmi Games)
- **Duration:** 25 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1029404
- **Slide Page:** https://www.gdcvault.com/play/1028884
- **Custom ID:** 1029404

### Overview


### Content Summary
[TLDR]
为了在 Meta Quest 上跑卡通风，放弃后期特效，靠把模型拆成三层并在顶点层面错位堆叠来画出清晰线条。

[Background]
Salmi Games 做 VR 射击游戏时，发现 Quest One 性能捉襟见肘，无法运行常规的后期处理管线，但又要实现类似 Borderlands 的低多边形漫画风格。

[Recaps]
这次分享主要解决一个问题：如何在性能极差的 Mobile VR 硬件上画出锐利的卡通线条？传统做法是用 后期处理 (Post Processing) 检测深度差，或者让美术手画贴图，但这俩要么太占 GPU 资源，要么太费人力。既然 Quest One 这种设备连简单的深度通道都不能开，那就只能另辟蹊径，直接把活儿扔给图形渲染管线的更前端去干。

他们的核心骚操作是“顶点置换”，也就是不通过像素计算，而是直接在 顶点着色器 (Vertex Shader) 层面动手脚。简单来说，就是把一个模型通过离线工具切成三张皮：一层向外扩的轮廓，一层向内缩产生缝隙的内线，还有原本身子。这三层叠在一起，缝隙自然就透出了黑线。关键在于利用模型的 切线向量 (Tangent Vector) 来定义挤压方向，保证不管模型多大，线条比例都对。

跑到游戏引擎里运行时，程序会根据玩家远近自动调整线条宽度，模拟真实透视感。这里有个坑叫 贴面冲突 (Z-Fighting)，就是两层皮贴太近会闪烁，解决办法是在裁剪空间 (Clip Space) 把内外层推远一点，肉眼看不出，但能避免穿帮。这样做的好处是兼容标准的 多重采样抗锯齿 (MSAA)，画面更干净，甚至还能批量渲染不同物体。

最后吐槽一下缺点，这种方法会让 顶点数 (Vertices) 增加约 65%，建模要仔细，而且模型互相穿插的时候容易穿模。但对于预算有限的独立团队来说，这是在不牺牲画质的前提下，对低端机能做出的极致压榨。如果你也是做 VR 或者低端机型的，这个思路非常值得参考。

## LIGHTSPEED STUDIOS Developer Summit: Exploring the Technical Arts in the Development of UNDAWN (Presented by LIGHTSPEED STUDIOS)
- **Speaker:** Joshua Yu, Leon Wei (LIGHTSPEED STUDIOS, LIGHTSPEED STUDIOS)
- **Duration:** 46 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1029050
- **Slide Page:** https://www.gdcvault.com/play/1028771
- **Custom ID:** 1029050

### Overview


### Content Summary
[TLDR]
移动端开世界生存 MMO 怎么活？光遇工作室分享 GPU 换 CPU 算力的技巧，搞定水面、建筑和动态光照，性能画质双平衡。

[Background]
想在手机上跑 UE4 级的大地图 MMO，硬件限制就是天堑。这次光遇的技术大佬们摊牌了，专门聊聊怎么在移动端把水面、建筑和光照做到极致而不爆表，给同行避坑参考。

[Recaps]
移动端跑大地图最头疼的就是性能预算。水面渲染这块，他们没用 CPU 密集的 FFT，而是靠投影网格加 4 层 Gerstner Waves（格斯特纳波浪）在 Vertex Shader（顶点着色器）里直接算位移。最硬核的是解决了水面透明问题，因为资源不够没法用昂贵的 顺序独立透明度 (OIT)，只能利用水网格屏幕空间顺序不变的特性，搞了个原语 ID 排序加上深度写入来欺骗 深度测试 (Depth Test)。远处水面抖动是因为顶点密度衰减，他们改用虚拟相机投影矩阵重新分配顶点密度，海边浪花碰撞则靠顶视深度纹理解决，最终单 Pass 就能搞定通透透明的海面。

建筑表现全靠“抠”出来的性能。外墙材质复用率极高，16 个纹理块能组合出上百栋楼，材料 ID 直接编码进 Vertex Color（顶点颜色）属性里，配合动态 UV 方案，极大减少了三角形数量和 绘制调用 (Draw Calls)。室内场景则是 动态烘焙 (Baking) 的杰作，把环境光、间接光和人工光源分别烘焙进一张 RGBA 图的四个通道，实时混合计算，既省了显存又适应了游戏内的日夜变化。

VFX 特效有个叫 Vertex Magics（顶点魔法）的方案。以前物体动画变换都在 CPU 跑，手机上太累，现在直接把变换数据预烘焙进 Vertex Animation Texture（顶点动画纹理），所有计算甩锅给 GPU。就连刚体破碎这种重活也这么搞，在 Houdini 算完物理后把数据存进 HDR 纹理。甚至镜头光晕 (Lens Flare) 都不用 CPU 光线追踪，直接用深度缓冲做遮挡检测，节省了开销让特效更丝滑。

引擎团队重点分享了动态世界的全局光照 (Global Illumination, GI)。玩家随时建房，传统静态光照贴图不行，他们搞了个 Progressive Irradiance Probes（渐进辐照度探针）系统。把复杂模型简化成色块盒子来渲染 G-buffer（G 缓冲），大幅降低 GPU 负载。针对漏光问题，独创了 Probe Tag（探针标签），通过俯视图深度判断内外区域。这套系统在低端安卓机上也能每秒生成 300 个探针，让玩家造房子时立刻看到光影变化，体验非常丝滑。

## Kung-fu and Speed Painting: Sifu's Art Direction and World Building Approach
- **Speaker:** Paul-Emile Boucher (Sloclap)
- **Duration:** 61 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1029204
- **Slide Page:** https://www.gdcvault.com/play/1028808
- **Custom ID:** 1029204

### Overview


### Content Summary
[TLDR]
Sifu 用“五行 + 道德”定骨架，速涂 + 风格化渲染，把电影感硬塞进 3D 关卡。

[Background]
小团队做项目最怕参考图太多太杂，最后做出来的东西四不像。这场分享专门讲怎么把零散的灵感串成统一的世界观，并如何在主机平台上做出像电影一样的 3D 质感。适合所有在纠结美术风格统一性、或是想提升关卡叙事能力的开发者。

[Recaps]
做世界观别光看参考图，得找根儿。他们深挖了功夫哲学，搞了一套“五行 (Wuxing)”配“儒家思想 (Confucian Values)"的叠加表来管事儿。游戏五个关卡对应五行元素和五种道德缺失，比如贫民窟变竹林，酒吧变火村，从真实城市逐渐过渡到神话战场。这种结构化方法解决了参考图太乱没法统一的问题，让环境随剧情变强，但也导致制作成本大增，有些原本设计的 BOSS 阶段为了保帧率只能砍掉。

美术风格上，核心就是“意在笔先”。他们大量使用“速涂 (Speed Painting)"，不求细节丰富，每一笔都得有目的。进了引擎后，故意打破真实物理渲染 (PBR) 的逻辑。模型造型走硬朗风，少平滑处理，材质上靠调整法线 (Normals) 或者直接用顶点颜色 (Vertex Color) 混合图形纹理，尽量不用复杂贴图。这样既省性能，又能保留一种粗粝的手绘感，画面看起来更干净有力。

最后定妆靠“修图”。直接把 3D 截图丢进 Photoshop 改色叫“覆盖绘画 (Paint Overs)"，以此做色彩脚本 (Color Scripts) 把控全局情绪。灯光方面，因为要在 PS4 上跑 60 帧，没法依赖实时全局光照，就靠静态光照加后期调色假作动态，连闪烁的霓虹灯都可能是贴图。这种折腾下来，虽然流程麻烦点，但确实做出了那种“不像 3D 的 3D 游戏”的独特味道。

## How To Make AAA-Looking Games Like 'A Plague Tale: Requiem' with 20 Artists
- **Speaker:** Loc Paulus (Asobo Studio)
- **Duration:** 49 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1029162
- **Slide Page:** https://www.gdcvault.com/play/1028794
- **Custom ID:** 1029162

### Overview


### Content Summary
[TLDR]
小团队做 AAA 画质核心在于资深多面手、高效工作流与“消除 3D 感”的艺术理念。

[Background]
Asobo 工作室分享如何用 20 人团队做出《瘟疫传说：安魂曲》的 AAA 级画面，解决了人手少预算有限的痛点，适合中小团队借鉴。

[Recaps]
首先得夸夸他们的组建模式。主创 Loic 强调，20 人的艺术团队里全是老江湖，平均工龄 15 年以上。大家别想着一专一能，必须当多面手。比如环境美术不光建模贴图，还得负责打光和 过场动画 (Cinematics)。还有一群叫“跨职能艺术家”的初级员工（Transverse Artists），谁缺人手就去哪帮忙，既能干活又能学艺，这才是培养新人的正道，避免了让大佬们陷在培训琐事里。每个关卡由“章节团队”（Chapter Team）承包，两人一设计师，迭代极快。

技术流方面，他们坚决不外包模型，省了沟通成本。为了快，直接走中模（Mid Poly）路线，不折腾高模（High Poly）烘焙，直接用自动 UV (UV Mapping)，材质全靠 MegaScan 搭配照片。这招内存省得飞起，改图也方便。引擎是他们自己研发的，好处是编辑器能实时预览改动，不用老重载场景。地形生成、雾效这些定制功能也是专门给项目组开的后门，效率杠杠的。遇到难题就找引擎组定制需求，比通用引擎灵活多了。

最后是艺术审美这块，核心就一个词：“消除 3D 感”（Effacer la trois D）。选地方选法国家乡，找经典油画当参考，让景色像画一样。具体操作就是注重轮廓剪影、地面细节和光照氛围，别让玩家觉得这是堆出来的模型。小细节决定大体验，比如树枝、石头的位置都有讲究。只要流程干净，优化自然就好。简单说就是少花时间抠高模，多花时间琢磨怎么让场景更像电影镜头，视觉重点放在叙事而非单纯的数量上。

## Squeezing Meta Quest 2 with Unreal Engine: A Tech Art Talk
- **Speaker:** Adam Andrzejczak (Black Drakkar Games)
- **Duration:** 49 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1029313
- **Slide Page:** https://www.gdcvault.com/play/1028856
- **Custom ID:** 1029313

### Overview


### Content Summary
[TLDR]
Meta Quest 2 画质优化核心在于牺牲性能预算换取稳定帧率，通过压缩材质通道、合并网格和“伪造”光照来实现。

[Background]
演讲者分享了在 Quest 2 平台开发 VR 游戏时的技术美术经验。主要解决移动端 VR 硬件受限下的画质与性能平衡问题，适合对 VR 开发感兴趣的开发者。

[Recaps]
开篇就泼冷水，说别迷信官方提供的虚幻引擎 (Unreal Engine) 分支样本，全是坑，不如直接用标准版。Meta Quest 2 这种移动 VR 算力有限，想稳跑 72 帧，绘制调用 (Draw Call) 最好控制在 200 以内，单帧三角形 (Triangle) 别超 50 万。既然硬件锁死，不如换个思路搞关卡设计，比如让大场景背景变成静态网格，只保留玩家可走的边缘区域，参考《Vader Immortal》的做法就很香。

材质优化才是精髓，得学会“抠门”。常规做法是把法线贴图 (Normal Map) 信息存单独纹理，建议把所有用到的信息塞进两个纹理的通道里，比如反照率 (Albedo) 和粗糙度一起打包，这样能省大量采样。还有金属质感太费劲就造假，用数学计算模拟高光；环境光遮蔽 (Ambient Occlusion) 直接烘焙进颜色通道；Quest 上自发光 (Emissive) 不好使，还得手动画梯度；甚至可以把粗糙度 (Roughness) 通道砍了，靠阴影蒙皮来补细节。

模型管理也要狠心，静态物能合并就合并，能用的实例化 (Instancing) 别开多份。动态光效不用原生光照，全用着色器 (Shader) 算出的伪光源加贴图遮罩替代，效率巨高。调试阶段强烈推荐 RenderDoc 工具，能直接抓显卡数据看指令复杂度。虽然有个叫 SpaceWarp 的功能能提升帧率，但跟手离得近就会穿帮，还是用注视点渲染 (Foveation) 更实在，反正别为了画质牺牲流畅度。

### Content Summary

[Background]
动捕匹配 (Motion Matching) 技术虽强，但落地极难。EA 资深开发分享五年经验，解决角色动作生硬、状态跳转卡顿痛点，适合动画与引擎开发人员参考避坑。

[Recaps]
家人们，简单说，别把这技术当只会走路的工具。为啥它能搞定复杂的键盘操作？因为每秒都在算账，看当前姿态特征 (Pose Features) 和轨迹特征 (Trajectory Features) 跟库里哪一帧最像，成本最低的直接接上去。但这玩意儿不能只用来挪位置，我们现在的做法是把它玩出花。比如在非移动环节也设个匹配节点 (Match Node)，进去了就查库找最佳动作播到底；或者搞个门控节点 (Gate Node)，没查到够好的绝不放行，这样就不容易出那种瞬移或者卡住的问题。要是遇到需要根据血量、AI 状态选动画这种事儿，纯物理不行怎么办？这时候就得请出上下文数据库 (Context Database)，先筛一波符合条件的素材池，再让动作匹配在里面挑细枝末节，物理属性和游戏逻辑这就打通了。

最后还得提一下调试工具和细节调优。根运动权重 (Root Motion Weight) 这玩意儿很有意思，值设为 0 就是全靠物理跑，稳但看着假；设为 1 就是全靠动画带动画，帅但容易飘。中间调个 0.5 甚至动态调整，急转弯时拉高点，正常跑着压低，手感立马不一样。再说调试，没个好用的工具瞎蒙肯定不行。咱们的调试面板能看实时成本拆解、候选帧列表，还能回放刚才的输入日志。哪怕你忘了咋复现的 bug，有了录制回放功能就能随时重演检查修改效果，这才是能保证技术真正落地的保障。

### Overview


### Content Summary
[TLDR]
腾讯光速工作室分享了这套虚幻引擎水插件，用“动静分离”策略实现跨平台水面仿真，兼顾移动端性能与高画质需求。

[Background]
传统水面要么死板要么太吃显卡，跨平台太难。这篇演讲主要展示如何用一套统一架构解决大世界水面在不同设备上的渲染与物理模拟难题。

[Recaps]
这次讲座的核心在于那个叫光子水系统 (Photon Water System) 的内网插件。物理模拟上，作者没全硬刚实时流体，而是离线用 晶格玻尔兹曼方法 (Lattice-Boltzmann Method) 烘焙固定的 流场图 (Flow Map)，这样既有真实水流方向又稳定。到了实时运行阶段，才上基于 高度场 (Height-field) 的 浅水方程 (Shallow Water Equation) 来做波动。遇到瀑布或断崖这种地形断裂，系统会自动把网格数据转成 粒子 (Particle) 下落，再重新合并回网格，实现了无缝过渡。

渲染管线这边更是把复杂功能拆开搞。先是用 分形布朗运动 (FBM) 生成 屏幕空间 (Screen Space) 的波纹细节，再通过 虚拟纹理 (Virtual Texture) 管理海量海图，避免加载卡顿。针对不同水域用了不同策略：河流湖泊用 连续动态层级细节 (CDLOD) 管理模型密度，近距离看大海怕 拉伸变形，他们就加了 自适应细分 (Adaptive Subdivision) 算法，只细化镜头中心区域，既省显存又保持细节。

除了逻辑，还有不少实用的优化小技巧。比如泡沫生成是靠 速度梯度 (Velocity Gradient) 判断，不用额外解复杂方程；利用 共享内存 (Shared Memory) 优化 GPU 读取；甚至教人用除以零技巧来裁剪网格边缘。他们还专门做了个轻量级表面波模拟适配手机端，PS5 跑两千分辨率的大世界水体也不卡。虽然目前主要针对 UE 引擎，但这套思路对于需要跨平台的大项目绝对有参考价值。

这场演讲的核心其实就是聊“声音怎么变得更立体”。以前玩 2D 游戏，声音就是屏幕前的两根喇叭响，或者戴个耳机瞎凑合，很难分清方向。到了 VR 和 AR 这种扩展现实 (Extended Reality) 时代，因为设备要轻便省电，没法接大音箱，只能靠头戴耳机输出独立的左右耳信号，这就要求**双耳音频 (Binaural Audio)** 必须做得非常逼真。演讲者提到一个关键技术叫 **全景声 (Ambisonics)**，它能把复杂的声场压缩成数据流，再转回耳机播放，效率高又省资源，是目前实现 **空间音频 (Spatial Audio)** 的主流路子。

从技术发展来看，这个领域也不是凭空来的。早先是干巴巴的直出声，后来为了模拟环境，引入了 **混响 (Reverb)**，让声音听起来像是有房间回声，再发展到能动态计算玩家在不同房间移动时的音效变化。Magic Leap 的引擎架构其实跟传统的游戏混音台很像，并没有完全颠覆，关键在于优化总线，保证不丢信息的同时还能扛住高性能渲染。毕竟这些头显设备电池有限，跑不动的话机器很快就烫手，所以代码效率至关重要。

不过现在最大的坑还是在 AR 这块。真正的 AR 不仅要有虚拟声音，还得把现实世界的声音（比如真人的说话声）混进来，两者要是没有统一的声学特征，听起来就会像隔着两层皮，特别出戏。微软和其他大厂正在研究物理声学模拟来解决这个问题。另外，即便是在纯 VR 里，**双耳音频 (Binaural Audio)** 也有缺陷，比如在正前方容易出现“声音绕过头顶”的定位误差。解决这个通常需要用到个性化的 **头相关传输函数 (Head Related Transfer Functions, HRTF)**，但目前还在完善阶段。未来的元宇宙演出，需要行业制定通用标准，让不同公司的内容能像拼积木一样无缝协作。

[Recaps]
这场干货主要是教大家怎么用虚幻引擎 (Unreal Engine) 里的 Niagara 系统，去搞定那种经典的图形学“障眼法”。核心是生成一种叫松弛锥步映射 (Relaxed Cone Step Mapping) 的特殊纹理，用来替代传统的视差遮挡映射 (Parallax Occlusion Mapping)。简单说，就是个平面四边形，靠着像素着色器 (Pixel Shader) 偷偷计算深度值，骗过摄像机眼睛看着像有凹凸，实际上并没有细分几何体 (Tessellated Geometry)，省资源还能防闪烁。

以前的 Tech Artist 想干这事，通常得写 C++ 配合计算着色器 (Compute Shader)，编译器设置、路径配置一堆麻烦事。现在有了 Niagara 这种节点工具，直接在编辑器里画逻辑就行。大家可以用编辑器实用工具组件 (Editor Utility Widgets) 做个界面，把高度图拖进去，后台跑 GPU 计算 (GPU Compute) 自动生成预处理的圆锥步长图。这样运行时材质只需采样，无需现场算，效率拉满，甚至能对接蓝图 (Blueprints) 做自动化打包。

演讲里花了大量篇幅讲怎么提速，因为暴力算法太慢。作者试了不同方案，比如把逐行扫描改成螺旋式扫描纹理，利用纹理缓存 (Texture Cache) 减少显存延迟；还有关键的“早退机制”，算着算着发现距离已经足够小就直接 break 跳出循环。最后发现，显卡其实不怕分支判断，合理的分支反而更快。从几十秒优化到几秒，这经验绝对是实打实的。

总结一下，别觉得图形学编程高不可攀，NVIDIA 当年的 GPU Gems 书籍里全是免费干货。多参考别人已有的成果，哪怕是用 Houdini 验证后再搬进 UE 也一样。Niagara 越来越强，未来肯定会有更多类似 CUDA 的功能加入。各位老哥有空多上手试试，这种把纸面理论落地成生产工具的过程，才是最锻炼人的。

[Recaps]

很多人以为做世界观就是拿笔乱涂，其实核心是定规矩。拳头专门有个跨项目的中央组，叫 Worldbuilding Team (世界观建设团队)，干了十年才攒出这套家底。早年他们的 Cinematic (CG 过场视频) 全是技能演示，被内部戏称“打架色情片”，玩家只记得操作，记不住剧情，最后决定必须跳出这个怪圈，先建立一套能通用的视觉规范。

以皮尔特沃夫为例，他们差点“翻车”。刚开始想做通用的未来科幻风，结果被毙掉说太普通。后来他们抓住“进步”这个词，结合了 Art Deco (装饰艺术风格) 的美学，设计了特定的黄金比例和机械结构。为了验证方案，他们专门画了张标志性的“皮城大门”概念图，这就是所谓的 Proof of Concept (验证原型)，确认风格没问题后，才把这套 Visual Library (视觉资料库) 分发给制作人员。

最后说说合作模式。拳头虽然给了大量指南，但没死板限制合作方，而是相信 Fortiche 这样的动画公司能在框架内自由发挥。他们甚至在公司内部设了一个写着“推倒重来”的红按钮，随时准备推翻不合理的设计。这种敢于否定前期成果、不断迭代的创作态度，才是能让游戏世界观比单纯的数据表更有生命力的根本原因。

- **Speaker:** Chris Landreth (JALI Research)

- **Category:** Animation Summit
- **Video Page:** https://www.gdcvault.com/play/1028944

### Overview


### Content Summary
[TLDR]
面部动画的核心不是嘴唇同步，而是基于肌肉解剖与真实观察的情绪传递，微妙克制往往比夸张表演更具感染力。

[Background]
很多动画师容易陷入只盯着嘴型匹配的误区，导致角色看着假。这位从 Maya 早期团队出来的大佬，结合自家 Jali 工具经验，想把“面部表演”的底层逻辑掰开揉碎讲透，专治各种面瘫感，适合所有想做逼真角色的老铁参考。

[Recaps]
这哥们开讲前先摆个事实：咱们大脑里有个专门识脸的硬装模块，叫梭状回 (Fusiform Gyrus)，进化论逼着人类得擅长看脸识人。所以学动画第一步不是摸电脑，是拿笔去画真人的头，练的是“重新观看”的能力。别觉得脸很简单，嘴巴张开其实是三维空间里的马鞍形状，正面侧面看都不一样，不把这个几何关系搞清楚，做出来的东西肯定飘。

接着他搬出了行业的金标准，面部动作编码系统 (Facial Action Coding System)。简单说，脸上几十块肌肉就是乐谱上的音符，或者像字母表一样，叫动作单元 (Action Units)。比如皱眉那个沟沟，在瑞典叫“十一号”，是皱眉肌 (Corrugator muscle) 干的事。想表现愤怒，光动眉毛不行，还得配合法令纹加深；想表现悲伤，最绝的是嘴角上扬但下巴凸起，那是颏肌 (Mentalis) 在捣乱，这种矛盾组合才是真实情绪，纯微笑反而假。

他还特别科普了怎么分辨真笑假笑。假笑只动嘴角，颧大肌 (Zygomaticus major) 扯动而已；真笑眼睛底下会跟着皱起来，那是眼轮匝肌 (Orbicularis oculi pars inferioris) 不受控制的工作。甚至提到一个经典案例，罗伯特·德尼罗那张龇牙咧嘴的照片，全是肌肉扭曲，但在动画里太过头就成怪物了。真正的高手得掌握三个层级：完全不动的“空镜头”张力、正常表演，还有像《谁陷害了兔子罗杰》那种过度夸张的卡通层，但底子必须是真实的人体结构。

最后那一段关于“少即是多”简直戳心窝子。Bob Dylan 面对镜头一句话不说，但你依然能感受到那种尴尬和冷战，这种负空间的力量远胜于一张脸疯狂抽搐。就像那个唇腭裂女孩的片子，她第一次看到自己变好的脸，只有两三分的表情强度，但那股震撼比全剧都强。所以结论很直白：别总想着把控制器拉满，懂得收着劲儿演，让观众自己去脑补，这才是高级的面部表演。

### Content Summary
[TLDR]
AMD 用两级辐射缓存加智能补全，把实时全局光照的效率拉满，让画质与性能不再打架。

[Background]
做图形开发的都头疼：烘焙光照不灵活，光线追踪又太贵。AMD 团队分享这套 GI-1.0 方案，专为解决动态世界的实时光照难题，适合引擎开发者参考如何低成本落地高性能光效。

[Recaps]
这演讲的核心就是 AMD 提出的两级辐射缓存 (Radiance Caching) 方案，也就是 GI-1.0。简单来说，就是要用更少的采样算出更好的实时全局光照 (Global Illumination)。传统的做法要么靠预计算，要么靠暴力光线追踪，但这俩要么没法动场景，要么吃显卡。AMD 的做法是先把画面切分成屏幕探针 (Screen Probes) 这种第一层缓存，直接贴在被动的物体表面上记录辐射信息，而不是像老式探针那样随便插在世界里。这样做的好处是位置准，不会穿模漏光，而且密度跟分辨率挂钩，哪有用算哪里，绝不浪费资源。

为了让这套系统跑得飞快，AMD 搞了几个骚操作。首先是时间缩放 (Temporal Upscaling)，一帧里只重新计算四分之一的探针，剩下四分之三靠上一帧的数据插值补全，只要补上了就不会有黑洞。针对补不全的情况，他们加了自适应采样 (Adaptive Sampling)，把有限的射线预算倾斜到有问题的地方去填补空白。还有一个核心技巧叫半球重建 (Hemisphere Reconstruction)，利用之前的旧数据帮当前的射线指路，相当于作弊导航，结果就是同样的射线数下，噪点能减少一大半。

为了解决那些细线条或者快速移动导致的闪烁问题，第二层用了空间里的哈希网格 (Hash Grid)。这东西是动态生成的，走到哪建到哪，还搞了个持久化的 LRU 缓存 (Persistent LRU Cache)，万一探针被踢出去了，如果是关键区域的数据还能存着下次接着用。算光影的时候也不用瞎蒙，借鉴了 ReSTIR 的思路做个世界空间光源采样，把最有用的光源挑出来重点算。最后再加个简单的降噪 (Denoising) 管道，把那些因为插值失败留下的破绽处理干净，整体稳定性稳如狗。

实测下来，在高端显卡上跑这套系统大概只要 3.6 毫秒，对比真正的路径追踪 (Path Tracing) 快了一大截，虽然细节没那么锐利，但亮度和氛围感基本吻合。虽然现在还没支持高光反射和多级反弹，但作为一套面向未来的实时光照框架，这套思路绝对硬核。对于不想在光跟上投入太多预算但又想要现代光影效果的团队来说，这简直是教科书级别的实战经验，值得好好钻研一下其中的缓存策略和修补技巧。

### Content Summary

核心观点：移植 PC 需自定义 PSO 缓存策略以消除卡顿，精细化显存管理，并深度优化光线追踪与宽屏兼容性。

[Background]
Nixxes 团队分享将《漫威蜘蛛侠》从主机移植 PC 的实战经验。重点解决 D3D12 带来的启动卡顿、跨平台显存差异及光线追踪优化等痛点，为游戏移植开发者提供参考案例。

[Recaps]
这次分享的痛点主要集中在 D3D12 特有的**管线状态对象 (PSO)** 问题上。由于 D3D12 要求在运行时编译着色器来生成各种状态的管线，如果直接在渲染循环里处理，玩家会遇到严重的启动卡顿或游戏内掉帧。传统的预加载虽然稳但会拉长等待时间，甚至需要数分钟。他们的解决方案是将 PSO 的创建工作合并到材质流式加载的过程中，放在加载界面悄悄完成。为了防止极端情况下 PSO 还没准备好导致的画面问题，他们还设计了一套“兜底”方案，用默认的低画质材质暂时替换真实资源，宁可牺牲一点视觉效果，也绝不向玩家展示卡顿。

另一个大挑战是跨平台的**显存管理**。PlayStation5 采用统一内存架构，而 PC 的 CPU 和 GPU 各有独立的视频显存，且系统内存访问速度远慢于显存。Windows 自带的资源调度机制有时为了腾空间，会把重要资源错误地移动到系统内存，导致性能骤降。Nixxes 为此开发了一套私有的内存管理系统，给不同资源设定优先级。例如关键的渲染目标永久保留在显存，普通纹理则根据预算进行替换。通过专用的后台线程搬运数据，确保即使显存不足，也能平滑降级，而不是像 Windows 原生机制那样触发阻塞式的切换。

在**光线追踪 (Ray Tracing)** 方面，他们不仅复刻了主机版的画面，还针对 PC 玩家的丰富硬件做了增强。PC 版允许开启更高精度的反射模型，甚至能反射城市建筑的额外细节，并提供了更高的分辨率选项。考虑到很多玩家 GPU 很强但 CPU 较弱，他们还添加了控制**顶加速结构 (TLAS)** 计算范围的滑块，帮助低配电脑减少 CPU 负载。此外，面对 PC 容易发生的显卡驱动崩溃（如**设备移除扩展数据 (DRED)** 报告的报错），他们完善了日志系统，记录崩溃前的显存状态和指令上下文，以便客服和技术人员快速判断是玩家硬件故障还是游戏代码问题，尽量提高修复率。

最后，宽屏和多显示器的适配也是一项繁重的“手工活”。主机的过场动画和 UI 大多固定为 16:9 比例，直接拉宽会导致场景穿模、物体丢失或 UI 错位。团队进行了大量的手动修复工作，包括调整摄像机剪切平面、修改 UI 锚点定位，以及针对不同比例动态添加黑边或背景模糊。特别是在超宽屏和多屏拼接模式下，原本的小地图和任务提示很容易跑到屏幕外或分裂显示，这些问题都需要逐一排查修复，确保在不同配置下都能维持沉浸感，这也是 PC 移植中不可忽视的隐形成本。

[TLDR]
以恐怖体验为核心，通过确立严格灯光准则及自研工具链，在兼顾性能的前提下实现画面与氛围的双重升级。

[Background]
重制版如何既保留原汁原味又利用新技术是个大坑。主讲人光效总监揭秘了如何在 Deadline 压力下，用新引擎把老版死空间的压迫感拉满，特别适合做 FPS 或恐怖游戏的开发同僚。

[Recaps]
这哥们开讲前就掏心窝子，说原版他都没通关，但这次负责重制版灯光。核心思路很简单：先定好艺术基调，也就是恐怖、沉浸和真实世界这三大支柱，其中恐怖永远优先级最高。基于此，他们制定了三个灯光原则：硬光照明体现工业冷感、限制色盘统一视觉风格、以及全环境光源 (Diegetic Lighting)，确保每一个光斑背后都有灯泡实物，拒绝凭空加光，保证世界观的合理性。

为了还原那种不安的观感，参考了电影《七宗罪》和《异形》的色调，整体走灰暗褐红色系。技术上最骚的操作是把默认管线换成了专业级 ACES (Academy Color Encoding System) 调色系统，搭配达芬奇后期处理，不仅黑得更深邃，中间调也更真实。加上引入了类似《战地》的大气迷雾系统，让光线有了实体感，玩家视线会被光柱引导，不知不觉就进了鬼打墙的陷阱。

最硬核的还是工具和性能优化。因为场景里灯多到离谱，他们做了个通用灯具资产，不仅能独立调整闪烁频率和颜色，还能跟电路开关系统联动。为了解决光照范围导致的画质崩坏，搞了个裁剪体积 (Clipping Volume) 控光；阴影则分静态动态两级缓存 (Smart Shadow Cache)，哪怕满地割尸体也不会卡顿。总之，提前定好蓝图，把工具做到极致，才能在两年工期里交出这个答卷。
