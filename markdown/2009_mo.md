## (308) The iPhone Bag Of Tricks
- **Speaker:** Guido Henkel (G3 Studios)
- **Duration:** 43 分钟
- **Category:** Mobile: Programming
- **Video Page:** https://www.gdcvault.com/play/1253
- **Slide Page:** 
- **Custom ID:** 1253

### Overview


### Content Summary
[TLDR]
iPhone 开发虽平台统一，核心在于掌握 Mac 环境下 C++ 混合开发，警惕浮点陷阱，善用原生 API 而非模拟层。

[Background]
告别多机型适配噩梦，iOS 只需搞定 Mac。本讲座专为想从传统平台转投 iOS 但被底层 API 劝退的开发者，拆解那些文档里藏着的坑，让你少走弯路。

[Recaps]
刚开始开发，老哥们得先认个服，买 Mac 是硬门槛，因为整个系统都是基于 OSX 的。语言方面，Apple 主推的 Objective-C 听着怪诞，其实不用全学。只要懂皮毛，把核心业务逻辑写成 C++ 就行，记得把所有源码后缀改成.mm 开启编译器选项，像把框架代码埋到底部库一样隔离掉，这样既能读苹果官方示例，又能跑自己的高性能逻辑。

性能这块最容易翻车。别以为 iPhone 快就能随便造，它没有专门的浮点处理单元 (FPU)，如果 CPU 上堆满浮点运算 (Float Operations)，程序立马卡顿。好在它的图形处理器 (GPU) 够强，画图用的浮点交给硬件扛，CPU 上的数值计算建议改用 64 位定点数数学 (Fixed Point Math)，也就是 long long 类型，既保精度又抗打击。图形渲染千万别碰慢如蜗牛的 UIKit 或 Core Graphics，老老实实上 OpenGL ES，哪怕是 2D 游戏也能跑出硬件加速的效果。

系统功能调用也有很多讲究。比如横竖屏切换，别死循环查状态，注册回调函数监听通知更靠谱；模拟器启动总偏 Portrait？去 Info.plist 里改键值设置 Landscape。本地化也是同理，读系统默认语言代码直接加载对应资源。还有个小窍门，如果是调音尺这类需要常亮的工具 App，关掉自动休眠定时器，不然黑屏会急死用户。文件读写方面，iOS 用的是“资源包” (Bundle) 机制，打包好的资源直接读取路径就能跑，存档数据则存到 Documents 目录，支持原子写入 (Atomic Writing) 更安全。

最后聊聊调试和音频。调试时别往屏幕乱吐字符，会把画面搞花，直接用标准输出 (Standard Output) 把日志塞进 Xcode 的控制台，简单的 printf 就能搞定所有打印需求。音频更是重头戏，iPhone 出身自带音质优势，但短音效别用 AudioServices，控制不了音量还容易丢帧。想要流畅播放音乐或录音，必须引入音频队列 (AudioQueue) 框架，它支持流式处理和异步回调，虽然入门门槛高，但一旦配好了，16 位 CD 音质随便跑。

## (308) Optimizing for OpenGL ES 2.0: The foundations of Firemint's Real Racing
- **Speaker:** Kristof Beets, Kynan Woodman (Imagination Technologies, Firemint)
- **Duration:** 40 分钟
- **Category:** Mobile: Programming
- **Video Page:** https://www.gdcvault.com/play/1339
- **Slide Page:** 
- **Custom ID:** 1339

### Overview


### Content Summary
[TLDR]
移动端设备虽普及，但带宽与算力受限，通过极致优化换取流畅体验才是核心关键。

[Background]
手机市场巨大但硬件弱，开发者常遇到卡顿发热。演讲者结合硬件厂商和实际开发经验，分享如何针对移动端做优化。

[Recaps]
大伙儿听我说，移动端市场虽大，但性能远不如 PC，功耗和散热限制决定了不能照搬主机那一套。核心痛点在于显存带宽太低，算法必须精简。CPU 端优化最关键，别瞎调接口，记得用`批处理 (Batching)`，把多个状态合在一起送进 GPU。有个惨痛的教训是千万别在游戏里随便`缓冲读取 (Buffer Readback)`，哪怕只读两个像素，也会导致 CPU 和 GPU 同步锁死，帧率瞬间暴跌一半。

渲染流程上，记住“先 opaque 后透明”的顺序，让硬件尽早剔除不可见物体。贴图要精打细算，尽量用小尺寸和压缩格式，`米普映射 (Mip Mapping)`是必选项，不然不仅浪费内存还会花屏。此外，所有几何体和纹理最好在启动时预加载，别等跑到游戏中间再去生成，那样对带宽简直是灾难。

到了 ES 2.0 阶段，主要是`着色器 (Shader)`的艺术。能用顶点算的就别用片元算，毕竟像素多。精度方面也别一根筋全开满血，顶点位置用`高精度 (High Precision)`防抖动，颜色和模糊效果直接用低精度提速，反正看着差不多就行。最后强调一句，别为了物理正确性牺牲帧率，能用假招子糊弄住玩家眼睛，就别真刀真枪去算，省下来的指令数才是真正的利润。

### Overview


### Content Summary
[TLDR]
印度手游虽客单价低，但用户基数庞大且年轻，3G 普及将是爆发关键。
[Background]
业界常低估印度市场潜力或误判商业模式。演讲者基于真实数据揭示当地消费习惯，旨在帮助开发者避开误区，把握增长红利。
[Recaps]
印度的情况跟咱们预想的完全不一样，别总拿着欧美那套硬套。这里最大的底牌就是年轻人，中位数年龄只有 24 岁，七成多人口都在 35 岁以下，全是精力旺盛的消费主力。手机用户基数更是吓人，短短十年从几百万窜到三亿五千万，未来还要冲七亿多。虽然大家每月手机费平均就五块半（ARPU (Average Revenue Per User)），看起来不多，但运营商靠这个薄利多销，EBITDA (Earnings Before Interest, Taxes, Depreciation and Amortization) 利润率还能做到 35%，不过这红利大部分都被卡脖子的大厂拿走了。

硬件和游戏价格得适应“土规矩”。iPhone 在印度基本是个笑话，销量不到十万部，因为用户觉得诺基亚更实在。好在三十美元就能买到能上网的手机，这是好事。但游戏千万别定高价，这里顶多能收六十美分。另外注意，电信运营商是分权的，全国被切成 27 个区，各玩各的，直接签总部合同没用，得分头谈。现在六成下载是靠非官方分发渠道 (off-deck) 做的，比如广告推广，比走官方商店更赚钱，这也是新入局者最容易忽略的坑。

内容方面，动作、赛车和板球是绝对主流，棒球橄榄球没人爱打。虽然英语普及度高，但现在还没强制要求本土语言包。最大的增长点其实是 3G (第三代移动通信技术) 的铺开，之前大家都在用手机打电话听歌，等网络通了，游戏下载会暴增。现在虽然市场规模小，分成比例也不高，但随着劣质厂商出局，环境会好转。建议各位想进去的先找个靠谱合伙人踩踩点，等量起来了再自己下场捞金，别一上来就硬刚。

## (308) Improving Game Play with Sensor Technology in Mobile Devices
- **Speaker:** Peter Lykke Nielsen (Nokia)
- **Duration:** 42 分钟
- **Category:** Mobile: Game Design
- **Video Page:** https://www.gdcvault.com/play/1684
- **Slide Page:** 
- **Custom ID:** 1684

### Overview


### Content Summary
[TLDR]
别光盯着屏幕玩游戏，要把手机当成连接现实的工具，用各种传感器把游戏玩进生活里，实现虚实结合的沉浸体验。

[Background]
针对当年手游同质化严重、开发者只会用加速度计做赛车的痛点，前诺基亚工程师分享如何深度挖掘手机内置的各类传感器，通过连接现实场景和数据，为移动端游戏设计提供突破性的创新思路。

[Recaps]
这老哥以前是诺基亚的技术大牛，看完他的演讲我就一个感受：现在的手机越来越强，但咱们的玩法还是停留在摇杆按键上，太浪费资源了。他把手机里的**传感器 (Sensor)** 比作新的玩法接口，核心就是别老想着怎么操作手柄，要想想怎么让手机跟现实世界对话。比如利用时间服务，游戏里的**非玩家角色 (NPC)** 可以知道你到底几点有空，甚至直接给你发短信约你在现实时间的固定地点见面，把游戏日程直接排进你的手机日历里，这种虚实结合的体验比单纯打怪升级有意思多了。

说到硬件，摄像头和麦克风简直是被大家低估的宝藏。以前大家拍照就是为了发朋友圈，现在能拿来做识别环境、找颜色，甚至对着麦克风吹气来吹散屏幕上的灰尘。有个叫 Laman Islands 的游戏就用摄像头扫实景里的颜色来给画填色，还有团队做了个**增强现实 (Augmented Reality)** Demo，你的手伸过去摸虚拟角色，它都会开心。麦克风也不光是语音指令，还能听摩斯密码或者风声，玩法多的是，关键看你怎么脑洞大开。

再聊聊移动相关的。**全球定位系统 (GPS)** 和**近场通信 (NFC)** 这类东西，别只当导航用。比如你住在哪，就能匹配同地区的玩家联机；甚至可以像那个诺基亚运动追踪器一样，把你的跑步路线跟地球到月亮的距离比长度，爽得不要不要的。还有**加速度计 (Accelerometer)**，别光用来开车了，你可以反过来用，拆弹的时候保持手机静止不能晃，一动就爆了，这才是把环境互动的高级用法。另外**蓝牙 (Bluetooth)** 也能用来在聚会时自动筛选想跟你聊的观众，挺实用的社交玩法。

最后大佬还提了一嘴未来的技术趋势，比如手机以后可能还要测空气质量啥的，反正现在的方向就是万物互联。鼓励大伙儿别被现有技术框死，多去研究些新项目，未来肯定有更多新玩具等着咱们整活。总之就是，硬件够硬，就看咱怎么整，千万别把这好牌打得稀烂。

## (308) GUITAR HERO MOBILE: Behind the Scenes
- **Speaker:** JJ Lechleiter (Hands-On Mobile)
- **Duration:** 42 分钟
- **Category:** Mobile: Game Design
- **Video Page:** https://www.gdcvault.com/play/1293
- **Slide Page:** 
- **Custom ID:** 1293

### Overview


### Content Summary
[TLDR]
手机音游别硬搬主机操作，简化按键配合后台精准同步，才能真正稳住核心玩法与体验。

[Background]
当年很多人质疑手机上没实体吉他怎么还原手感，演讲者复盘了从主机移植移动端的实战路径，包括操作简化、音频适配和多人同步方案，给手游开发者提供避坑指南。

[Recaps]
很多人做移植容易犯傻，以为直接照搬主机五键操作就行，结果手机端根本没法适配。制作组决定反其道而行，将核心玩法改成三键模式，通过提高音符密度和难度曲线来补偿操作简化的损失。这里提到的核心 IP 是吉他英雄 (Guitar Hero)，哪怕后来出了带鼓的续作，也只多加了一个脚键，坚持直觉式上手，避免像竞品那样因按键映射混乱劝退用户。

技术坑比想象中多，当年要支持 Java 2 微型版 (J2ME)、北电 Brew 平台 (Brew) 各种低端机能，音乐文件得有十几种格式备选，包括 MP3 音频格式 (MP3) 和 MIDI 文件格式。最硬核的是给 Brew 设备做了四通道音频混音器，吉他、人声、音效各走一条线，漏唱了才停吉他轨，保证听感不缩水。鉴于流量限制，歌曲被切分成两分钟版本，虽然有人吐槽，但这是为了加载速度和下载成本的无奈妥协。

真正的绝活是多人联机 (Multiplayer) 系统。在网络不稳定的情况下，要做到双方同一首歌无缝同步极难。他们通过后端服务器 (Backend Server) 统一计算时间偏移和加载进度，只传输关键数据而非音频流，实现毫秒级的技能交换，比如战斗干扰道具 (Battle Powers)。再配合每月新歌掉落机制和网页统计站，不仅解决了内容消耗问题，还靠高粘性排行榜强行留住了大量回头客，让手游也能跑出主机级的社交生态。

## (308) Handheld Augmented Reality Games
- **Speaker:** Blair MacIntyre (School of Interactive Computing at Georgia Tech)
- **Duration:** 47 分钟
- **Category:** Mobile: Game Design
- **Video Page:** https://www.gdcvault.com/play/1256
- **Slide Page:** 
- **Custom ID:** 1256

### Overview


### Content Summary
[TLDR]
手持 AR 的真正价值不是简单叠加贴图，而是借助物理空间与自然交互，实现虚实世界的深度融合体验。

[Background]
早期 AR 开发门槛太高，非研究人员玩不起；手机屏幕小又容易让人低头沉浸孤岛。演讲者 Blair 多年研究后认为，真正的机会在于用手机当透镜，让朋友围坐在一起，通过实体道具来玩增强现实 (Augmented Reality) 游戏，以此解决社交互动弱和技术难以落地的痛点。

[Recaps]
演讲者 Blair 开宗明义泼了一盆冷水：别以为加了贴图就是好 AR，如果只是让虚拟怪兽坐在你旁边当背景板，那过两天就腻了，纯属视觉特效。真正的杀手锏在于回答“为什么选 AR"。这玩意儿最大的优势是人就在现场，大家围着一张桌子，拿着实体卡片、骰子，手机只是块透视玻璃。玩家不需要低头盯着虚拟手柄，而是可以直接用手比划或者戳桌子上的东西。这种把现实空间变成巨大游乐场的设计思路，能让玩家调动所有物理和社交本能，而不是被小屏幕锁死。

技术上，老生常谈还是那个跟踪 (Tracking) 问题。现在的低配设备主要靠贴黑白方块标记物，虽然麻烦但稳。未来趋势是自然特征跟踪 (Natural Feature Tracking)，直接认房间里的墙角、地板纹理，不用贴东西了，但这玩意儿算力要求高，而且一旦光照变化就容易丢帧。另外，为了不让画面浮在空中，阴影 (Shadows) 和遮挡 (Occlusion) 是关键，比如虚拟鲨鱼游过书本时，得真的被书本挡住才行。再加上手机摄像头快门延迟导致的画面漂移，新硬件像 NVIDIA Tegra 带来的 GPU 提升才是打破瓶颈的希望。

具体作品方面，Blair 展示了团队过去的实验品。像《Bragfish》是典型的多人竞技，玩坏了还能互相干扰对方视线，很有桌游味。合作类的《Art of Defense》则利用六边形地图，让两人配合摆塔防守，大家一边动手摆道具一边沟通，社交粘性极高。还有学生组做的《Joe Workin》，拿个硬纸盒模拟城市，玩家得抱着盒子满场跑躲避伤害，极度考验体力。最新的僵尸演示虽然还没正式上线，但证明了新硬件跑高多边形模型加自由移动的可行性，未来或许能和 Facebook 这类社交平台结合，把线上好友拉到线下一起玩。

## (308) Am I dead yet?
- **Speaker:** John Szeder (Mofactor)
- **Duration:** 30 分钟
- **Category:** Mobile: Deals & Distribution
- **Video Page:** https://www.gdcvault.com/play/1302
- **Slide Page:** 
- **Custom ID:** 1302

### Overview


### Content Summary
[TLDR]
创业别光做梦，先备好五万美金烧钱，签合同时小心陷阱，别指望用后作养前作来续命。

[Background]
演讲者以关站血泪史劝退新人，点出初创团队最容易踩的法律坑和现金流死穴，适合准备单干的游戏开发者避坑。

[Recaps]
各位想单干的同行听好了，这老哥是以关站血泪史在跟大家掏心窝子。很多人为求创意自由或者觉得在大厂撞墙了才出来创业，但首先得问问兜里有没有 5 万美金够扔进去当燃料。这笔开销不光有注册公司，还包括差旅费和昂贵的律师费，毕竟游戏圈合同多如牛毛，没个靠谱的**独立承包商 (Independent Contractor)** 协议连工人都得防着侵权。尤其是那些帮公司写代码的，如果合同里没明确版权归属，到时候可能辛苦做出来的东西不归你。

谈判这块更是深水区，合同必须讲究对等互惠。老哥分享说，他有一次跟运营商谈，对方发来的文件全是红笔修改的，但他坚持只要了对等的**双向保密协议 (Mutual Non-Disclosure Agreement)** 就敢签，结果反而谈成了好 deal。遇到发行商提到的**回本机制 (Recoupment)** 一定要警惕，一旦你的收益要被发行商先拿去填补成本，那你基本就是等到猴年马月才能拿到分红。老哥推荐用降低回本门槛或者阶梯版税的方式，哪怕初期点数低，保证手里有现金流比啥都强，不然项目结束等着下一分钱时发不出工资才是真死局。

搞钱这事儿没那么浪漫，资金来源分好几个梯队。亲友资金最稳妥，**天使投资人 (Angels)** 虽然来得快但要抽成狠，以后找机构钱麻烦；如果要找**风险投资 (Venture Capital)**，你得证明自己有无对等优势，比如你有关系能直接搞定大平台。最扎心的建议是，如果你还没赚大钱就想纯靠原创游戏养家糊口，不如先去星巴克这类地方打工，拿份稳定工资交社保，用业余时间打磨作品。别指望像以前那样通过接外包维持生计，做久了你会发现技术越精越忙不过来，反而没精力做自己的游戏。
