## Level Design Case Studies: Trainyard and Cut the Rope
- **Speaker:** Matt Rix, Semyon Voinov (Magicule, ZeptoLab)
- **Duration:** 52 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015570
- **Slide Page:** https://www.gdcvault.com/play/1015344
- **Custom ID:** 1015570

### Overview


### Content Summary
[TLDR]
关卡设计的核心在于“教学”，用循序渐进的节奏和正向反馈，让休闲玩家在解谜中获得掌控感并持续渴望内容。

[Background]
这是《火车庭院》和《割绳子》主创的分享，针对移动端 Puzzle 游戏如何平衡硬核机制与大众体验，为独立开发者提供实战方法论，解决“怎么教小白玩家”的痛点。

[Recaps]
主讲人直言，关卡设计 (Level Design) 本质上就是教学。每一关都是给学生上的课，整体流程则是课程。别以为休闲玩家蠢，只是缺了“游戏语料库”，所以得从基础机制手把手教。宏观规划要渐进，别一次抛出一堆元素，不然组合爆炸没法做。新手引导别扔大段文字，像宜家说明书那样用图或者直接在游戏里演示最靠谱，而且要把知识点拆开撒进游戏里，别让玩家记不住。

难点把控方面，有个经典的难度曲线 (Difficulty Curve)，有爬坡也得有低谷，让佬们喘口气顺便复习旧技能。遇到存档丢了这种糟心事，《火车庭院》后期加了个“一键解锁”，虽说是作弊代码但也实用。针对那帮“强迫症”玩家卡死在终极难题的情况，后来干脆上了关卡编辑器 (Level Editor)，让硬核粉自己造，大家都有饭吃。最重要的是别让玩家陷入盲目试错，那是设计失败的信号。

另一边的《割绳子》更看重玩家心里咋想的。设计第一条原则就是正向反馈 (Positive Reinforcement)，给星星奖励比设陷阱好，还能自定义难度。物理引擎 (Physics Engine) 的效果得符合现实常识，走错了得有明显提示，别让人瞎折腾。更新后看数据说话，失败率 (Failure Rate) 高说明手感难操作，跳过率 (Skip Rate) 高说明谜题看不懂，根据这两项指标调整。最后一关不一定是最难的，但要最有创意，留钩子让玩家想下一盒。

## Trainyard: A level design post-mortem
- **Speaker:** Matt Rix, Semyon Voinov (Magicule, ZeptoLab)
- **Duration:** 0 分钟
- **Category:** Game Design
- **Video Page:** 
- **Slide Page:** https://www.gdcvault.com/play/1015343
- **Custom ID:** 1015343

### Overview
Cut the Rope and Trainyard are two of the most critically acclaimed and commercially successful puzzle games available on the App Store today. Join Semyon Voinov (Cut the Rope) and Matt Rix (Trainyard) as they share game design insights they learned while creating these massively successful games.

### Content Summary
[TLDR]
关卡设计的本质是教学，通过循序渐进地引导而非堆砌难度来制造玩家的内在成就感。

[Background]
独立开发者 Matt Rix 分享了《Trainyard》的成功经验。旨在解决新手上手难、教程冗长的痛点，特别适合想要提升用户体验的关卡设计师或 Indie 制作人阅读。

[Recaps]
首先得明确，**关卡设计 (Level Design)** 的本质其实就是搞教学，别把**休闲玩家 (Casual Players)** 当傻子，他们只是不懂咱们的游戏**基础技巧**。核心思路就是把每个关卡当成一堂课，从最基础的**互动方式 (Interaction)** 开始讲起。就像宜家说明书一样，能少写文字就少写，多用视觉示意。特别是复杂的**机制 (Mechanics)**，别指望玩家读文本就能懂，直接在游戏里演示一遍，甚至用虚拟手去操作给他们看。而且千万别一股脑把知识全倒出来，只教当前解谜需要的东西，让新技能马上有地方练手，否则玩家会一脸懵。

在**宏观设计 (Macro Design)** 上，要把“组合元素”当成新元素来看待，增加粒度要细。**难度曲线 (Difficulty Curve)** 不能一直陡增，中间穿插简单关卡让玩家透口气，顺便巩固基本功。关于**关卡解锁 (Level Unlocking)** 和奖励，给个一键解锁选项能极大减少因设备丢失数据带来的差评。另外，别为了炫技硬塞一些极难的“隐藏内容”，这会烦死**收集控 (Completionists)**，而硬核玩家本身就不会停，这种费力不讨好的设计不如不做。

微观层面做谜题时，每个格子都有存在的意义。讲究对称和平衡，看起来得像精心打磨过的艺术品，而不是程序随机生成的**过程生成 (Procedural Generation)** 废料。千万别加多余障碍物强行限制解法，这会让玩家觉得你在逼他们走你的路，像 Portal 1 那样有多条路更好玩。还要控制屏幕上同时活动的元素数量，别让脑子过载。**迭代 (Iteration)** 速度决定了最终质量，编辑器得有版本回溯功能，快速改图才能试出好手感。

最后，做好**内在激励 (Intrinsic Motivation)** 比外在奖励重要。没有分数和经验值也没事，关键是放大玩家解开谜题那一瞬间的快感。甚至可以埋些没教过的彩蛋机制（比如颜色混合），让玩家自己发现，那种“原来如此”的惊喜感才是留住他们的关键。

## What You Don’t Know IS Hurting You: How Aggressive User-Research Improved Resistance 3
- **Speaker:** Drew Murray (Insomniac Games)
- **Duration:** 0 分钟
- **Category:** Game Design
- **Video Page:** 
- **Slide Page:** https://www.gdcvault.com/play/1015854
- **Custom ID:** 1015854

### Overview
Watching a formal usability test of Resistance 2 was an eye-opening experience for developers at Insomniac Games. Players were struggling with FPS basics such as aiming and navigating, as well as hallmark Resistance features such as exotic weapons. The game was simply not being played the way we expected or wanted.

### Content Summary
[TLDR]
别闷头开发，像《抵抗 3》一样搞激进用户调研，用数据说话，游戏手感好口碑才硬。

[Background]
很多团队容易陷入“自嗨式”开发，做出来的东西玩家不爱玩。讲者结合《抵抗 3》实战，分享如何用最有效的用户调研方法避开雷区，适合所有负责玩法设计的同学参考。

[Recaps]
各位兄弟，做游戏最忌讳的就是闭门造车。很多项目只搞内部 **开发者试玩 (Developer Playtest)**，结果上线了才发现不好玩。讲者强调得做激进的 **用户研究 (User Research)**，核心就是找真实玩家搞 **外部试玩 (External Playtest)**。在测试前心里得有个底，搞清楚四个问题：找人测还是找专家？测的是感受、操作还是思维？看定性还是定量数据？怎么拿到这些数据？把这些逻辑理顺了，才知道怎么下嘴。

具体到《抵抗 3》，团队把重心放在核心枪感上。判定手柄好坏有三个标准：平衡（Balanced）、紧致（Tight）和修正快（Fast Correction）。为了验证这个，他们用了一种叫 **RITE 方法 (RITE Method)** 的技巧，就是 Rapid Iteration Testing Evaluation，说白了就是边测边改，别等攒一大推问题再开方子。还有一个冷知识，新入职的员工其实是宝贝，因为你们老油条都习惯了，新人眼里的问题才是最直观的痛点，别嫌人家乱按。

除了单人体验，还得靠群体数据。内部开发人员适合用来测 **可用性测试 (Usability Testing)** 的原型和数值细节，比如调整关卡难度；而外部的普通玩家更适合评估整体节奏和爽感。做问卷调查时，尽量别让玩家费脑子，能自动化的就自动化，但最后的分析得人工盯着点。这就好比盖楼，先把地基和承重墙（核心机制）打牢了，再去考虑搞什么精装修，不然全是在空中楼阁。

最后看看战绩，游戏发出去后评分很高，IGN 和 PS LifeStyle 这些大媒体都觉得这是系列里最好的一作。这说明之前的折腾绝对没白搭，特别是武器手感这块儿调教得当，玩家是真买单。讲者的结论非常扎心：“你不懂的地方就在伤害你。”所以别迷信直觉，多上实测数据，哪怕是激进一点也没关系，毕竟好口碑才是硬通货。

## The Titans: Creating Living, Breathing Levels in God of War III
- **Speaker:** Chris O'Neill, Bruno Velazquez (SCEA Santa Monica Studio, SCEA Santa Monica Studio)
- **Duration:** 59 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015524
- **Slide Page:** https://www.gdcvault.com/play/1015314
- **Custom ID:** 1015524

### Overview


### Content Summary
[TLDR]
用动态碰撞系统配合高频迭代设计，将超巨型泰坦打造成可互动、有情感弧光的“活体关卡”，实现史诗级战斗体验。

[Background]
圣莫尼卡工作室要在 PS3 机能限制下，把 500 米高的巨神做成可玩 Boss，分享如何从技术攻坚到玩法落地的全流程经验。

[Recaps]
圣莫尼卡这帮老哥在设计《战神 3》里的泰坦巨神克洛诺斯时，根本没按常规出牌。他们不把这当成普通 Boss 战，而是要造一个会呼吸、有情绪的“活体关卡”。为了还原神话感，克洛诺斯高达 500 米，模型复杂到离谱，开发团队得想办法让这个庞然大物动起来还不穿模，还得让玩家觉得是在跟真的怪物打架。

最大的技术硬骨头，就是把游戏里的脚本和摄像机绑定到这个移动的巨人身上。以前引擎只能处理静态盒子，但这回他们搞出了动态状态转换系统 (Dynamic State Transition System)，还能把碰撞网格 (Collision Mesh) 像装甲一样分区域贴在巨人的皮肤网格上。这活儿干起来简直要命，光是检查几百个动画帧里物体位置对不对，就能把人逼疯，但没这黑科技根本做不出那种丝滑的移动平台感。

玩法设计上，他们信奉“少写文档，多搓原型”。早期直接拿旧资产拼凑灰盒 (Graybox) 试错，比如后来经典的“撕手指甲”环节，就是测试时发现太假，临时改成更痛感的互动才定下来的。整个流程讲究高频迭代，一个 Boss 能打几十遍测试，确保玩家每五分钟就能碰到个大惊喜，节奏不能一直紧绷，不然玩家早崩了。同时他们定义了不少奇观场面 (Set Pieces) 来锚住玩家记忆。

最让人佩服的是团队协作，设计师和动画师恨不得长在一块儿，毕竟地形跟着人跑，传统流水线根本跟不上。管理层敢放手，让大家去野路子创新，最后靠全 studio 几十号人合力，硬是把这个看似不可能的技术梦实现了，成了游戏史上难忘的演出片段。

## The Future of Japanese Games

- **Duration:** 67 分钟

### Overview


### Content Summary
[TLDR]
稻船启治痛斥日业躺平现状：光靠情怀不行，只有丢掉包袱、敢于选苦路才能真正“赢”回世界。

[Background]
作为前卡普空的大佬，稻船启治这次没穿马甲，直接摊牌聊日业痛点。他觉得自己以前说“日业已死”太保守了，现在的情况更糟，想唤醒沉迷过去的制作人和玩家，别再用经典 IP 当遮羞布了。

[Recaps]
说白了，现在的日本游戏圈就是忘了咋“赢”。稻船觉得，大家总抱着旧日的辉煌当宝，就像听披头士的老歌一样，好听但没法当饭吃。核心问题不是技术差，而是输不起。以前我们以为自己是胜利者，其实早就成败者了还不自知。要想翻身，得承认自己输了，敢从头再来，不然就只能在《高清重制 (Remaster)》版里混日子，用户要的可是全新体验。

他自己就有血泪教训。当初做《洛克人传说》续作扑街得很惨，后来坐上了《生化危机》这匹“赢马”才翻身。他发现靠 **品牌 (Brand)** 的光环确实能省力气，但要是完全依赖它，反而看不出开发的本质。真正的本事是像乔布斯那样，不光维护旧牌子，还得重构新品牌，把过去的荣光变成燃料，而不是枷锁。毕竟没有哪个大厂永远稳如泰山，连苹果都得折腾。

所以现在他自己单干了，从几千人的大公司跳槽到几十人的小作坊，主动选了条难走的路。他对比韩国人搞 K-Pop 和三星电子，人家为了赢连面子都不要，拼命学日语去攻占市场，反观日本企业还在守着脸面。做游戏的也一样，别光盯着花钱砸大预算，得学会 **成本控制 (Budget Control)**。毕竟《主机游戏 (Console Game)》越来越贵，不能像当年那样无脑烧钱，也要像《社交游戏 (Social Game)`一样灵活。能不能用更少的钱做出更好玩的东西，才是硬道理。如果只想赚安稳钱，不如改行；想赢就得选苦受累。

## The 5 Domains of Play: Applying Psychology's Big 5 Motivation Domains to Games
- **Speaker:** Jason VandenBerghe (Ubisoft)
- **Duration:** 63 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015595
- **Slide Page:** https://www.gdcvault.com/play/1015364
- **Custom ID:** 1015595

### Overview


### Content Summary
[TLDR]
拒绝拍脑袋，用科学的“大五人格”模型翻译出五种游戏玩域，让设计决策能精准命中玩家真实动机。

[Background]
行业常把玩家需求画成死板的象限图，或者盲目追求所有数值最大化。主讲人为了搞清玩家真正为啥爱玩游戏，引入了成熟的心理学量表来指导设计。

[Recaps]
主讲人开场就抛出了一个核心结论，别再用过时的理论忽悠自己了。他直接引入了科学的心理模型——`大五人格 (Big Five Personality Model)`，包含开放性、尽责性等五个维度。这东西比那些过时的性格测试靠谱多了，是公开开源的数据流。经过研究他发现，我们玩游戏本质上是为了满足现实生活中没达成的心理需求，就像《模拟人生》里的状态条，现实里的怨气可以在游戏里通过扮演反派来解决，这就是所谓的玩家动机。

基于这个模型，他把心理学转化成了游戏设计的`游戏玩域 (Domains of Play)`，包括新奇、挑战、刺激、和谐与威胁。最关键的 insight 是打破了“温度计思维 (Thermometer Thinking)"，以前的思路是追求所有指标越高越好，但其实喜好的两极都能赚钱。比如既要有追求成就感的硬核玩家，也要有不在乎数值随便逛逛的休闲玩家。像《我的世界》满足了高开放性的新奇感，而《FIFA》则满足了低开放性对稳定规则的需求，没有优劣之分，只有受众不同。

最后他展示了如何将模型细化到三十个`细分子维 (Facets)`，比如将成就系统做成可选还是强制，就能同时兼顾追求完成度和拒绝强迫症的两类人。这套方法论不是为了让你写检查清单去生搬硬套，而是作为一个分析地图，让你在项目复盘时能看清自己的机制到底覆盖了哪些动机区间，防止漏掉某类玩家。虽然细节很烧脑，但它给了设计师一套科学语言，去解释为什么有些机制会引发特定玩家的负面情绪，从而在设计初期就能规避风险。

## Team Fortress 2 from the Orange Box to Free to Play in Just Four Years!
- **Speaker:** Joe Ludwig (Valve)
- **Duration:** 61 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015654
- **Slide Page:** https://www.gdcvault.com/play/1015887
- **Custom ID:** 1015654

### Overview


### Content Summary
[TLDR]
TF2 通过售卖非数值外观并推行免费模式，成功对齐了开发模型与商业模式，实现营收与活跃度翻倍。

[Background]
Valve 工程师复盘 TF2 从传统买断转免费之路，旨在解决持续开发与单一销售模式的冲突，为想探索内购平衡的玩家提供经验。

[Recaps]
Valve 的大佬们复盘了 TF2 怎么从**3A 盒装产品 (AAA Box Product)**一步步走到今天。起初大家发现光靠卖光盘，收入早就见顶了。他们试过打折促销，效果不错，但更核心的办法是靠不断的更新来拉新。不过这就有个矛盾：更新要照顾新玩家体验，但又不能让老玩家觉得被抛弃。直到 Medic 更新大获成功，团队才意识到必须把业务模式和开发节奏彻底解绑，不然永远都在两头讨好。

转折点在于引入了**微交易 (Microtransaction)**和稀有饰品。最经典的策略就是卖“帽子”，通过随机掉落制造稀缺感，建立经济体系。关键是死磕原则，绝不让玩家感觉**花钱变强 (Pay-to-win)**，所有功能性武器都能免费获取，商店里只卖外观。结算直接用 **Steam 钱包 (Steam Wallet)**，省去货币换算的麻烦。另外大力扶持社区，让玩家的创作能通过创意工坊 (Steam Workshop) 变成正式内容甚至分润，这下玩家积极性直接拉满，质量也比官方做得好。

最后一步才是彻底转型**免费游玩 (Free-to-Play)**。当时很多人担心会被骂，但他们把过渡做得比较平滑，比如给老用户发纪念皮肤，限制免费用户的背包大小而不是功能。结果数据打脸：活跃人数翻了三番，收入再次爆炸。加上后来上线的 Steam 交易 (Steam Trading) 打击了骗子行为，顺便还能给 Steam 上别的游戏带流量。这套打法证明了对在线游戏来说，把商业模式和开发节奏拧成一股绳，远比死守传统订阅制强得多。

## Tackling Large Scale Destruction FX: Lessons Learned From Raam's Shadow DLC

[Background]

[Recaps]
核心思路是把硬碰硬的物理模拟变成动画播放。大家习惯直接跑物理引擎算出来的破碎效果，但这玩意儿特别吃内存和时间。大佬的做法是先在 Maya 或者 Houdini 这种数字内容创作软件 (DCC App) 里把破碎过程演一遍，然后导出成 FBX，让虚幻引擎把这些碎片当成骨骼网格 (Skeletal Mesh) 来播。虽然这不是真正的物理交互，但好处是你能完全控制每个碎块的动次打次，还能随便调形状，不用担心穿模或者网格破破烂烂的问题，最重要的是稳定。他选的是基于 Bullet Physics Library 的物理求解器插件，只要能抗住网格瑕疵，准度差点也无所谓，反正玩家也不会拿放大镜盯着看。

画面感全靠“作弊”加细节。既然省了模拟，怎么看着像真的？得靠粒子系统 (Particle Systems) 当填缝剂。真事发生的时候，大块刚掉下来就全是灰，根本看清细枝末节。所以在大块碎片之间撒点灰尘粒子，既能挡住碰撞 bug 造成的晃动，又能掩盖物理计算不精确的地方。还有材质动画和音效设计也是神器，玻璃裂开的纹理和撞击声都能让玩家脑补出比实际更复杂的爆炸场面。特别是前景关键道具用手动画，背景能凑合就凑合，用静态网格动起来假装是碎的，这招能省下大量 CPU 算力。

workflow 上的骚操作更重要。跟关卡设计师 (Level Designers) 搞好关系是关键，先给个粗糙版让他占坑定好内存预算，最后再精修，避免后面发现内存爆了就改不动。另外采用两遍流程法，第一遍只管乱飞管像不像，第二遍才搞优化节省内存，千万别一边听反馈一边重跑模拟，累死还来不及。最后就是共享资源，同个模型多复制几个换个动画方向，破碎前先简化网格减少顶点数，能把几千万个碎块压缩到几兆内存里，这才是小团队生存之道。

## Minimal vs Elaborate, Simple vs Complex and the Space Between
- **Speaker:** Andy Nealen (Rutgers University / Hemisphere Games)
- **Duration:** 57 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015535
- **Slide Page:** https://www.gdcvault.com/play/1015323
- **Custom ID:** 1015535

### Overview


### Content Summary
[TLDR]
真正的游戏深度不在于堆砌数据或规则，而在于通过系统耦合与交互设计，让玩家感知到比表面数字更丰富的玩法体验。

[Background]
很多设计师头疼怎么才算“好玩又够深”，这讲座直接点破了“数学算出来的复杂”和“玩家脑子觉得的复杂”根本是两码事。适合那些想摆脱盲目加量，真正想掌握系统平衡和设计节奏的独立开发者及硬核玩家。

[Recaps]
这哥们儿一上来就泼冷水，说大部分所谓的复杂度其实都是我们瞎猜的。计算机能算出棋盘的**状态空间 (State Space)** 或者**决策树 (Decision Tree)** 有多大，比如围棋这种玩意儿状态多到天文数字，但人类玩的时候会自动过滤噪音，只关注关键信息。所以别老盯着那几个死板的数学指标，玩家的脑子和心理模型才是衡量**感知复杂度 (Perceived Complexity)** 的真正尺子，要是玩家觉得晕，哪怕代码再简洁也是垃圾设计。

为了让游戏体验既丰富又不把玩家绕晕，他总结了三个绝活。第一是用**过程化生成 (Procedural Generation)** 来做“纹理”，就像他在《Osmos》里做的，生成的背景元素虽然多，但因为规律稳定，不会增加认知负担；第二是精简操作，减少玩家的**自由度 (Degrees of Freedom)**，像《Canabalt》就只保留跳跃这一个关键信号；第三也是最核心的，是做**耦合 (Coupling)**，也就是把现有系统连起来而不是硬塞新东西。比如《Dark Souls》里的灵魂既是钱又是经验值，《Braid》的时间轴跟位置挂钩，这种闭环设计能让简单机制产生惊人的策略深度。

最后他拿自己设计的桌游《Grow 21》举例，这游戏完全靠限制来逼出创意。没有手牌全靠桌上随机摆放凑 21 分，不仅省物料还方便围观。这事儿说明一个道理，好的设计往往是戴着镣铐跳舞。现在游戏圈也该多跟实体桌游互相交流，别总闷头写代码，有时候改变一下输入反馈或者重新定义一个资源的用法，整个游戏可能就变成了完全不同的作品，这才是做游戏的乐趣所在。

最后还得给游戏加点“小心思”，比如微小的违和感 (Quirkiness) 能勾起好奇心，让人忍不住想探究。更重要的是制造“游戏外附加价值 (Game Plus Alpha Value)"，让玩家觉得玩这个游戏很酷。比如让玩家的名字出现在通关名单里，或者生成的菜单能变成可玩关卡，这种专属感和荣誉感会让玩家产生自豪感，自发帮你做口碑传播 (Buzz)。归根结底，做游戏不仅是赚快钱，是要让玩家觉得这时间花得值，愿意把这当成自己个性的一部分来展示。

## Don't trust the HiPPOs: A/B Testing Online Games
- **Speaker:** Steven Collins (Swrve)
- **Duration:** 25 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015563
- **Slide Page:** https://www.gdcvault.com/play/1015891
- **Custom ID:** 1015563

### Overview


### Content Summary
[TLDR]
别听大老板拍脑袋，用数据驱动的元数据 (Metadata) 和统计方法做 A-B 测试 (A-B Testing)，快速迭代游戏。

[Background]
解决开发中依赖直觉决策的痛点。适合手游策划和工程师，如何用数据替代最高薪资人士意见 (HIPPO) 指导游戏迭代。

[Recaps]
这演讲的核心就是劝大家别当"HIPPO"，也就是“最高薪资人士意见”。很多团队做决定全靠大佬拍脑门，不如拿数据说话。传统的做法是把 A-B 测试 (A-B Testing) 硬写进代码里，改个按钮色就得发新版本更新，这在移动端太慢了。正确的姿势是把数据和代码彻底分开，搭一个元数据 (Metadata) 层，让后台随时能下发配置，不用过应用商店审核就能秒级生效，实现产品设计和引擎开发的并行循环，真正响应“互联网时间”。

具体怎么落地呢？关键在于给用户分桶。利用哈希函数 (Hash Function) 把用户 ID 和测试 ID 混合运算，确保每个人稳稳落在同一个组里，不会今天看这个明天看那个。服务器根据分组结果推送不同的配置（比如宝石颜色），客户端收到后渲染对应内容。同时，所有的点击、购买事件都要按测试桶打标签上报，这样对比才公平，不然数据全混一块没法算出真实效果。

光有数据还不够，还得懂点统计学，否则容易瞎猜。我们要建立零假设 (Null Hypothesis)，默认两种方案没区别，除非数据证明差异显著。这里涉及两类错误：一类错误 (Type 1 Error) 是误报，二类错误 (Type 2 Error) 是漏报。通过计算样本量，结合正态分布 (Normal Distribution)，确定一个 P 值 (P-value) 阈值，才能自信地宣布哪个方案胜出，而不是被随机噪音忽悠了。

最后要注意几个实际踩坑的地方。老玩家和新玩家行为可能不同，最好隔离测试；还要确认因果关系，别把其他因素导致的收入上涨怪到改动上。QA 压力会变大，因为同一时间可能有多个版本在跑，得有一套机制支持强制拉入特定测试桶方便调试，确保能快速回滚或扩量。这套流程虽然前期搭建麻烦，但后期收益巨大，是数据民主化的必经之路。

- **Speaker:** Jaime Griesemer (Sucker Punch)
- **Duration:** 58 分钟
- **Category:** Game Design

[TLDR]
游戏设计并非堆砌机制，而是像调音一样管理细节，在玩家脑容量限制内平衡约束、交互与系统的谐波节奏。

[Background]
演讲者厌倦了只聊自己的光环系列，转而分享通用设计心法。面向广大开发者，剖析为何同类型游戏评分差异大，强调细节如何决定成败，教人如何用“脑容量”视角拆解机制。

[Recaps]
第一块聊的是细节和约束，这是基础中的基础。很多游戏看着差不多，其实就差在那点微操上。比如《愤怒的小鸟》(Angry_Birds) 就是靠死磕移动端手感和时间投入这些细节才火的，反观《神秘海域 3》(Uncharted_3) 哪怕是大厂，只要镜头控制 (Camera Controls) 没调好，手感都会飘。咱们设计开局就得定好**约束条件 (Constraints)**，就像光环系列定好了交战距离，后面武器伤害、AI 寻路甚至地图规模都得围着这个石头转。千万别无视玩家的大脑也是硬件，得算好**系统要求 (System Requirements)**，既不能太快导致玩家反应不过来，也不能太慢让人犯困。比如手机版《俄罗斯方块》一开始输入太繁复反而难上手，后来简化成选五个点才流畅。手柄按键分配也得按重要程度分级，把移动这种连续动作和攻击这种普通动作分开，别让常用键位冲突，别让新手被复杂的操作劝退。

第二块重点讲交互体验和反馈心理。玩家对延迟很敏感，超过 100 毫秒就能感觉到卡顿，所以竞技射击都奔着高帧率去了。还有瞄准辅助这东西，光环不是硬锁死，而是**目标辅助 (Aim Assist)**，它猜你想打哪，枪口会自己修正，这样就算你技术菜也有赢面。再说回报机制，别以为给个图标就是奖励，玩家要的是**多巴胺 (Dopamine)** 分泌的快乐。只有真实的胜利才能刺激激素，虚假的任务就像吃假糖，容易血糖低。最好的奖励就是让你做的事更有价值，原版《魔兽世界》(World_Of_Warcraft) 里打怪掉装备直接增强战斗力，这就是良性循环，现在的版本反而因为跨职业需求变得臃肿，失去了那种纯粹的快感。

第三块提个新概念叫**谐波 (Harmonics)**，简单说就是把游戏当音乐写。马里奥、刺猬索尼克和小机器人虽然都是横版过关，但 BOSS 战时的节奏感天差地别，因为它们的**节拍器 (Pace Setters)** 设置不同。马里奥的大蘑菇状态一过战斗就结束了，节奏单一；而《超级肉食男孩》或《暗黑之魂》则是利用复活机制和死亡惩罚来重置频率。如果回血、换弹和移动频率都对不上，玩家会觉得散架；如果像《死亡空间》(Dead_Space) 那样，系统间频率对齐，玩起来就特别顺滑。所以设计别光看数值，要像个作曲家一样，确保整个系统的音符都在一个调子上，这才是高手和普通人的区别。

## Contrastive Juxtaposition: Contrast and Context in BioWare Story and Cinematics
- **Speaker:** Jonathan Perry (BioWare)
- **Duration:** 50 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015672
- **Slide Page:** https://www.gdcvault.com/play/1016328
- **Custom ID:** 1015672

### Overview


### Content Summary
[TLDR]
通过运用“对比并置 (Contrastive Juxtaposition)"手法，利用视听与叙事的强烈反差，激发玩家深层情感共鸣。

[Background]
Bioware 电影总监揭秘如何打造《质量效应》等作品中的催泪瞬间，解决互动叙事中玩家情感投入不足、角色缺乏厚度的痛点。

[Recaps]
今儿这位大佬叫乔纳森·佩里，是 BioWare 的王牌电影总监。他这次主要想跟大家聊聊怎么让玩家真正爱上游戏里的角色。他提出了一个核心概念，叫“对比并置 (Contrastive Juxtaposition)"，说白了就是把两个完全相反的东西放一块儿，比如生与死、光与暗，这样戏剧张力才大。为啥这招管用？因为人类天生对变化敏感，这是生存本能，看到动静就知道有事儿。在咱们做游戏的时候，可以利用这种“极性 (Polarity)"来展示角色的成长方向，比如从善良走向堕落的轨迹，让玩家感觉到自己在推动这个变化，而不是干等着看。

接下来讲讲具体咋落地。首先得定主题，别整那种非黑即白的，搞点灰色的吧。比如《质量效应》里是人性的自由意志对抗雷普尔人的秩序决定论。定好主题后，要把这个逻辑贯穿到美术和音效上，不能两边脱节。就像之前有个经验教训，《龙腾世纪 2》本来想把友谊值和敌对值都做成正反馈，结果玩家习惯了老规矩觉得坏就是坏，导致误解。所以沟通别整那些厚厚的文档没人读，直接跟美术说清楚要什么色调、什么氛围，让他们也参与进来创造“对比”。还有那著名的库勒肖夫效应，同一个表情配不同画面意思完全不同，这就是“语境 (Context)"的力量。

最后就是实操层面的剪辑和设计。要想高潮更震撼，前面必须够低谷。拿《质量效应 2》乔克牺牲那段举例，先是大爆炸声音戛然而止，只剩呼吸声，最后只剩悲伤的钢琴曲，视觉也从特写拉到远景看人消失在宇宙里，这一套组合拳下来，眼泪根本挡不住。另外别忘了玩家的“反射性语境”，你之前的选择得影响现在的体验，比如杀敌动作得根据装备类型来变，不然就很违和。千万别忽略细节，要是前面浑身血去谈恋爱，场面就太离谱了。总之，把所有元素拧成一股绳，才能整出让人印象深刻的名场面。

[Recaps]
首先，王田桑强调做商业游戏光有激情不够，得有个清晰的“灯塔”，也就是**概念 (Concept)**。这得包含两层：一个是咋好玩（不战斗、体验乡间生活），另一个是咋赚钱（降低风险）。他当年没直接砸钱，而是先做几个稳项目攒信誉，这叫**投资组合 (Portfolio)**策略，拿实际成果跟资方要钱，比空谈靠谱。

设计层面，为避开当时主流的“打怪”套路，他们提出了“工作即乐趣”的逻辑。参考**模拟城市 (SimCity)**的渐进成长逻辑和**塞尔达传说 (The_Legend_Of_Zelda)**的实体交互，将抽象数值转化为具体**核心玩法 (Core Mechanic)**反馈。比如锄地、施肥都有物理触感，而非单纯加属性。遇到硬件性能瓶颈时，优先保证流畅度，通过删减冗余素材来换取帧率稳定，确保**可玩原型 (First Playable)**的手感顺滑。

最燃的是差点破产那段。公司倒闭后，团队仅剩两人，硬是靠睡睡袋续命半年，砍掉一半内容才完工。这证明游戏做不完比做得烂更丢人，活下来才有机会迭代。后来根据玩家反馈（发现女性比例意外高），后续几代调整婚育系统，甚至搞出寿命机制。这种“听劝”精神加上技术积累，让系列存活十六年，累计销量破千万，这才是老游戏长红的正确打开方式。

- **Duration:** 60 分钟

### Overview


### Content Summary
[TLDR]
街机黄金时代的成败取决于实打实的“投币率”，《Gauntlet》的成功证明了简单上手与深度合作才是王道。

[Background]
这场演讲由传奇开发者 Dave Theurer 带来，揭秘了街机黄金时代那些被遗忘的残酷真相。主要解决了初学者对早期硬件极限、市场测试机制以及商业盈利逻辑的认知空白，适合想了解行业历史和设计根源的开发者。

[Recaps]
先说说当时的街机 (Coin-op) 圈有多残酷。不像现在发个宣发就完了，以前游戏得直接放现场测试 (Field Test)。只要没人扔硬币，那就是死路一条，根本没面子子工程能救你。据老 Dave 说，差不多六成项目连测试都不过，最后能赚钱的也就一成。而且这行利润链太复杂，开发商甚至摸不到一分钱的机箱收入，全是运营商和分销商在分钱。那时候街头点位比现在的网吧还重要，一旦点位饱和，新游戏根本插不进手，这就是为什么 83 年大崩盘后，很多大厂都得裁员转型。

技术实现上真是各种魔改。像《Gauntlet》这种四人对战，受限于显存和 CPU，每行只能处理 56 个运动对象 (Motion Objects)。为了塞进电路并抗干扰，硬是顶住压力上了四层电路板 (Four-layer board)，这可是行业首例，后来都成了标配。因为当时没有高清资源，所有颜色都得靠色彩调色板 (Color Palettes)。为了省电又防鬼畜闪烁，他们还搞了前瞻算法，把屏幕看不见的对象也算进开销里优化渲染队列，不然画面能卡成 PPT。另外为了解决屏幕边缘穿模问题，甚至设计了滑步机制，撞墙还能贴着走，手感特别溜。

设计理念反而是最值钱的。核心就两条：上手必须秒懂，没地方写说明书；策略要有深度，让人愿意反复试错。角色设计不是谁强谁弱，而是功能互补，比如有的负责扛伤害，有的负责捡金币，配合不好就是送人头。关卡生成用了质数算法保证循环不重复，玩久了也不会腻。至于版权防盗版？那是真没办法，芯片都能被抄，但玩法一旦火了，盗版商也只能跟着你喝汤。对于想入行的新人，他给出的建议是：别总想着教玩家规则，要让他们一眼看懂，这才是好游戏的门槛。顺便提一句，虽然大家都防盗版，但他也承认有时候故意留个后门让玩家能无限续关，反而能让老板们更爽快地扔硬币，毕竟没人喜欢游戏太容易结束，只要能回本，小漏洞就当是福利吧。

## Breaking the Rules of Game Design: When to Go Against Competence, Autonomy and Relatedness
- **Speaker:** Kaitlyn Burnell (Naughty Dog)
- **Duration:** 41 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015647
- **Slide Page:** https://www.gdcvault.com/play/1015398
- **Custom ID:** 1015647

### Overview


### Content Summary
[TLDR]
为了打造极致的剧情张力，开发者有时需故意打破玩家的自主、胜任与关联感，用负面情绪驱动叙事。

[Background]
传统设计迷信提升玩家满足感，但这篇演讲反其道而行，分享如何用“破坏心理需求”制造深刻体验。适合想深挖叙事力度、不想只做快餐式产品的制作人参考。

[Recaps]
咱们都知道提升玩家的**内在动机 (Intrinsic Motivation)** 是留人的王道，核心就是抓稳**自主性 (Autonomy)**、**胜任感 (Competence)** 和**关联感 (Relatedness)** 这三根支柱。数据摆在那儿，满足这仨，玩家流失率都能砍一半。但要是把这三项全都拉满，搞出来的可能就是《Farmville》那种纯肝无脑的游戏，虽然稳，但没啥回味。真正的高手玩法，是懂得什么时候踩刹车，故意让玩家感到“不爽”，从而把这种情绪转化成剧情的燃料。

破坏**自主性 (Autonomy)** 就是个很狠的招。比如在《Portal》里强迫你亲手销毁一个跟你建立了感情的箱子，这种被迫感会产生强烈的挫败和愤怒。这里有个门道：得想办法让玩家把火撒在游戏里的反派身上，而不是骂你是设计者。如果想加强效果，可以在强行推进剧情前留点缝隙，比如允许玩家给箱子画个告别涂鸦，这种微小的**自主性 (Autonomy)** 会让最后的悲剧更有仪式感，玩家也会更投入。

至于**胜任感 (Competence)** 和**关联感 (Relatedness)**，搞坏了能引发无助或心碎。像《Prince_Of_Persia》里女主救场，或者是《Heavy_Rain》里的两难选择，本质都是让人体验无力感。尤其是像《Final_Fantasy_VII》里艾丽斯的死，之所以震撼，是因为之前通过装备和机制跟玩家建立了深厚的依赖关系。这时候把她弄没了，玩家才真的痛。不过要注意，别随便剥夺玩家的能力，除非是为了铺垫后续的剧情反转，否则单纯让玩家“打不过”，很容易直接劝退。

最后提几个实操时的避坑指南。这招不能频繁用，毕竟人类的大脑对特定情绪的耐受度有限，一直高潮最后全是麻木。如果是做开放世界这种非线性设计，建议把这些情绪浓重的片段做成独立的封闭区域，防止前后剧情逻辑打架。总结来说，先定下你想要什么情绪，再反推该切断玩家的哪项基本需求。好的设计不一定是让玩家全程顺滑，有时候就是得在关键节点给玩家使绊子，让那一刻的“难受”变成玩完后回想起来最难忘的瞬间。

## Attention, Not Immersion: Making Your Games Better with Psychology and Playtesting, the Uncharted Way
- **Speaker:** Richard Lemarchand (Naughty Dog)
- **Duration:** 68 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015745
- **Slide Page:** https://www.gdcvault.com/play/1015464
- **Custom ID:** 1015745

### Overview


### Content Summary
[TLDR]
别整那些虚头巴脑的“沉浸感”，游戏设计的核心其实是争夺和管理玩家的“注意力”，用对比、叙事和系统三招把玩家牢牢抓在手里。

[Background]
主讲人是 Naughty Dog 的大佬，干了二十年动作游戏设计，早就对业内乱吹“沉浸感”腻歪了。他觉得这词容易误导方向，不如聊聊心理学上的“注意力”。今天他想拿《神秘海域》开发时的实战干货，给大伙安利一套基于认知科学的注意力管理方案，帮大家理清到底是怎么抓住玩家的眼球的。

[Recaps]
首先得把“沉浸感”这个词放一放，换成更准确的“注意力”。心理学家发现人有“注意瓶颈”，没法同时顾全所有事，而且盯着看久了会“警觉疲劳”，所以节奏得张弛有度。人的注意力分两种，一种是“反射性注意力 (Reflexive Attention)”，像屏幕突然变大就忍不住看过去；另一种是“执行性注意力 (Executive Attention)”，是你自己主动选择关注哪的。做设计就是得利用前一种去抢眼球，靠后一种来留住人。

那具体咋抓人呢？演讲者总结了三招：第一是“对比 (Contrast)”，也就是美术和视觉上的冲击力，比如鲜艳的颜色或独特的形状，能瞬间抢走玩家的视线；第二是“叙事 (Narrative)”，特别是带点社交属性的内容，人类天生关注人和关系，角色塑造好了比讲大道理管用；第三是“系统 (Systems)"，也就是玩法机制本身，只要规则清晰、变化够多，就能像猫薄荷一样让人沉迷。这三样东西混着用，比单一堆砌特效强多了。

落地到实操上，有几个坑得避雷。比如玩家视线集中在屏幕中央，角落的东西很容易漏看，这就是所谓的“视觉重力”，重要信息最好放下面一点。还有玩测环节，光靠眼动仪太贵还不准，最好的办法是收集“坏跳跃系统”这种数据，记录玩家以为能爬但没爬上去的地方，直接告诉美术哪块砖有问题。科学数据是工具，但最终还是得听设计直觉，别让数字绑架了你的创意。

最后聊个深层的，关于“心流 (Flow)"状态。很多开放游戏像《我的世界》，没有明确目标也能让人上瘾，这叫“自目的性体验 (Autotelic Experience)”，玩家自己给自己找乐子。游戏设计不必死磕强迫循环，有时候让玩家暂时脱离“心流”，去看看风景或听段音乐，反而能创造更深的情感冲击。好的设计是在理性和感性之间找平衡，让游戏体验成为既有逻辑又有温度的独特艺术。

## Art History for Game Devs: In Praise of Abstraction
- **Speaker:** John Sharp (Georgia Institute of Technology)
- **Duration:** 58 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015684
- **Slide Page:** https://www.gdcvault.com/play/1015423
- **Custom ID:** 1015684

### Overview


### Content Summary
[TLDR]
游戏设计别死磕写实，善用抽象（Abstraction）打破现实束缚，用“行动语言”创造新意义。

[Background]
当下游戏界过度迷恋写实画面和线性叙事，容易陷入“具象主义（Literalism）”陷阱。适合想要突破玩法表达、寻找新意义的开发者。

[Recaps]
讲者 John Sharp 结合了设计师和艺术史学者的双重视角，提出一个核心观点：别总盯着像素堆砌写实，游戏真正的核心在于“动作语言（Language of Action）”。现在很多作品陷入“具象主义（Literalism）”泥潭，觉得必须还原真实世界，这反而限制了玩法的想象力。他主张把抽象（Abstraction）当作设计工具，不是简单的图形简化，而是提炼现象产生新意义。

在机制探索上，他回顾了绘画史，从莫奈到波洛克，画家最终关注的是笔触和动作本身，而非物体。映射到游戏，就像《Johann Sebastian Joust》直接把屏幕去掉，强迫玩家用肢体互动；还有《V.》这类平台跳，改成了重力移动，都是在“弯曲”甚至“打破”类型框架，给旧类型注入新生命。

表达层面上，抽象能传递无形之物。比如 Brenda Brathwaite 的桌游《Train》，不画受害者，只通过发牌规则和负罪感机制，让玩家体验大屠杀的历史重量。Jonathan Blow 的《The Witness》则完全靠环境解谜教人上手，不用文字。还有《The Unfinished Swan》把“看”这个动作变成喷墨塑造世界。这些例子都说明，抽象能让游戏超越单纯的叙事，成为承载情感和文化的容器，这才是设计自由的真谛。

[Background]
面对被数据党垄断的决策环境，许多设计师担心数据扼杀创意。这篇演讲旨在打破“数据=生意人”的刻板印象，教策划如何用数据反哺设计体验，而不是被数据牵着鼻子走。

- **Speaker:** Drew Murray (Insomniac Games)
- **Duration:** 60 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015805
- **Slide Page:**

### Overview


### Content Summary
[TLDR]
只有彻底摆脱开发者自嗨，靠大量真实玩家测试数据死磕细节，才能做出真正懂玩家的好游戏。

[Background]
许多开发团队因工期压力省略测试环节，导致游戏上线后满屏 Bug 和设计槽点。Insomniac 以《抵抗军》系列为例，展示如何通过系统化测试从赶工模式转型为品质驱动，适合所有面临“既要快又要好”的制作人阅读参考。

[Recaps]
过去在开发《抵抗军 2》时，团队习惯在截止前硬塞功能，结果请来专家做**可用性测试 (Usability Testing)**时发现，新手根本不懂怎么用副武器，甚至不知道地图出口在哪。这种巨大的认知落差促使主创决定改变工作室的**开发者导向文化 (Developer-Centric Culture)**，转而建立**玩家导向文化 (Player-Centric Culture)**。他们雇佣了专业的用户体验顾问，发誓要把验证工作前置，确保玩家拿到的是设计者原本意图的体验，而不是被猜谜一样的误导。

为了落实这一理念，《抵抗军 3》采用了四种测试组合拳。首先是正式的**可用性测试 (Usability Testing)**，一对一观察玩家实时操作和反应，获取**定性数据 (Qualitative Data)**；其次是大规模的**玩法测试 (Playtesting)**，收集**量化数据 (Quantitative Data)**如死亡率和武器使用频率。有趣的是，内部开发者测试也很有用，尤其是在评估原型阶段，因为老手能透过简陋素材看到潜力，而且成本低廉灵活。例如瞄准系统，团队直接剥离了所有特效，只留基础操作反复打磨，直到确保新手能快速修正射偏，专家也能觉得手感顺滑。

这种高压测试也倒逼了理性的资源分配。通过问卷评分和热力图，团队发现某些强力武器或关卡区域并不受欢迎。比如一款重锤武器评分极低，考虑到距离发售仅剩三个月，团队果断放弃修复，将资源挪给更关键的内容。相反，一款冰冻枪则通过修改关卡演示场景，强行让玩家体验到它最强的控场能力。虽然这些流程挤占了原本的工时，团队不得不找索尼申请延期九个月，但最终效果证明了投入产出比极高。

这场变革最大的收获并非单一功能的提升，而是整个设计思维的进化。团队成员学会了不再凭经验拍脑门，而是时刻代入陌生玩家视角去预判体验断点。尽管过程中有人抱怨加班严重，但当看到成品上市后玩家对操作流畅度的好评时，大家都明白：那些为了真实反馈而熬过的夜，才是好游戏真正的基石。

- **Speaker:** Matthew Ricchetti (Kabam)

- **Category:** Game Design

- **Slide Page:**

### Overview


### Content Summary
[TLDR]
别把社交游戏简单分成休闲和硬核，用三组维度拆解机制，才能设计出真正让玩家离不开的在线互动体验。

[Background]
传统的休闲和硬核二分法已经没法解释现在的市场了，特别是随着移动互联网和免费游玩模式的普及，玩家的社交习惯发生了巨大变化。这场演讲旨在为开发者提供一套实用的分析框架，帮助大家在新平台上更好地利用社交机制来提升留存和收入。

[Recaps]
演讲者 Matt Ricchetti 指出，现在的在线游戏早就不是单纯的非黑即白。以前我们觉得社交游戏要么是 Facebook 上的那种轻量级异步互动，要么是 MMORPG 里的深度实时交流。但现在手机和网页端让会话变得碎片化，输入方式也变成了触屏，技术限制更多。更重要的是，在免费游玩 (Free-to-Play) 模式下，开发商和用户的关系没结束，社交直接成了拉新、留存和变现的核心引擎，地位比以前重要了太多。

为了理清复杂的社交设计，他提出了三组简单的启发式规则。第一组是同步 (Synchronous) 与异步 (Asynchronous)，也就是玩家互动是否需要在同一时间发生。比如实时的团战很有激情但技术难搞，而异步的回合制更适合碎片时间，像《象棋》那样。第二组是对称 (Symmetrical) 与非对称 (Asymmetrical)，指的是建立关系是否需要双向确认。像微信好友就是对称，信任度高；像微博关注是非对称，信息传播快但隐私差。第三组是强关系 (Strong Tie) 与弱关系 (Loose Tie)，看的是关系的深度和持久度。比如公会联盟属于强关系，虽然深但需要大量维护成本；而阵营选择属于弱关系，门槛低但随时可以换，却能带来广泛的群体认同。

他以《Kingdoms of Camelot》为例，说明如何混合使用这些机制。这游戏既有异步的个人攻防，也有实时的公会战争，还把公会做强关系、把阵营选边当弱关系，既满足了深度玩家又照顾了轻度用户。演讲最后强调，别总想着靠过滤词解决骂人问题，那是治标不治本。更好的办法是给玩家权力，比如让他们自己能屏蔽讨厌的人，让社区自己治理。未来的社交设计得灵活点，看看你的机制是不是真的适配现在的平台和用户习惯。

[Background]
针对传统游戏中虚拟角色表情僵硬、缺乏情感共鸣的痛点，Quantic Dream 分享了如何利用全表演捕捉技术还原真实表演，为叙事类游戏探索新方向。

[Recaps]
David 开场先给大伙儿定义了啥叫“全表演捕捉 (Full Performance Capture)"，简单说就是脸、身子、配音一次性撸下来，别像以前那样分开录。这招好莱坞大片如《阿凡达》都用，效果炸裂，但成本太高游戏公司扛不住。大多数游戏还在用“关键帧 (Keyframe)"拼嘴巴或者“分拆表演”，虽然省钱，但看着就没内味儿，感情都是硬凑的。对于游戏开发者来说，核心是用“虚拟演员 (Virtual Actors)"去演活剧本，而不是只当个提线木偶。

Quantic Dream 这家法国工作室折腾了十几年，从最早的《奥米克隆》玩音素控制，到《暴雨》时期尝试分拆流程，最后搞出了“卡拉 (Kara)"这个原型。他们在 PS3 上直接跑实时渲染，把演员扫描成数字克隆人，动作数据直接灌进引擎，基本不修。为了不让脸看起来脏兮兮的，他们还专门配了灯光编辑器，确保特写镜头光影干净，避免露怯。这过程讲究“重定向 (Retargeting)"灵活性，甚至能把一个演员的动作套到其他人脸上，方便多语言版本。

David 最后掏心窝子说，技术只是笔，内容才是书。虽然现在还在“恐怖谷 (Uncanny Valley)"边缘试探，但只要戏拍得好，大家其实不在乎是真脸还是皮套。未来的钱不该全花在堆多边形上，得多砸钱请好演员、好编剧。游戏要想真正出圈，得靠有深度的成人向故事来留住玩家的心，毕竟互动媒体最大的潜力就在于这种能打动人心的瞬间。

[Recaps]

接着是 Naughty Dog 的大佬 Richard Le Marchand，他玩起了心理学。他认为“羞耻感 (Shame)"是人类行为的核心驱动力之一，于是做了个全员参与的对视游戏。全场观众两两结对，一边哼歌一边盯着对方眼睛看 30 秒（想着糗事），再切换成美好回忆。通过赛前后举手调查对比，发现确实有人感受到了预期的不适和后续的正向调节。他用这种低成本的方式验证了对负面情绪的“脱敏疗法”，虽然测量主要靠主观反馈，但在情感体验上的突破很值得琢磨。

最后是老牌设计师 Noah Falstein，他搞了个大而全的方案叫"60 秒超级英雄”。灵感来自移动设备和真人秀，玩法是让网友拍下身边的好人好事视频上传，其他人在 60 秒内投票评选。获胜者和拍摄者都能获得奖金和名声，背后还挂着电视栏目和广告变现的逻辑。他提到了“免费增值 (Freemium)"模式来维持运营，并引用《魔兽世界》的血疫事件说明数据的重要性。虽然这个方案偏商业化构想，但他试图解决“谁来激励好人做好事”的问题，把社交传播和游戏机制结合得非常紧密。

[Recaps]
老哥掏心窝子说：别搞什么万能的大相机，要像搭积木一样用一堆小相机，最后通过一个管理栈把它们**混合 (Blend)** 起来。设计师能随便调参数，导出设置就能生效，甚至能把摄像机数据直接塞进角色动画里，这样切战斗或过场时就能自动调用合适的镜头。调试工具也很给力，开了**手动相机 (Manual Camera)** 模式还能双屏分别控制，方便排查 BUG。

[Recaps]

最后聊聊设计方法论。很多大牛容易陷入“设计原教旨主义”（Design Fundamentalism），非要争论什么才是“真游戏”，动不动就拿科学标准压人。其实咱们手里的概念，比如经典的“机制 - 动态 - 美学”框架，还有那个著名的“魔法圈”（Magic Circle），本质上都是“水手结”，是用来解决具体问题的工具，而不是绝对真理。真理在于“效用”（Utility），只要能把活儿干漂亮，哪怕是反直觉的创意也得给它留着。所以大伙儿别纠结定义，多想想怎么把这玩意儿用得顺手，让设计本身成为你的修行，享受那种创造快乐的美感就够了。

独立工作室 Tiger Style 面对“无枪游戏”的创新困境，想探索 iOS 平台新玩法。本文总结他们如何通过废弃原型、调整设计重心，把一款洞穴求生改成强调生态互动的创造型游戏。

[Recaps]
Randy 这次主要聊了《Waking Mars》是怎么从一堆废弃原型里抠出来的。起初团队想做像《蜘蛛：布赖庄园的秘密》那样的创新，但在新项目上纠结了很久。他们试过画地图生成世界、机械臂操作等方案，最后发现单纯做“洞穴探险”太枯燥，就像《古墓丽影》没什么新意。于是灵光一闪，把场景搬到火星，核心机制从“生存破坏”变成了“生态创造”。这一招彻底扭转了方向，让游戏不再是为了活命，而是为了培育生命。

在机制打磨上，早期的 Demo 有个氧气倒计时，结果逼着玩家不敢探索，反而增加了焦虑感。还有那个“月球着陆器 (Lunar Lander)"式的喷气背包，虽然真实但上手太难，加上手电筒占满屏幕导致视线受阻，这些体验都被砍掉了。Randy 提出了个关键概念叫“交互密度 (Interaction Density)"，意思就是玩家每做一次操作，得到的反馈要多快多明显。如果种个草要跑半天流程，那就是“做家务”，玩家会腻。最后定下的核心玩法是扔种子，因为物理碰撞（比如撞到蝙蝠掉落种子）天然符合这种高密度反馈，玩家凭直觉就能理解复杂的物理规则，不用教就会玩。

到了关卡设计层面，他们意识到不该搞太复杂的数值平衡，比如控制碳氧比之类的策略游戏那套，这对动作游戏来说是负担。后来简化成了只要生物量达标就行，这样就把复杂度下放到了底层交互。他们还用了“视距细节 (Level Of Detail)"的技术手段，允许某些生物互动在屏幕外悄悄发生，既保持了世界的生机，又省了性能。最妙的是强化了碰撞的意义，比如撞飞东西会让敌人逃跑、植物会生长连锁反应，这就是典型的“涌现式玩法 (Emergent Gameplay)"，让玩家觉得自己在玩一个活的世界，而不是按剧本走路。

最后一点心得是关于决策心态。作为独立开发者，他们有资本去试错和砍内容。通过高频次的“内部测试 (Playtesting)"，他们看到了什么真的好玩，什么只是自嗨，从而果断删改。Randy 认为，创新不能指望第一次就成，得有勇气推翻重来。最终这游戏不再是单纯的洞穴或种田游戏，而是一个基于物理模拟的动态生态沙盒，证明了把重点放在“创造可能性”而非“制定规则”上能行得通。

- **Speaker:** Scott Rigby (Immersyve)

### Overview


### Content Summary
[TLDR]
动机不止内驱外驱那么简单，满足基本心理需求（胜任、关联、自主）才是长期留存的关键。

[Background]
针对开发者只看行为数据忽略动机的痛点，指出单纯靠外在奖励难保长期活跃，揭示如何通过满足心理需求实现真正留存，适合全体从业者深入理解玩家心理。

[Recaps]
别再用“斯金纳箱 (Skinner Box)"那一套来忽悠玩家，把人当老鼠喂饲料的时代早过了。演讲大神说动机是条连续谱，从完全外部推到内部整合都有不同层次。侄子拆乐高重搭的例子说明，Autotelic Motivation（自足性动机）才是最高级的快乐，不求结果只求过程。外在奖励也不是洪水猛兽，关键看能不能帮玩家达成 Internalization（内化），把任务变成自己的追求。

想搞长流水，三大心理刚需一个都不能少：Competence（胜任感）、Relatedness（关联感）、Autonomy（自主感）。胜任感别光看数值成长，像《塞尔达传说》拿到道具就能探索新世界才算真胜任；关联感不是加一堆好友，是像 COD 组队时那种生死托付；自主感就是像《荒野大镖客》发现各种奇葩解法，觉得自己能掌控局面。需求满足了，忠诚度和口碑自然就来了。

还要小心 Undermining Effect（削弱效应），一旦明确告知做了就有钱拿，大脑对游戏本身的兴趣就会断崖下跌。别总把重复劳动说成“搬砖”，如果目标是像 WoW 里的机械兽那样有意义，那就是 Pursuing（追求）。设计者的角色应是 Facilitator（促进者），别让“内摄调节 (Introjected Regulation)"（比如愧疚感弹窗）逼退玩家。少用“鲸鱼”这种词，多收集 Motivational Metrics（动机指标），光看行为数据太浅，知道玩家“为何而玩”才能留住人心。

## Inspiration from the Trash: The TRS-80's Lost Game Designs
- **Speaker:** Jim McGinley (Bigpants)
- **Duration:** 54 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015922
- **Slide Page:**

### Overview


### Content Summary
[TLDR]
老旧硬件限制催生出独特的精准对齐美学，主张现代开发者应从旧时代约束中挖掘高密度与精细手感的灵感。

[Background]
演讲者复盘了 30 年前 TRS-80 电脑的硬件限制，揭示了那些被遗忘的独特设计美学。旨在提醒现代开发者反思当下游戏过度顺滑的弊端，从中汲取提升操作手感与设计密度的经验。

[Recaps]
这位老哥的核心意思就是，当年的破电脑虽然硬件太差，但逼出来的设计反而更有味。那时候电脑的分辨率 (Resolution) 低得离谱，只有 128 x 48，而且像素 (Pixel) 又高又怪，画面看着很丑。但正因为屏幕小、性能弱，开发者没法搞什么花里胡哨的光效，反而把精力放在了玩法的精准度上，这就形成了一种粗糙却扎实的审美。

现在的游戏物理引擎 (Physics Engine) 做得太丝滑，反倒在操作上丢掉了那种硬碰硬的爽感。老游戏里的碰撞检测 (Collision Detection) 特别硬核，像素一大，玩家就能清清楚楚地感觉到自己贴着边缘走还能刚好不死。这种“千钧一发”的惊险感，比后来那些滑溜溜的移动要好得多。像《Outhouse》这类的游戏，敌人一枪就倒，没有那种耗血的垃圾时间，这就是纯粹的动作节奏。

除了硬件，还有些设计细节值得借鉴。比如有个叫《Defense_Command》的游戏，它的互动过场 (Interactive Cutscene) 设计得很骚，你以为那是固定剧情的过场动画，结果你居然能开枪干预结果，给了玩家一种错觉的控制权。另外，老游戏非常注重帧率 (Frame Rate) 管理，有些运行在 20 帧也能跑顺溜，关键在于控制节奏。别总想着填满大地图，那种高密度、快节奏的关卡设计，能让玩家始终保持警惕，不至于玩着玩着想睡觉。

总结一下，大家别被高清分辨率绑架了。有时候故意把像素做大点，移动粗粝点，能让玩家觉得自己掌控了全场。就像当年的方块游戏一样，小地图加上大目标，反而更容易让人上瘾。这些 30 年前的土法子，其实就是教咱们怎么用有限的资源做出更有质感的手感，而不是堆砌毫无意义的视觉特效。

## Interesting Decisions
- **Speaker:** Sid Meier (Firaxis Games)
- **Duration:** 60 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015756
- **Slide Page:** 
- **Custom ID:** 1015756

### Overview


### Content Summary
[TLDR]
游戏设计的本质不是堆砌功能，而是围绕“有趣的决策”构建，让玩家在权衡代价与后果中获得真实的掌控感。

[Background]
很多开发新手容易陷入“乐高式”误区，简单地把热门游戏的特性拼凑在一起，结果做出来的东西毫无灵魂。这次 Sid Meier 的大佬现身说法，专门教大伙儿怎么识别和设计那些能真正留住玩家的决策点，无论你是做策略还是动作，这套逻辑都能帮你避开填坑，找到游戏的核心乐趣。

[Recaps]
什么是有趣的决策？说白了就是不能让你一眼就看出选哪个最好，也不能完全是纯运气。最核心的要素是引入权衡 (Trade-off)，比如你想买把大剑得扣一大笔金币，或者选辆快车但操控变差。这些选择还得具备情境性 (Situational)，得跟当下的战场局势挂钩；同时要有持久性 (Persistence)，早期的决定可能会影响后面的好几步棋。如果不管选啥结果都一样，那电脑自己替玩家选了就行，没必要让玩家上手。好的设计就是让玩家觉得每步棋都走在了刀尖上，但又充满期待。

在设计执行上，别一上来就把信息全部倒给玩家，新手容易被吓跑。我们要利用好类型惯例 (Genre Conventions)，比如 FPS 射击键默认在哪大家都懂，这样省去了教育成本，再在这些基础上加一点新花样。同时还要考虑决策的层级，短期战术要灵活，中期战略要清晰，长期目标要像“再来一局”的钩子。测试的时候也别太天真，玩家里有为了赢输不起的“必胜先生”，有死磕数值的“最小最大先生”，还有总觉得 AI 作弊的“偏执狂”。你得学会过滤他们的反馈，只吸取有用的部分，不然容易把自己搞疯。

到了打磨阶段，最狠的一招就是“删减”。有时候你会发现某个机制改来改去都不好玩，那就直接砍掉，别让半成品拖累整体。记住，决策不是目的，而是手段，它必须服务于游戏的幻想世界。无论是历史背景还是科幻设定，都要通过视觉、音效把这些决策包装得更酷。最后一定要建立快速的决策反馈循环 (Decision Feedback Loop)，反复迭代，哪怕离上线很近了也要敢于推翻之前的方案，因为最后成品好不好，不看设计了多少功能，只看最后留在玩家脑子里的那些爽瞬间够不够多。

[Background]

[Recaps]
想让游戏让人开心，其实比制造愤怒或恐惧难得多。这次分享的核心是给小宝宝做体感游戏的血泪史。主要痛点是小孩身体控制力还没发育好，这叫本体感觉 (Proprioception)，他们经常分不清左右手，动作幅度也小。所以设计时必须极度宽容，手势判定放宽，左手换右手都行，只要大概在动作范围内就算成功，千万别搞那些繁琐的纠错，否则孩子一会就哭。

## Flexible Rendering for Multiple Platforms (Presented by NVIDIA)
- **Speaker:** Niklas Frykholm, Tobias Persson (BitSquid AB, BitSquid)
- **Duration:** 48 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015770
- **Slide Page:** 
- **Custom ID:** 1015770

### Overview


### Content Summary
[TLDR]
放弃硬编码堆砌，用 JSON 配置驱动整个渲染管线，配合工具引擎分离，轻松搞定多平台适配与快速迭代。

[Background]
针对跨平台开发中硬件差异大、游戏类型杂导致的引擎臃肿痛点，BitSquid 分享了一套轻量化、数据驱动的渲染架构与工具工作流经验，适合中小型团队寻找平衡性能与生产力的方案。

[Recaps]
这哥们儿开门见山，说咱们公司虽然年轻，但理念特实在：代码越少越好。为了不让系统耦合得像八爪鱼一样难维护，他们坚持“数据导向设计” (Data-Oriented Design)，把 20 万行包含工具在内的代码全部压箱底，核心逻辑全塞进配置文件 (JSON configuration files) 里。这种设计让引擎特别轻，不管是跑 PC 还是主机甚至高端手游，都能通过改配置灵活调整，不用动不动就重构 C++ 代码。

核心难点在于怎么把复杂的渲染步骤拆开还能跑得快。他们用“数据驱动渲染管线” (Data-Driven Rendering Pipe) 替代传统硬连接。所有着色器调用、GPU 资源创建、渲染顺序，统统由文件控制。比如定义好几个“层级配置” (Layer Configuration)，每个层级决定画什么、按什么顺序排。为了实现并行，系统会给每个绘制命令打上 64 位的“排序键” (64-bit sort key)，后端收到一堆数据包后，根据这个键值统一排序再发出去。因为指令都是自包含的数据包，多线程处理也不容易出错，效率还高。

工具链这块更是骚操作，工具和引擎完全剥离开。编辑器通过 TCP+JSON 去控后台运行的引擎实例。就算引擎崩了也只是重启一下子进程，编辑器不会挂，还能直接上真机调试。为了照顾美术同学，他们还做了个“艺术家性能显示界面” (Artist Performance HUD)，直接把帧率和显存占用拆分成不同“桶”，标出预算红线，让大家一眼就能知道哪里优化过头或不足，彻底告别盲猜性能问题。

### Content Summary

[Background]

[Recaps]
老乔什上来就说了个大实话，现在的 RPG 分支对话 (Branching Dialogue) 容易出问题。为啥？因为有时候你想玩个坏蛋角色，结果游戏机制告诉你这样拿不到好东西；或者为了赢对话必须说话带刺，结果你原本想做个正人君子却被迫成了混蛋。这就是在设计 故事代理权 (Story Agency) 和 角色代理权 (Character Agency) 时打架了。好的设计不应该强迫玩家为了通关牺牲人设，而是要让所有的表达方式都在游戏支持的范围内，不管是当好人还是当混蛋，都能走出一条路来。

[Background]
很多开发者以为虚拟经济只要高效就行，结果玩着没劲。演讲者从经济学角度拆解了货币属性，提倡为了游戏体验故意制造“缺陷”，让玩家有更多博弈和故事可讲，适合想优化内购和经济系统的主策看。

[Recaps]
咱们先聊透底账。不管是真金白银还是游戏道具，定义上没差别，核心就三件事：做交换媒介 (Medium of Exchange) 让大家买东西方便，做价值储存 (Store of Value) 保证存款不会变废纸，做价值尺度 (Measure of Value) 帮东西定价格。以前人互相对换货太麻烦，得正好凑双份需求才行，现在有了通用货币就不愁这个。在网游里，虚拟经济和市场经济道理差不多，别老把系统设计搞混了，一个是定规矩，一个是设计那堆数字。

传统经济学讲究“好钱”得全能：方便携带、能切分、防小偷、隐私好。但在游戏里，太完美的货币意味着无聊。大佬们建议故意设计点“缺点”来整活。比如让金币超沉，像早期 MMORPG 里背一大袋铜币跑图，累死你；或者让钱会过期，像哈比酒店的可乐罐当钱，存久了坏掉，逼着你花钱消费而不是囤积。这看似反人类，实则增加了玩家的操作空间和生存压力。这里涉及到的关键属性包括不可分性 (Divisibility) 和 可替代性 (Fungible)，打破它们往往能带来意外的趣味。

这种“烂钱”设计有个爽处就是强拉社交和博弈。要是钱不能精准切割，你就得拿别的道具凑差价，买卖过程多了聊天环节；要是钱容易被抢，运输货物的时候就有心理战了，像 EVE 里护矿就是高风险高回报。而且有些钱能展示给别人看，有钱人就忍不住装 X，引发新的交易需求。当然，这一切的前提是这钱好歹得能花在刀口上，要是连 NPC 都不认，那就彻底凉了，毕竟所有货币最终都得有价值支撑。

### Content Summary
[TLDR]
免费游玩（Free-to-Play）模式常被批毁游戏，但优秀设计能平衡商业与体验，核心在于拒绝“付费赢”并保持公平的竞技环境。

[Background]
这场圆桌会直指一个行业痛点：为了搞钱（商业化），免费游玩（Free-to-Play）模式是不是必然要牺牲游戏的艺术性和公平性？几位资深制作人现场开撕，探讨如何在维持营收的同时，不让玩家觉得被掏空了钱包还毁了体验。

[Recaps]
主持人 Tom Chick 开篇就吐槽，很多经典单机变免费后就像被强拆装修成了商场。比如《魔戒 Online》里，原本诗意的夏尔被到处乱建的收费按钮搞得面目全非；《英雄联盟》因为英雄太多导致新手根本玩不明白，体验变得碎片化；《喷射背包》虽然好玩，但关键道具太贵，玩家靠肝永远买不起。他的核心观点是：为了赚钱，免费游玩（Free-to-Play）往往破坏了设计初衷，让商业逻辑侵入到了本该纯粹的魔法圈（Magic Circle）里。

关于怎么解决这问题，来自 EA 的 Ben Cousins 提出了三种商业化阶段论。第一阶段是直接卖皮肤，第二阶段是“收保护费”，即游戏难打时逼你花钱买捷径，这叫“负向付费”。最理想的是第三阶段，比如送花而不是治病，利用惊喜、社交和随机奖励让玩家开心地掏钱。他建议利用双货币系统，大部分物品既能赚也能买，只留少量稀有物品给纯粹的非付费党当荣誉象征，避免贫富差距直接体现在数值上。

另一方面，David Edery 和 Soren Johnson 则从道德层面辩论。David 认为富人对穷人是一种“累进税”，有钱人买单能让全世界更多人免费玩到游戏。但他也强调不能过度卖弄“即时满足（Instant Gratification）”，像 Soren 举的那个棉花糖实验一样，好游戏应该引导玩家学会延迟满足（Delayed Gratification）。如果允许玩家随便花钱跳过所有流程，游戏就失去了教育意义和成就感，设计师不再是服务玩家，而是变成了帮商家收割韭菜的机器。

最后大家达成共识，真正的出路在于“价值互换”而非“数值碾压”。比如《军团要塞 2》里的 Side Grading（横向替代），新武器伤害一样只是手感不同，既满足了个性化又没破坏平衡。虽然免费游玩（Free-to-Play）已成大趋势，但像《星际争霸》这种追求绝对公平的游戏，以及中小团队做的精品付费游戏依然有一席之地。关键在于别盯着那些毫无自控力的鲸鱼玩家（Whales），而是要为愿意花时间磨练技术的普通玩家保留尊严和乐趣。

做续集别瞎拆家，核心机制和角色不能丢，但必须根据玩家实测反馈大胆迭代和取舍。

[Background]
很多人觉得《传送门 1》已经完美了，续作难做。Valve 内部有人想继续开发，分享重点是如何在保留核心体验的同时优化新手引导，并解决多人合作模式的叙事节奏问题。适合关卡设计和叙事策划学习。

[Background]
这位在 Volition 干了 10 年的老大哥，主要分享《红色派系：末日审判》在全场景破坏环境下，如何让特效不只是“烟花秀”，而是真正指导玩家操作的实用技巧。适合想了解实战流程的特效同行或策划读。

[Recaps]
这哥们儿直接戳破了一个行规，很多人以为弄好视觉特效 (Visual Effects) 就是整点酷炫爆炸。其实核心在于视觉传达 (Visual Communication)，说白了就是给玩家的反馈 (Feedback)。比如打爆个怪，血花的大小、溅射的方向都不需要文字提示，玩家看一眼特效就知道伤害高低以及敌人位置。这里最大的坑是脱离语境 (Context) 调效果。别总在灰盒 (Gray Box) 里玩单机模式，不放在游戏环境里对比大小，谁都不知道“再大一点”到底是多大。

至于怎么迭代，作者说了句实话，第一版往往是一坨屎，别太爱惜羽毛。比如黑暗洞穴里的油桶，一开始看不清还以为是装饰，后来改成带警示灯的“燃料舱”，玩家才敢随手拿起来扔。还有导航系统，试过几十种箭头，最后用全息球投影的光标才是最优解。只要效果好，哪怕是被吐槽的设计也得认账，毕竟最终是为游戏体验服务的，而不是为了满足艺术家自己的面子。

## Cinematic Game Design IV: Character & Empathy
- **Speaker:** Richard Rouse III, Marty Stoltz (Paranoid Productions, Big Huge Games/38 Studios)
- **Duration:** 54 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015520
- **Slide Page:** 
- **Custom ID:** 1015520

### Overview


### Content Summary
[TLDR]
利用电影化叙事技巧结合游戏独特互动机制，打破屏幕隔阂，让玩家真正穿上角色的鞋子感同身受。

[Background]
游戏常被吐槽叙事太硬，不如电影有代入感。这篇演讲就是为了给开发者支招：别光抄电影的皮，要用玩法把观众变成体验者，借助人性的弱点做深度角色塑造，适合剧情向项目的设计师参考。

[Recaps]
这场**Cinematic Game Design (电影化游戏设计)** 的核心其实就是怎么让游戏比电影更能做到**Empathy (共情)**。演讲者开篇就强调，电影擅长让观众代入主角，但游戏有天然优势——你能亲手操作。首先要注意角色的第一印象，就像《Halo》用战斗确立士官长的猛度，《Uncharted》让玩家开局就跟主角一样“懵圈”，迅速拉近距离。更狠的是要把**Conscious Narrative (显性叙事)** 和**Unconscious Narrative (隐性叙事)** 结合起来。像《Eternal Darkness》那种老游戏，通过删存档、黑屏警告等操作，直接让玩家跟着角色一起怀疑人生，这才是真正的技术流，把玩家的生理焦虑和角色精神状态完美同步。

其次是怎么给角色立动机和转折。故事得有根，比如《Fallout_3》直接从出生演到长大，让玩家亲自培养父子情，后期寻父才顺理成章。到了人物命运大转弯的地方，像《Splinter_Cell_Conviction》里揭露好友背叛，不仅是剧情爽点，还直接给了无限攻击力的反馈。还有视角的切换大法，《Bioshock_2》当保姆小萝莉视角时，血腥世界瞬间变成童话滤镜，让玩家明白孩子眼中的残酷是多么不可思议。这种视觉上的“变色龙”效果，配合《Fable》或《Mass_Effect》里的道德选择系统，能让玩家直观看到善恶带来的外观和技能变化，沉浸感拉满。

最后是关于那些“非人类”和“大反派”的处理。《Portal》系列是个绝佳例子，GLaDOS 从想杀你到最后被困土豆里求你帮忙，这种权力关系的倒置，让玩家从对抗变成了某种程度的同情。就像 Elvis 歌里唱的，如果能进彼此的大脑看世界，你会惊讶于他人的盲点。演讲者认为，游戏不仅仅是娱乐，它有一种独特的责任去扩展玩家的 worldview，让我们透过别人的眼睛看世界。别总想着画面有多炫，得琢磨怎么用互动机制让人心里头“疼”，这才是顶尖设计的精髓所在。

## Android Gaming on Tegra: The Future of Gaming is Now, and it's on the Move! (Presented by NVIDIA)
- **Speaker:** Lars Bishop, Marek Rabas (NVIDIA, Madfinger Games)
- **Duration:** 48 分钟
- **Category:** Game Design
- **Video Page:** https://www.gdcvault.com/play/1015768
- **Slide Page:** 
- **Custom ID:** 1015768

### Overview


### Content Summary
[TLDR]
NVIDIA 老哥详解 Android 纯原生架构与生命周期陷阱，教你优化功耗并实现主机级大屏体验。

[Background]
新入坑 Android 的大佬容易在 Java/C++ 混合、生命周期崩溃和功耗上翻车。这篇演讲是 NVIDIA 整理的避坑指南，重点讲怎么用最少的 Java 写出高性能原生游戏，特别适合想适配 Tegra 设备优化的开发者。

[Recaps]
各位老哥，想搞 Android 游戏开发别瞎忙活，先下个 Tegra Android Development Pack (TadP)。想走纯原生路线？可以，但别以为就能无视 Java 了，Android 底层还是基于活动 (Activity) 类管理的，所以得用原生活动 (Native Activity)。这玩意儿直接把系统回调扔给 C++，让你少写 Java，但原生活动本身没有主函数入口，全是事件驱动。强烈建议大伙 fork 一份 Google 的 原生应用粘合剂 (Native App Glue)，把它改写成自己的库。这样能把零散的生命周期事件变成队列，不用担心被系统判定为无响应卡死，还能方便地随时扩展功能，这招亲测好用。

最要命的其实是生命周期处理，很多新手都在这里栽跟头。原生代码不能直接 return 就退出了，得靠 Java 层发回调通知。特别是返回键 (Back Button)，如果你没自己拦截，默认行为是直接杀进程，这操作太骚了，用户绝对会炸毛。另外 manifest 配置文件里得把开关调对，不然写了 Java 代码系统也看不见。要是搞内购或者弹对话框这种 UI 功能，老老实实地 subclass 原生活动写点 Java，非要死磕  Java 本地接口 (JNI) 只会导致代码膨胀十倍，纯属没事找事，听劝别硬刚。

性能跟功耗是鱼和熊掌，Tegra 这种多核处理器得把线程跑起来才能降频省电。做引擎时注意内存访问，尽量让所有核心同时干活，GPU 调试用 PerfHUD ES，CPU 看 O-Profile。千万别死命开 唤醒锁 (Wake Locks)，挂机时别硬扛着屏幕亮着，暂停游戏就把 陀螺仪 (Gyro) 和 加速度计 (Accelerometer) 关掉，不然电量瞬间掉光。传感器数据还得做个 传感器融合 (Sensor Fusion)，不然 gyro 漂移了你都没法玩。至于手柄映射更是个坑，不同厂商轴键定义都不一样，必须内置校准面板让用户自己配，默认配置根本不够用。

最后聊聊主机级大屏体验，这是加分项。通过 HDMI 输出支持 1080p 甚至双份渲染的 立体 3D (Stereo 3D)。记得 UI 元素放在深度 0 层，不然容易穿模。大屏上光影特效太吃资源，动态调整分辨率和像素效果，别让引擎硬撑。最后现场演示了 Shadowgun 的多人对战，画面确实顶，有能力的兄弟可以去试试 Tegra 平板，真的能把手机变成小主机，体验感完全不一样。

核心在于优先保证玩法趣味性，用局部化抽象替代复杂物理模拟，并善用涌现式玩法激发社区活力。
[Background]
针对独立开发者常遇到的“过度设计”与“玩法验证”难题，Notch 用 Minecraft 实战经验告诉你如何平衡系统设计与玩家乐趣，适合中小规模团队避坑参考。
[Recaps]
Notch 开篇拿女儿提问树为啥不倒切入，直言电脑太笨，没必要搞全套**物理模拟 (Physics Simulation)**。他在 MC 里只做**局部判定 (Local Effects)**，比如挖了树底树就浮空，反正不影响玩就行。要是真做了重力连锁反应，玩家一铲子下去山崩了，复杂度直接爆炸。他还强调主题是为机制服务的，科幻或奇幻只是让用户快速理解机制设定的捷径，核心还是看交互好不好玩。比起严肃真实感，像苦力怕这种带点荒诞的**涌现玩法 (Emergent Gameplay)** 更讨喜，后期他故意让狼追着羊跑，把意外当成特色保留下来。

系统设计上，制作表特意不加搜索栏，逼迫玩家上网查 wiki 或问朋友。这个决定意外引爆了社区传播，证明了留给玩家探索空间比封闭指引更有效。至于半块砖这种后悔加的设定，他说因为这会导致存档兼容性噩梦，改动一块砖能让玩家造的房子变鬼屋。所以修改现有特性可以，但删除已存在的积木基本不可能，否则激怒老玩家。此外他后悔晚加了联机功能，单机变联机是地狱难度的重构工作，切记尽早规划架构。

给开发者的建议很硬核。Notch 自己开发时一半时间在打游戏，推崇**缺陷驱动开发 (Flaw-driven development)**，一边玩一边找 BUG 一边修，保证核心循环好玩。编程语言首选 Java 因为编译快，提升个人**生产力 (Productivity)** 比追求极致性能更重要。商业上支持**付费测试 (Paid Beta)** 模式，像《Cortex Command》那样提前收费，能快速验证市场反馈，避免拿母亲的钱无限期开发。对于投资，他们看重项目的重玩潜力和团队激情，而非纯叙事体验。
