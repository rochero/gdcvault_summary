### Overview
This presentation teaches and explains not only how the API is  used, but also how to write stable, clean tools that can easily be  extended later.

### Content Summary
[TLDR]
做好技术美术工具的核心是前期规划与用户需求，根据场景选择 MEL 或 API，并注重代码的可维护性与效率平衡。

[Background]
针对很多 TD 写工具缺乏规划、后期难维护、效率低的问题，作者结合 Naughty Dog 的实战经验，教大家如何高效开发 Maya 工具，适合想进阶的技术美术和 TD 看。

[Recaps]
先把思路理清楚，别上来就敲代码。作者强调规划比编码更重要，先拿纸笔把功能Dependencies（依赖关系）画出来，能预判坑位。还要去问使用者到底想要啥，别搞一堆花里胡哨的“特效”功能，生产环境时间就是钱，工具越简单越稳定越好。代码要注释，还要模块化，把大堆操作拆成小函数，这样以后改动起来才不头疼，不然全是复制粘贴的代码简直是灾难现场。

MEL（Maya Embedded Language）这部分主要讲怎么在 Maya 里快速造轮子。比如右键菜单的自定义弹窗，可以通过修改 dagMenuProc.mel 脚本实现，给物体加个属性就能调用特定命令。还有 OptionVar 可以存全局偏好设置，不用每次都手动调。Pick Walk（拾取漫步）也是个黑科技，用 Message Attribute 连接控制点，按键盘上下键就能自动选到对应的骨骼或控制器。另外 MEL 里的数组是按引用传递的，这点很重要，传地址比复制数据快多了，还能一次返回多个类型的数据。UI 界面部分推荐用 Template（模板），定义好一套按钮样式，后面新建控件直接套用，统一风格又省时间。

当 MEL 搞不定性能或者需要深度访问内部功能时，就得上 Maya API。这是个 C++ 接口，编译成 Plug-in（插件）后速度飞快，但门槛高，得懂 OOP（对象导向编程）。这里分了三种主要形式：Commands 是自定义命令，做 Shape Snap 这种修改变化的操作时要设计好 undo/redo 支持，核心是把状态保存好；Nodes 是处理数据流的，输入变了自动算输出，比如 Poly Face Node 计算面法线；Locators 带形状显示的节点，能在视图里画东西，但这涉及到 OpenGL（图形库）渲染，比较麻烦。总之，能 MEL 就别 API，真要高性能或复杂逻辑再动刀子，而且一定要学会 MGlobal 类和错误检查，不然崩了都不知道咋回事。
