## Power Python Development for Maya
- **Speaker:** Jason Parks (Sony Online Entertainment)
- **Duration:** 61 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014364
- **Slide Page:** https://www.gdcvault.com/play/1014365
- **Custom ID:** 1014364

### Overview


### Content Summary
[TLDR]
别再死磕 Mel 了，转战 PyMEL 配合专业 IDE 和断点调试，能让你的 Maya 工具开发效率起飞，这才是行业顶尖玩法。

[Background]
讲者在索尼干了十几年技术美术，见过太多人卡在老旧的脚本模式里。这次想打破常规，教大家如何用更现代的工具链解决脚本难以维护、调试痛苦的大痛点，特别适合想进阶的 TD 和 TA。

[Recaps]
首先，赶紧弃坑旧脚本语言 (Mel)，拥抱 Python。虽然 Mel 曾是入门捷径，但在字符串处理、文件系统和日志模块 (Logging) 上远不如 Python 灵活。Python 支持对象化操作，能轻松返回复杂数据结构，而且代码可读性极强。哪怕你之前只会写 Mel，转学 Python 这种第二语言也会非常顺手，毕竟全行业标准都在这。

其次，别被 Maya 原生命令糊弄。原生的 Python 指令本质上是披着皮囊的 Mel，语法晦涩且功能受限。强烈建议上 PyMEL 封装库 (PyMEL)，它把 Maya 里的节点变成了类 (Class)，让你能用点号调用方法，比如直接查关节属性，不用死记硬背一堆 Flag 参数。虽然性能有微小损耗，但在 95% 的日常管线里完全不是问题，千万别为了那几毫秒牺牲代码的可维护性。要是遇到顶点遍历这种高负载场景，再考虑去调底层的 API (OpenMaya) 或 C++ 即可。

第三，工欲善其事必先利其器，脚本编辑器太简陋，必须得用集成开发环境 (IDE)。推荐免费开源的 Eclipse 或者付费的 Wing。最炸裂的功能是实时调试 (Real-time Debugging)，它能设置断点查看变量状态，这比满屏幕打印 print 语句强一万倍。老话常说迭代速度优于代码质量，有了调试器才能真正实现快速试错，让你的代码跑得飞快。

最后，讲者还抛了一个未来的脑洞：利用 PyMEL 的特性，可以把构建 Rig 的代码实例嵌入到元网络节点里。这样 Rig 就有了“大脑”，能自我查询或修改结构。这玩意儿在旧脚本里想做梦都做不出来，只有在 Python 加上专业 IDE 的环境下，才能支撑起这种高阶的对象化架构。

## Cinematic Character Lighting in STAR WARS: THE OLD REPUBLIC
- **Speaker:** Ben Cloward, Aaron Otstott (Bioware, Bioware)
- **Duration:** 58 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014360
- **Slide Page:** https://www.gdcvault.com/play/1014362
- **Custom ID:** 1014360

### Overview


### Content Summary
[TLDR]
BioWare 通过五种自动化光照技术，让 SWTOR 无需逐帧手调就能达成电影级且契合概念画风的角色表现。

[Background]
SWTOR 内容量巨大，人工为数千段过场逐帧布光需耗时数月，团队旨在开发一套自动化系统，在低成本下解决角色与环境分离及风格统一的问题。

[Recaps]
BioWare 这组分享直接解决了个大难题：游戏里角色要想像电影那样帅，通常得美术一对一给几千个过场打光，这人力成本太高了。所以他们反其道而行，不搞死磕写实的路线，而是定了个插画风的目标，追求游戏画面能和概念图一模一样。第一步就是用光照颜色渐变 (Light Color Gradient)，允许美术在模型周围画出一条颜色的渐变曲线，亮部、阴影交界处、背光的侧面都能独立配色调，连 Tython 星球树叶透过的绿色光线都能模拟进去，彻底摆脱了那种平面死板的漫反射感。

为了让角色在复杂背景里一眼被认出来，第二招是着色器 (Shader) 里硬算的轮廓光 (Rim Lighting)，这玩意儿不是真的在背后点个灯，而是通过算法算出来的背光效果，配合高光贴图能特意提亮衣服金属扣那些细节，防止人物跟背景糊成一片。第三步更是个狠活，叫光源方向控制 (Controlled Light Direction)，不管场景里太阳在哪，反正给人物设定的主光永远是相机侧后方一点的位置，保证不管剧情怎么切镜头，主角的脸永远是被照得最顺眼的那个角度，不用担心那种能把演员整废的大顶光。

遇到像地牢这种漆黑场景咋办？他们加了个天空高光 (Sky Specular)，算是种伪环境光，能在不破坏整体暗调的前提下，用柔和的光晕把人物的身体轮廓和环境细节给显形出来。最后一个是处理那些鬼灵精怪的透明特效，比如全息投影或者激光，常规的景深 (Depth of Field) 模糊会把它们弄得很假，所以他们搞了一套兼容 DirectX 9 (DX9) 的老古董方案来处理透明物的景深，近处的特效清楚，远处的慢慢变虚，完美适配各种奇怪的镜头调度。

## Ultimate Customization in Character Creation - Challenges and Innovations
- **Speaker:** Brad Stokan (Cryptic Studios)
- **Duration:** 53 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014370
- **Slide Page:** 
- **Custom ID:** 1014370

### Overview


### Content Summary
[TLDR]
靠一套强大的模块化系统和数据规则，Cryptic 解决了 MMO 角色创建中“自由度”与“穿模/性能”的矛盾。

[Background]
传统 MMO 捏脸系统往往顾此失彼，要么选项太少没得玩，要么太复杂新玩家根本搞不定。这场分享主要讲 Cryptic 团队如何在《Champions Online》这类项目里，搞定几千个部件的组合冲突、美术管线效率以及商业变现的平衡问题，非常适合做 MMO 或者高自由度角色定制的制作人参考。

[Recaps]
核心思路就是极致的模块化。为了不让左右肢体总是长得一样，他们搞出了非对称设计 (Asymmetry)，比如左腿可以比右腿粗，甚至一边是机械臂另一边是肉手。最狠的是他们坚持只做一个基础身体模型，全靠骨骼缩放 (Bone Scaling) 来变胖变瘦或长胳膊长腿，而不是像老派做法那样建十几个不同体型。这样做虽然技术难度高，但能让所有装备在任何体型下都兼容，彻底避免了传统换皮带来的资源冗余。为了实现这个目标，美术团队必须按严格的区域划分去建模，防止装备互相穿插。

技术流方面，他们搞了一套土办法解决生产力瓶颈。最关键是建立了数据定义系统 (Data Definition System)，用文本文件管理成千上万个部件的规则标签，比如“这件铠甲只能跟裤子配对，不能跟夹克混”，这样引擎就知道哪些零件会穿模，自动屏蔽冲突。美术工具也深度定制，比如 Max 里的镜像权重脚本 (Mirror Weight Script)，画好一只手另一边自动生成；还有引擎内的实时更新机制，修改材质不用重新导出，直接刷脸刷新，大大加快了迭代速度。

用户体验和商业平衡也是门学问。他们发现新手最怕满屏滑块，所以提供了预设模板 (Presets) 作为引导，但保留了高级参数给硬核党。到了《Star Trek Online》因为版权限制更严，就把自由度收束在头部细节，还加了个“外星基因”通道让玩家自己捏未发现的种族。关于收费内容，他们发现免费做的东西反而被拿来跟付费货对比挑剔，所以后期严格区分免费池和付费池。最后老哥还得靠社区反馈调优，毕竟谁知道玩家是喜欢自由还是喜欢官方指哪打哪呢。

## The Animation of HALO REACH: Raising the Bar
- **Speaker:** Tam Armstrong, Joe Spataro (Bungie, Bungie)
- **Duration:** 61 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014357
- **Slide Page:** 
- **Custom ID:** 1014357

### Overview


### Content Summary
[TLDR]
Bungie 证明通过零停机原则与数据驱动管线，可在保持旧版兼容性的同时大幅提升动画迭代效率。
[Background]
Bungie 剖析《光环：致远星》动画管线难题，解决迭代周期长、角色表演僵硬及新旧系统兼容性差的问题，为同类项目提供可落地的技术与管理方案。
[Recaps]
Bungie 这次主要是把自家《光环》系列的动画管线翻了个身，核心就三个字：效率高。他们立了三条规矩，首先是必须按时交车，其次得提升角色表演自然度，最重要的是别破坏旧系统。为此他们引入了专门的技术设计 (Technical Design) 岗位，充当缓冲带，把动画师从配置游戏数据 (Game Data) 的琐事里捞出来，让他们专心在软件里干活。最狠的一条是“零停机”，无论新旧系统怎么并，绝对不能因为内容错误导致游戏崩溃，保证大家每时每刻都在工作，而不是修 BUG。

技术上最大的干货是对移动动作 (Locomotion) 的重构。老引擎直接混编走和跑，脚容易飘。Reach 用了分段门控，把走、快跑、冲刺分块，中间过渡时间固定且短，解决了穿模和打滑。脚下适配也不再是生硬的锁定，而是利用逆运动学 (IK) 实时扭曲脚部轨迹贴合地形，上坡下坡脚掌始终抓地。此外，针对武器握持和射击姿势，他们改用数据驱动 (Data-driven) 的混合，不再预设死板的角度，动画师可以在编辑器里随意定义姿态样本，系统会自动计算权重，让开火和瞄准看起来更像真人在操作，而不是机械卡顿。

关于未来规划，他们承认现有的逻辑还是有点硬，后续打算上程序化剪辑选择 (Procedural Clip Selection)，让动画库自己连成网。还有一个重点是动作重定向 (Motion Retargeting)，希望以后一套骨架能通吃所有兵种，省得重复劳动。虽然这次没大提内存优化，但强调网络同步要求下核心逻辑必须全量运行。总结下来，这就是把艺术创作从技术束缚里解放出来的经典案例，管你们是不是 TPS 玩家，做项目的都该看看。

## Realistic and Interactive Clothing in Epic Games' Samaritan Demo Using NVIDIA APEX (Presented by NVIDIA)
- **Speaker:** Jeremy Ernst, Dane Johnston, Monier Maher (Epic Games, NVIDIA, NVIDIA)
- **Duration:** 34 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014667
- **Slide Page:** 
- **Custom ID:** 1014667

### Overview


### Content Summary
[TLDR]
借助 NVIDIA Apex 框架，美术能用 MAX 搞定实时布料、破坏与流体模拟，极大降低制作成本并提升画面表现。

[Background]
告别枯燥的硬编码，这套方案让美术主导物理效果。主要解决衣服布料、场景破坏等难题，工具免费且跨平台，是当时追求极致沉浸感的开发者首选。

[Recaps]
咱们先说做衣服这块儿，以前美术得求程序员写脚本，现在用 3ds Max 或 Maya 加插件就能干。核心是个“驱动网格 (Drive Mesh)"，这不需要太精细，但布线得匀，用来算物理数据。然后拿高精度角色模型通过“最近点锁定 (Latch to Nearest)"把它包在网格上。要是衣服比较厚，还得在人物身上挂个“运动学布娃娃 (Kinematic Ragdoll)"当内骨，防止布料穿模陷进肉里，操作起来跟画贴图差不多顺手。

接着导入虚幻引擎 (Unreal Engine)，只要材质 ID 对上号，衣服立马就能飘起来。这时候能实时开风速吹两下看看效果，还能开启调试模式，盯着那些碰撞点看是不是卡脖子。有个坑得注意，某些动画起手式会让衣服卡住，建议先把关键帧摆平再演。另外为了性能，系统支持多层级细节 (LOD / Level of Detail)，离远了就把物理计算降级，既不糊又省资源。

最后这 Apex 物理引擎 (APEX Dynamics Framework) 不止衣服，环境破坏也强。它能画张图告诉机器哪里该碎，甚至能用 GPU 算出上万块瓦砾往下砸。粒子效果也升级了，不再是死贴图，是真的有重量的，像烟或者水都能跟力场互动。听说这玩意儿还优化过主机的 SPU (协同处理器单元) 性能，以后免费公开，以后咱做大型项目不用愁特效卡壳了。

## Punching Above Your Weight: Small Art Teams, Big Games
- **Speaker:** Tim Appleby, Paul Greveson (SplashDamage, Splash Damage)
- **Duration:** 60 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014359
- **Slide Page:** 
- **Custom ID:** 1014359

### Overview


### Content Summary
[TLDR]
小团队不拼人手拼效率，靠脚本自动化和工艺简化，硬是用少人完成了复杂的游戏自定义系统。

[Background]
Splash Damage 是个小厂，做《Brink》时只剩几个人负责美术定制。面对老旧的 Doom 3 引擎限制和庞大的工作量，他们不想加班也不愿出烂活，于是决定把技术难点在前期全部攻克。适合所有关心开发效率和管线优化的同行参考。

[Recaps]
这个小团队最核心的经验就是别迷信“规划”，得敢于自己试错。既然团队只有三个人，那就不能指望引擎厂商给现成的功能，所以他们在预生产阶段就敢直接否定“变形目标 (Morph Targets)"这种大需求，因为引擎不支持。他们选择了一条更硬核的路，通过“纹理合成 (Texture Compositing)"和固定区域组合来规避实时模型变形的坑。这种做法虽然初期看起来麻烦，但能把风险彻底暴露在前期，避免到了游戏上线前才发现工作量爆炸，本质上就是用技术决策换来了可执行的时间表。

为了让几个人干几百万人活的活，他们把大量重复性劳动扔给了脚本。美术师在 Maya 里操作一个主模型，系统会自动调用“混合形状 (Blend Shapes)"和“包裹变形器 (Wrap Deformers)"，一键生成胖、瘦、中等三种体型的所有衣服和装备。甚至“蒙皮权重 (Skin Weights)"这种需要人工调整很久的工作，也可以通过脚本自动从平均体型复制过去。再加上强制统一的 UV 布局，保证了所有部件拼在一起时不会穿模或贴图错位。这套自动化流水线让团队真正摆脱了技术杂事的束缚，可以专心打磨画质。

最后是内容生产和协作的智慧。他们没像其他游戏那样设计零散的零件，而是设计了具有鲜明性格的“原型人物 (Archetypes)"，这样不仅风格统一，还减少了不必要的资产数量。武器和复杂道具虽然找外包做，但内部先把规格和流程死锁清楚，让外包变成延伸团队而非甩手掌柜。这种精细化管理加技术加持，让他们在引擎功能落后的情况下，依然做出了让人眼前一亮的自定义体验，证明了小团队的核心竞争力在于如何用最少的资源撬动最大的价值。

## PS3 & Xbox360 NARUTO SHIPPUDEN: ULTIMATE NINJA STORM 2 Exploring the 'Other Side' of Super Anime-like Visual Elements
- **Speaker:** Hiroshi Matsuyama, Isao Takeshita (Cyber Connect 2, Cyberconnect)
- **Duration:** 54 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014372
- **Slide Page:** 
- **Custom ID:** 1014372

### Overview


### Content Summary
[TLDR]
赛博网连接（CyberConnect2）通过自研工具链与简易图形技术，完美复刻了日式动画的“神作画”体验。

[Background]
很多游戏想做动漫风格但容易穿模或僵硬，CC2 基于《火影忍者》系列经验，分享如何通过工具和美术手法解决“动漫感丢失”痛点，适合做动作游戏的开发者参考。

[Recaps]
开发团队在续作制作上痛定思痛，针对前作遗留问题做了大量架构调整。首先是砍掉了角色模型的 LOD（Level of Detail，细节层次）方案，因为格斗游戏角色距离近，低模几乎没机会调用，直接废掉能省工数提升品质。接着利用合作伙伴 Bandai Namco 提供的技术库，直接用皮肤模型生成阴影（Shadow），彻底抛弃了繁琐的独立影模绘制。为了解决效率瓶颈，他们搞出了专用工具，比如让艺术家自己配置技能的技能编辑器（Skill Editor），以及让非程序员也能剪辑长片剧情演出的流程编辑器（Flow Editor）。甚至连角色面部绑定都细化到单根骨骼控制，方便夸张地做出漫画表情，整个工作流从依赖代码变成了依赖参数化设计。

美术表现方面，核心逻辑是用最简单的素材模拟最高级的动画效果，而非堆砌技术。为了还原“神作画”的动态感，他们用一张简单的纹理贴出运动模糊（Motion Blur），配合旋转镜头或背景图制造视差错觉，把静态场景变活。战斗特效采用多层半透明贴图叠加，利用后期处理融合成烟、水、火的感觉。特别是那种粗线条的漫画轮廓，其实是单独的多边形层压上去，配合 UV 动画随机抖动。连背景地图这种大工程，都是找手绘师画好平面图后，用透视贴图（Perspective Map）贴合到低多边形模型上，最后加滤镜搞定，成本极低但效果逼真。所有管线最终汇总在实时渲染引擎里，不需要额外渲染通道。

除了技术硬货，CC2 的团队文化也值得一看。全员在一个楼层办公，每个人都是三屏 setup，中间是制作软件，两边是主机预览和动画设定。更重要的是他们对源材料的极致研究，公司会买下所有周边、每一期杂志、每一张原盘碟，甚至派人去漫展蹲点观察粉丝反应。这种对原作 IP 的敬畏心和技术上的务实结合，让他们找到了平衡点：不追求炫技，而是追求精准还原日式赛璐珞动画的神韵。最后松山老哥放话，未来还会继续打磨自动化流程，毕竟日本动漫还是世界最强，我们要继续跟他们对着干。

- **Speaker:** Choong-Hyo Kim, Ju Bok Kim (Nexon, Nexon)
- **Duration:** 46 分钟

### Overview


### Content Summary
[TLDR]
实时辅助骨骼系统无需烘焙即可解决复杂关节变形，显著降低资产维护成本并减小包体大小。

[Background]
MMO 开发中角色定制需求大，传统烘焙方案修改难、体积大，且无法适配程序化动画，此项目分享如何解决这一痛点。

[Recaps]
现在的游戏做角色，骨骼绑定最怕遇到“糖果纸效应”(Candy Wrapping)，就是肩膀手肘这些地方一弯曲，皮就乱扭，像被糖纸裹住一样。以前老手都靠预烘焙的辅助骨骼 (Helper Joint) 来修补，比如“扭转骨”(Twist Bone)。但问题是，每次改动作都得重新烘焙，对于要搞大量服装换装的 MMO，简直是噩梦，而且包里塞满了数据，流量费都心疼。所以这俩来自 Nexon 的老哥决定自己造轮子，做个不需要烘焙、实时计算的辅助骨骼系统。

核心思路是把 Maya/3ds Max 里的约束控制器搬到引擎里跑。他们先研究了人类皮肤怎么动，发现比肌肉运动更直观。最难搞的是计算顺序，因为辅助骨骼可能指向还没生成的骨头，导致结果错乱。他们没写复杂的依赖分析代码，而是直接在计算时动态检测谁依赖谁，谁先算谁后算，哪怕中间换了层也不慌。为了保证美术不懵，尽量复用原生功能，不搞太邪乎的插件。如果碰到循环依赖，就直接提示美术改掉。

性能这块是重头戏，毕竟 MMO 里同屏人多。本来以为多线程就能行，结果发现 L2 缓存丢失成了大坑，因为调用内存地址太随机。他们用了“脏标记”(Dirty Mask) 技术，类似文件系统的更新标记，只有变了的数据才重新算父节点的“层级变换矩阵”(Order Transform Matrix)，否则直接跳过。还专门给“缩放变换”(Scale Transform) 做了个简化判断，反正大部分姿势没啥缩放，能省则省。针对这个内存访问问题，他们还追踪了访问顺序，提前把数据拉到缓存里，减少等待时间，就像去超市买好东西提前排好队，而不是走到哪算到哪。

另外搞了个“层级化”(Layering) 骨架系统，把身体、肌肉、衣服分成不同层。基础层的动作是预好的，衣服层只存辅助骨骼的设置，运行时根据距离动态卸载细节。这样美术加衣服就不用全套重导，只要发个配置表就行，质检也方便。当然代价是性能损耗没法完全消除，你得盯着瓶颈测优化，但这套流程确实让高质时装的制作变得容易多了，属于花钱买未来的长期投资。

[Background]
Epic 在开发《战争机器 3》时面临角色激增但人手不足的困境，旧管线混乱且难以统一管理外包质量。演讲者分享如何构建一套可快速迁移、兼顾效率与电影级精度的面部绑定管线，特别适合想提升绑定效率的同行参考。

[Recaps]
这次讲的是 Epic 在《战争机器 3》里怎么搞面部绑定的。本来团队就小，还要给 27 个过场角色做脸，如果每个手动去调整关节（Joints）那就累死人了。所以核心思路就是别一个个去动关节，而是通过控制属性来驱动，这样能生成干净的曲线数据，方便后期修整。为了应对外包，他还打包了可执行文件（Executable）而不是发脚本，确保大家用的都是统一工具。

为了既好用又能快速复制，他设计了一个四层结构的复杂绑定方案。第一层是低模笼子（Low Poly Cage）配合形变目标（Morph Targets），原理来自面部动作编码系统（FACS）。第二层是用定位器（Locators）把笼子的形变转为旋转数据，因为单纯形变没法做旋转。第三层是偏移绑定（Offset Rig），给最终关节留出微调空间，像微表情或者不对称表情都能在这里补回来。最后是游戏实际运行的骨骼。最神的技术点在于，新角色只需要把头模加进来当一个新的形变目标，整个架子和关节位置几分钟全带过去，彻底不用重新摆骨骼。

此外还有几招实用的优化技巧。为了让同一个模型既能应付远距离也能应付特写，他们用了相同的拓扑但不同的皮肤权重（Skin Weighting）来做细节层次（Level of Detail / LOD）。为了防止嘴巴闭紧或者做特定表情时脸部穿模，特意加了修正形变（Corrective Morphs）。为了皮肤看起来不假，还做了法线贴图（Normal Maps）的动态混合，让皱纹和肌肉绷紧感随表情浮现。最后他还抛出了一个未来计划：推行通用头部拓扑，以后建模师直接往标准头上套壳就能自动继承所有权重和修正，彻底解放生产力，这招要是真成了，以后做新角色至少省下一半时间。

## Beyond Horror: Art Directing DEAD SPACE 2
- **Speaker:** Ian Milham (Electronic Arts Redwood Shores)
- **Duration:** 60 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014368
- **Slide Page:** 
- **Custom ID:** 1014368

### Overview


### Content Summary
[TLDR]
资深艺术总监复盘《死亡空间》，如何平衡恐怖氛围与玩家记忆点，从“统一风格”转向“情感节奏”。

[Background]
针对首作成功后遭遇的视觉疲劳与剧情疏离痛点，分享如何通过色彩脚本和场景细节重塑体验，适合关心叙事节奏与美术管制的开发者。

[Recaps]
说起一代就是个典型的翻车现场。虽然确立了独特的哥特式建筑 (Gothic Architecture)，但太死板了，全程一个色调，玩家玩久了觉得全是褐色飞船。主角不说话虽强化了代入感，但也让玩家觉得自己像个听话的传令兵，跟剧情有隔阂。而且一直紧绷的恐怖感最后反而不吓人了，就像过山车只掉下去不爬上来一样，审美疲劳严重。

到了二代就是想着怎么给玩家加点猛料。美术组搞了个详细的色彩脚本 (Color Script)，把游戏当电影做情绪起伏。一开始用冷色调拉开距离，中间紧张时红绿色调拉满，最后政府区变成黑白红的高对比风格。环境不再套用单一纹理，医院用脏兮兮的瓷砖显真实，邪教总部用 DNA 螺旋元素区分，敌人造型也更贴合当地环境，一眼就能认出是个啥怪。

技术流这块更是玩明白了。利用延迟渲染 (Deferred Rendering) 特性堆叠大量光源，让金属走廊和烟雾效果成为品牌标识，顺便避开引擎不擅长的透明度问题。为了规避加载卡顿，利用遮挡物在过渡动画里悄悄完成细节层次 (Level of Detail)。另外 Demo 要做得极度自信来堵甲方改口的嘴，这些看似取巧的方法其实都极大优化了最终体验，有时候顺着引擎弱点走反而能成风格。

## Basically, We Sold Our Souls: The Art Implementation of INFINITY BLADE
- **Speaker:** Donald Mustard, Geremy Mustard (ChAIR Entertainment Group, Chair Entertainment)
- **Duration:** 73 分钟
- **Category:** Visual Arts
- **Video Page:** https://www.gdcvault.com/play/1014715
- **Slide Page:** 
- **Custom ID:** 1014715

### Overview


### Content Summary
[TLDR]
利用高内存与极致优化手段，在移动端实现了传统主机级别的视觉表现力。

[Background]
面对五个月极限工期和手机硬件瓶颈，Chair 工作室尝试用虚幻引擎 3 打造《Infinity Blade》。适合关注移动端性能挖掘、图形优化及工业化流程的从业者。

[Recaps]
讲真，去年这时候我还觉得手机上跑不出好游戏，但 Chair 工作室用实际证明我们错了。他们被 Epic 喊过来，就 5 个月时间，要做个能撑场面的 UE3 手游。核心思路很简单：别跟主机比架构，要跟玩家比感官。因为手机屏幕小且握持方式特殊，他们定了个死规矩——“四根支柱”：单手操作、碎片化体验、设备独占感、还有靠技术而不是运气赢的快感。为了展示精细模型，干脆把摄像机怼脸上，虽然牺牲了自由漫游，但能把每个角色的贴图细节拉满。

性能这块绝对是硬核干货。传统主机的逻辑在手机上是行不通的，比如默认的一个骨架要七八十根骨头，他们砍到六十根以内，甚至手指都简化。顶点密度也狠降，一个角色大概 3000 顶点就能搞定，还用了双权重的算法减少 Vertex Weights (顶点权重) 的计算量。最绝的是控制 Draw Calls (绘制调用)，主角身上所有装备不单独算，全塞进一张纹理图集 (Texture Atlases) 里，场景里的石头草丛也是合在一起渲染。哪怕有几百兆内存随便花，也不能乱堆多边形，每一笔都要花在刀刃上。

为了弥补硬件差距，美术组玩出了各种花活。既然没有强力动态光，他们就疯狂堆 Light Maps (光照贴图)，而且不仅仅是照度，他们通过工具把 Normal Maps (法线贴图) 烘焙进光照里，这样阴影就有凹凸质感，还不增加显存。远景更绝，直接拿照片合成或者画板子拼起来，假装是 3D 透视，省下一大笔开销。甚至连粒子特效都不用程序生成，直接用 Frame Buffer 截图做成动画序列。这波操作说明，只要敢想敢裁，移动端也能跑出主机级的画质，关键就是怎么压榨那一点点算力。
