### Overview


### Content Summary
[TLDR]
开源项目想壮大，光写代码不够，还得会算账、搞钱和哄好社区的大爷们。

[Background]
演讲者来自 GDQuest，主要讲怎么把 Godot 引擎从一个小众工具做成大厂级开源。适合独立工作室负责人或开源维护者看，解决资金少、社区乱、发展慢的难题。

[Recaps]
做开源软件 (Open Source Software) 最头疼的就是预算少，跟商业公司比可能差几十倍。所以首要任务是学会“抠门”，核心功能要少而精，其他交给插件 API (Plugin API)。搞钱方面别死磕捐款，企业赞助、众筹、甚至拿风险投资 (VC Funding) 成立服务公司养核心团队都是路子，有钱才能全员全职，效率才高。

产品做好了没人会玩也不行，所以学习材料 (Learning Materials) 得跟上。GitHub 对小白太难，建议用 GitBook。别觉得只有程序员能干活，让社区的画师、UP 主帮忙宣传，几百上千万播放量全是人家推出来的。因为隐私原因没法搞用户遥测 (Telemetry)，那就主动去 Discord 聊天，问用户真实目标和困难，这比冷数据准多了。

最后就是管人和管情绪，这是最容易翻车的地方。社区大了肯定有不同意见，立好规矩，公事公办，别扯政治宗教。需求被拒了别让人觉得是针对个人，要把路线图 (Roadmap) 说清楚。信任是攒下来的，愿景一句话讲透就行。把写代码的人培训成能安抚情绪的管理者，别光会敲键盘不会做人，运用同理心 (Empathy) 处理冲突，这样才能让大家愿意一直跟着干。平台也别整得太复杂，Blender 就有那种简单的投票网站让非开发者参与。GitHub 的讨论区门槛太高，有些专业人士懒得上去，你就得走出去问。还有，社区里难免有人带节奏或者吵架，这时候要有私人渠道处理，别在公开场合撕逼。

## Tabletop Summit: Reimagining Historical Settings in Game Design
- **Speaker:** Cole Wehrle (Leder Games, Wehrlegig Games)
- **Duration:** 61 分钟
- **Category:** Tabletop Summit
- **Video Page:** https://www.gdcvault.com/play/1029322
- **Slide Page:** https://www.gdcvault.com/play/1028843
- **Custom ID:** 1029322

### Overview


### Content Summary
[TLDR]
设计历史游戏别光换皮，得找准角色的能动性，让机制真正服务于历史逻辑，不然就是乱设坑。

[Background]
本演讲由桌游资深制作人分享，专门解决历史题材游戏中“主题与机制割裂”的问题。适合想做历史题材游戏的设计师观看，避免无意冒犯历史群体或造成设定灾难。

[Recaps]
讲者认为很多设计把**主题 (Theme)** 当皮肤贴，实际上**机制 (Mechanics)** 才是骨架。他用语言学比喻，机制是语法，主题词汇是内容。如果玩法不支持历史逻辑，硬套就会露馅。比如《Catan》早期美国版强行加入殖民元素，却没法处理原住民互动，就被批评为种族抹除。正确的做法是让主题词汇丰富且准确，而不是靠美术贴图掩盖设计的苍白。

接着给出实操方法：先画出“知识地图”，确认玩家是谁，以及他们的**能动性 (Agency)** 在哪。他举了自己做的《Pax Pamir》为例，起初想做间谍冒险，结果主角毫无决策权，后来改成政治代理人的权力博弈，才还原出中亚复杂的政权更迭。还有《John Company》通过三层美学风格，让玩家同时体验伦敦宫廷、印度战场与公司内部利益，营造出帝国扩张时的真实氛围，而非单纯的资源掠夺。

最后强调社会责任。玩反派不丢人，但必须提供足够语境防止误解。像《Puerto Rico》新改版纳入时间线限制，避开奴隶制这一机械学无法处理的痛点，反而更尊重历史。讲者还提到《Infamous Traffic》，最初让中国玩家扮演反殖民方压力太大，最后改为全员扮演英国商人，统一道德立场来反思贪婪。总之，游戏也是历史认知的一部分，设计师得对玩家负责，找到专为该背景定制的玩法，别硬凑。

## Tabletop Summit: Encouraging Emergent Narratives with Puzzle Design in 'Decorum'
- **Speaker:** Charlie Mackin (Independent)
- **Duration:** 0 分钟
- **Category:** Tabletop Summit
- **Video Page:** 
- **Slide Page:** https://www.gdcvault.com/play/1028766
- **Custom ID:** 1028766

### Overview
How do developers encourage players to see moving pieces around a board as a relationship argument? In this session, game designer Charlie Mackin breaks down how her team injected narrative into their puzzle designs, while still allowing each player's group dynamics to lead the interaction. She'll give specific examples from Decorum, a cooperative puzzle game themed around partners decorating a house together including puzzle design tricks and tips, mechanic and theme alignment, and how much in-box narrative is enough. Then, she'll talk more broadly about the importance of letting interactions happen naturally, and leaning into the player's own assumptions to create a more genuine exchange.

### Content Summary
[TLDR]
利用受限沟通与不平衡机制，诱导玩家在合作中爆发冲突再和解，实现涌现式叙事 (Emergent Narrative)。

[Background]
很多独立团队想做带剧情的游戏怕写脚本太难。这分享专门针对桌游或轻策略开发者，教怎么用规则逼出玩家真实互动，省掉硬编台词还能玩出感情戏。

[Recaps]
这次主要是唠怎么在不写死剧本的情况下，让玩家自己生成故事，这就是咱常说的“涌现式叙事 (Emergent Narrative)"。演讲者掏出了《Décorum》的干货，这是款双人合作局，两个室友得在摸不清对方底牌的情况下装修房子。最难搞的就是怎么把这两根独立的火柴凑一块，让他们从互相看不上眼变成真心搭伙过日子。

想让大伙儿愿意入戏，先得把氛围造足。这套玩法的核心配方是“共同胜利状态 (Cooperative winstate)"叠加“隐藏信息 (Hidden Information)"外加“有限沟通”。这几样一加，自然就能整出一种“被动攻击 (Passive Aggressive)"的同居生活 (Cohabitation) 味儿。因为没法直接摊牌喊需求，大家都只能瞎猜，猜不对就起冲突，这误会产生的劲儿就是好戏的燃料。

具体咋整全靠“谜题设计 (Puzzle Design)"动刀子。博主总结了三个骚操作：“聚光灯 (Spotlights)"就是硬把一个破灯泡做成焦点，逼双方都得蹭它；“注意力分散 (Split Attention)"是让大家盯不同角落，搞得鸡同鸭讲；“权力动态 (Power Dynamics)"则是故意搞个进度差，一方刚摆好，另一方就得拆。这种人为的烂摊子，最能逼着玩家把心里话吼出来。

最后得留个口子控制节奏，搞个“谈心时刻 (Heart to Heart)"。前面攒了一肚子火，这时候让大伙儿敞开了说，把怨气撒一撒。这一步能把重心从“刷副本”转移到“谈感情”上，才算圆满。说白了，就是用规则框住手脚，再用自由空间塞进玩家的情绪，这才是懂行设计师该玩的套路。

## Open Source Game Development Summit: Evolve a Legacy Game Engine With Open Source Tools
- **Speaker:** Kai Zhang (Netease)
- **Duration:** 45 分钟
- **Category:** Open Source Game Development Summit
- **Video Page:** https://www.gdcvault.com/play/1029267
- **Slide Page:** https://www.gdcvault.com/play/1028770
- **Custom ID:** 1029267

### Overview


### Content Summary
[TLDR]
网易通过引入开源工具与定制方案，成功将老旧引擎编译效率提升十倍并优化了整体代码质量。

[Background]
专为被庞大工程构建耗时、跨平台配置繁琐及技术债务缠身的游戏团队提供实战经验，展示了如何用开源生态解决传统工作流的性能瓶颈。

[Recaps]
咱们都知道老项目最怕什么？不就是编译慢如蜗牛吗？网易这个 NeoX 引擎以前全量编译得花半个多小时，改个渲染逻辑更是要等四十分钟，严重拖慢开发节奏。为了解决这个痛点，他们决定放弃原有的 CMake，全面迁移到了 Google 开源的**构建系统 (Build System)**——巴塞尔 (Bazel)。这玩意儿最大的优势就是能把编译过程做成**沙盒化 (Sandboxing)**，杜绝因依赖混乱导致的构建错误，而且天然支持跨平台。为了让老程序员的 IDE 习惯无缝衔接，他们还借助 Lavender 和 Tulsi 这些开源插件，让 Visual Studio 和 Xcode 能调用 Bazel 进行编译和调试，真正做到了效率与体验双提升。

光有快还不行，还得让服务器扛得住。网易专门搭了一套**远程缓存 (Remote Cache)**和**远程执行 (Remote Execution)**集群，把计算任务分发出去。这里有个大坑，当时主流开源服务端对 Windows 支持不太友好，导致增量构建还是慢。于是网易团队自己动手，基于 Python 写了一个自定义的远程 Worker，虽然只有几千行代码，但直接解决了 Windows 端的编译加速问题。他们还巧妙利用了 Clang 的调试前缀映射参数，把远程路径转成本地相对路径，彻底修好了远程编译后的断点调试失效问题。

除了编译速度，代码质量也是重中之重。以前用**静态分析 (Static Analysis)**工具 Clang-Tidy 跑一遍完整代码得要四十分钟，根本没法做到每次合并代码都检查。后来利用 Bazel 提供的**方面 (Aspect)**机制做精细的依赖追踪，现在只扫描改动的文件，效率瞬间起飞。同时配合**Include-What-You-Use**工具自动清理无用的头文件引用，他们把一个庞大的世界库硬生生拆解成了二十五个独立模块，不仅降低了耦合度，还让后续维护变得容易多了。

最后给大伙提个干货建议：别因为开源工具一开始不好用就弃之不用。遇到问题是常态，先在社区问问，没人回也别灰心。既然是开源，源码摆在那，有能力就自己改 Bug、加功能，最好记得反向贡献回上游社区。这样既能保证你的特殊需求不被后续更新破坏，也能让你的项目跟着工具的进化一起变强。这才是和开源社区打交道最正确的姿势。

## Open Source Game Development Summit: Render Graph, a Data-Oriented Approach
- **Speaker:** Zhenglong ZHOU, Huabin LING (Cocos Technologies, Cocos Technologies)
- **Duration:** 27 分钟
- **Category:** Open Source Game Development Summit
- **Video Page:** https://www.gdcvault.com/play/1029268
- **Slide Page:** https://www.gdcvault.com/play/1028845
- **Custom ID:** 1029268

### Overview


### Content Summary
[TLDR]
Cocos 开源团队揭秘：用数据导向渲染图（Render Graph）替代旧框架，实现管线动态修改与性能优化双重突破。

[Background]
传统游戏引擎渲染管线改起来费劲，调试也麻烦。Cocos 技术团队借此分享如何用新架构解决底层痛点，适合想深入引擎开发或关注性能优化的硬核玩家与同行阅读。

[Recaps]
Cocos 团队这次带来的核心就是渲染图（Render Graph），它是整个渲染管线的底层基建。开场先展示了个赛博朋克风格的射击 Demo，不仅跨平台丝滑，最牛的是能运行时动态切换管线，比如直接在编辑器关掉灯光或辉光效果。这得益于新架构的灵活性，不像以前改了底层代码就得重编译，现在配置层就能实时调整，真正做到了所见即所得。

讲者重点对比了传统的“帧图（FrameGraph）”与新方案。老路子用的是“控制反转（Inversion of Control）”，用户写回调函数告诉系统怎么跑，一旦流程定型很难修改。而 Cocos 用了“数据导向（Data-Oriented）”方案，把渲染任务写成数据描述发引擎执行。这样不仅能做无侵入式验证，还能在不改源码下插入 Debug 功能，比如直接截取中间纹理看光照结果，极大简化了测试工作流。

为实现这套逻辑，他们将图拆解为“命令图（Command Graph）”和“依赖图（Dependency Graph）”，前者管执行顺序，后者管资源流转。此外还设计了“描述符布局（Descriptor Layout）”来合并 Shader 的资源绑定，降低 CPU 开销。底层库直接基于开源的 Boost 图库（Boost Graph），利用其接口屏蔽差异保证缓存效率，并通过代码生成器打通了 C++ 与 TypeScript 双端支持，展现了极高的工程化水准。

## Open Source Game Development Summit: Simple DirectMedia Layer: Past, Present, and Future

### Overview


### Content Summary
[TLDR]
SDL 3 重构了构建与 API，推出统一 GPU 抽象，兼顾新旧兼容性，让跨平台开发不再被底层硬件劝退。

[Background]
跨平台开发就像在雷区走路，SDL 干了 25 年，专门负责把底层那些破事都挡掉。这课适合写引擎或者做移植的朋友，看看大厂怎么搞定多平台兼容性，顺便了解未来图形接口的方向。

[Recaps]
SDL 这兄弟从 Loki 时代就开始了，后来 Valve 接手并把它变成开源社区。以前搞维护容易踩坑，上了 GitHub 之后大家贡献热情高了。核心逻辑是保持稳定，他们甚至做了个 sdl2-compat 库，让老游戏在不改源码的情况下能在新版本上跑，这对维护经典项目非常友好，避免了被迫重写代码的痛苦。

SDL 3.0 这次是个大手术，主要是为了爽。构建系统统一用 CMake，砍掉了不少老古董支持，像 CD-ROM 这种早就没人用的功能直接被移除。API 也做了减法，比如创建窗口不需要手动定坐标了，让操作系统自动安排。最关键是鼠标控制，别再用什么鼠标瞬移（Warped）的土办法了，现在调用 SetRelativeMouseMode 直接拿原生输入数据，精度和延迟都拉满，尤其是做 FPS 游戏时手感提升巨大。

重头戏还是图形部分。高分屏（High DPI）适配一直是头疼事，SDL 3 统一了虚拟分辨率的概念，不管显示器多清晰，你代码里看到的都是整数倍的标准尺寸，系统会自动帮你切像素缓冲区。更厉害的是那个新的 GPU API，它屏蔽了 DirectX、Metal 和 Vulkan 的具体差异，你只需要写一套统一的指令集，编译器会把着色器生成一份通用的字节码，不用管具体显卡驱动。原本写个 Hello World 要上千行，现在一百多行就能搞定，而且天然支持多线程和沙盒环境，这才是咱们开发者真正需要的生产力工具。

## Tabletop Summit: Increasing Accessibility and Broadening Disability Representation in Tabletop Games
- **Speaker:** Morgan Baker, Jesse Martinez, Carol Mertz, Rachel Voss (Electronic Arts, University of Washington, Exploding Kittens, Forge Ahead: A Party To Access)
- **Duration:** 60 分钟
- **Category:** Tabletop Summit
- **Video Page:** https://www.gdcvault.com/play/1029321
- **Slide Page:** https://www.gdcvault.com/play/1028804
- **Custom ID:** 1029321

### Overview


### Content Summary
[TLDR]
别总想着治愈残疾玩家，要把障碍归咎于设计而非身体，无障碍设计能让所有人受益。

[Background]
许多开发者对残障群体缺乏了解，常把问题归咎于个人身体状况，导致角色刻画刻薄或缺乏真实感。这场演讲呼吁大家转变思维，用实际经验指导设计，让游戏真正能玩、好玩。

[Recaps]
主讲人 Rachel 开篇就撕开了行业遮羞布，指出很多开发者拿着剧本写残疾角色，这其实掉进了“健全中心主义”的坑。她建议用 社会模型 (Social Model) 替代传统的 医疗模型 (Medical Model)。简单说，别总想着“治好”玩家的肢体，而是想办法修平路面的障碍。比如在设计跑团道具时，与其强行给轮椅角色加双腿，不如设计能变形地面的魔法道具，让轮椅变成独立的工具，而不是需要被修正的错误。

中间提到的“路缘坡效应”特别有意思，这是指当初专门为轮椅修的路边斜坡，最后发现婴儿车、拉杆箱都能用。做游戏也一样，你给听障加字幕，听力好的也能看懂剧情；给色弱优化配色，大家都看更清楚。这就是为小部分人设计，却让大部分人受益。核心在于不要试图让残疾角色看起来“像正常人”，而是要尊重他们的存在方式。

最后的桌游案例非常硬核，以《Hand-to-Hand Wombat》为例讲实操。他们采用了 双编码 (Dual Coding)，零件既看形状也有触觉标记，确保不看脸也能分得清大小。他们甚至教玩家用手机代替沙漏计时，既省钱又适应不同感官需求。他们还提供了分阶段教程和官方修改规则，最重要的一点是：必须找残障玩家来 试玩 (Playtesting)。正如那句口号，“没有我们的参与就没有关于我们的事情”，这才是保证不雷不歪的唯一正道。

物理引擎 20 年演进：从游戏核心到 AI 训练基石，开源与神经网络正在重写模拟规则。

老哥干了七年手游，见多了 **软首发 (Soft Launch)** 失败，多半是起步的根基没打好。这次分享的是 **核心循环 (Core Loop)** 的设计心得，这玩意儿跟设计支柱一样是地基文件，必须得抽象出最简单的框架。规则特简单：只要是为了升级不得不干的就是核心循环，像社交、剧情这些选着玩的都不算。还得加上时间和难度摩擦，好比拧螺丝，有阻力才觉得有成就感，光爽没用。

循环里少不了 **门限 (Gates)**，用来卡进度也方便赚钱。主要分三类：**难度门限 (Difficulty Gate)** 看你水平，**刷资源门限 (Grind Gate)** 看你肝度，还有**时间门限 (Time Gate)** 让你耗着。移动端变现基本就两条路：要么充钱跳过等待，要么充钱提升效率防止进度归零。这里提到的 **货币 (Currencies)** 很关键，它是维持玩家在屏幕间体验连续性的线索，哪怕只是简单的经验值堆积也算。

实战案例全是血泪教训。《June's Journey》初期加了收集加装修双重元玩法，节奏打架，后来把收集踢出核心循环，日活立马飙升。《Tropic Cats》把刷资源门限换成难度门限，结果玩家卡住没法解锁新地图，Loading 慢还劝退。还有个侦探项目想把剧情解锁和等级解锁分开，结果代码量翻倍，状态混乱，最后还是得砍成单一循环。

最后敲黑板，核心循环千万别妥协分裂，也别搞双重锁，一旦卡住两个地方就完了。如果一个系统非强制，宁可当成可选项放进去。早期就得把原型跑通，别指望后期修补。地基歪了，后期堆再多内容是救不回来的，这就是用几百万学费换来的经验。

[Background]

[Recaps]
这演讲核心就是教怎么用花钱投广告来测游戏点子。叫市场性测试 (Marketability Testing)，简单说就是没做出游戏前，先搞个假应用商店页面 (Fake App Store Page)，跑付费广告看反应。主要盯两个指标：点击率 (Click Through Rate, CTR) 代表广告多吸睛，每安装成本 (Cost Per Install, CPI) 算拉新要多少血。要是早能测出大家愿不愿意点，项目立项就稳多了，不瞎烧钱。

最后给了几招实操指南，别把测试当唯一真理。变量差异要够大，比如改整体美术，光改名字没用。深挖数据看不同年龄表现，配合问卷或定性调研 (Qualitative Research) 听听用户咋想的，这叫知情决策 (Data Informed Approach)。尽量跟竞品比，别自己跟自己比一堆垃圾变体。记住，市场测试只是辅助，最终还得靠人的判断，别让数据把你带沟里去，不然就是无效预算浪费。

[Recaps]
首先，只要你给了玩家真正的资产所有权，开放市场 (Open Market) 就一定会冒出来，堵也堵不住。别幻想搞围墙花园，那只会逼着玩家走灰色市场 (Gray Market)。真正有价值的“拥有”，得看物品的交互能力 (Affordance)，比如一把武器不仅好用还能卖钱，这才是网络效应。开发商管不了价格，得让玩家自己决定价值，参考《EVE》那些经典例子，`宏观经济 (Macro Economics)` 的健康度比单纯的留存率更复杂，一旦失控全服崩盘。

最后，用户体验 (User Experience) 决定生死。Web3 现在最大的坑就是操作摩擦，签交易、连钱包太恶心。Shrapnel 的做法是给普通玩家默认开托管钱包 (Custodial Wallets)，他们在后台跑链，玩家只管打游戏。新人不用先买币，玩的过程中积累资产再变现。经济模型要用 Machinations 之类的工具提前模拟，防止新玩家涌入导致通胀，或者旧玩家跑路导致通缩。只有把链上体验伪装成无缝连接，才能真正让链上资产发挥价值，实现自由 F2P 入场。

技术上怎么整？这活儿可不像普通版本更新那么简单。为了不影响正式玩家，他们开了一个独立的 Steam 测试分支 (Steam Beta Branch)，把主游的线上服和研究版完全隔开，防止代码污染或 Bug 连累到正式版。数据采集分两路走：基础的游玩时长、购买记录这种通用数据走 Azure PlayFab 做遥测数据 (Telemetry)；涉及隐私的问卷答案则加密直接发给学校用的数据库，开发商自己看不到原始敏感信息。为了让问卷不打断游戏节奏，设计团队把弹窗伪装成游戏里的 NPC 聊天框，有个专门叫“The Researchers”的虚拟角色提前发消息预告，减少突然切断视角带来的挫败感，这就是为了提升用户体验 (UX)。

最后几个避坑指南大家得记好。为了防止有人拿奖励刷数据，奖励用了限定皮肤，但为了平衡性承诺后期全服发放。另外，两个独立数据库的时间戳容易对不上，后来加了统一的事件 ID 和坐标本地化策略来解决同步问题。还有就是要小心 IP 授权问题，研究版直接把受限的 DLC 和第三方 IP 内容去掉了。最关键的经验是，别反复问同一个问题，否则玩家会因为厌烦直接弃坑。整个流程强调了透明度，比如最终用户许可协议 (EULA) 必须写清楚，性别选项要包容，确保玩家知情同意，这样才能在合规的前提下拿到高质量数据。

### Overview


### Content Summary
[TLDR]
游戏设计若能支持玩家建立成长型思维，不仅能提升留存，还能构建更坚韧健康的社区生态。

[Background]
两位心理学家指出，许多热门游戏隐含了支持玩家心理成长的设计。旨在解决玩家易因挫折放弃或社区有毒的问题，帮助开发者用心理学原理优化留存和社区健康。

[Recaps]
这段演讲的核心就是教咱们怎么用心理学概念把玩家变成“理想玩家 (Ideal Players)"。主讲人两位博士来自心理健康相关的非营利组织，他们发现那些叫好又叫座的游戏，背后其实都藏着让人愿意继续变强的设计逻辑。简单来说，如果能让玩家相信自己的技能能通过练习提升，而不是天生注定，他们就更容易在困难面前不头铁、不秒退。这比那种觉得“我就是个菜鸟”的“固定型思维 (Fixed Mindset)"强多了。这种心态在游戏里被称作“成长型思维 (Growth Mindset)"，配合上面对逆境的“坚毅 (Grit)"，能帮玩家建立情感连接，让社区氛围更健康。

为了落实这一点，演讲分析了《艾尔登法环》、《Hades》和《命运 2》这三个案例，总结出了五个关键设计要素。首先是降低“失败后果 (Consequences for Failure)"，别让死一次就亏得倾家荡产，像《Hades》那样把死亡做成推进剧情的必要环节。其次是给点直接的心理按摩，比如 NPC 告诉你“输赢都很正常”。第三是奖励“努力”而不是光看结果，比如做日常任务练新武器。第四是提供好的“反馈 (Feedback)"和支持系统，让队友互相夸或者给具体建议，而不是冷冰冰的数据。最后是明确传达“失败很正常”的期望，别让玩家觉得死了很丢人，要把挫败感当成通关必经之路。

最后还得提一嘴注意事项，别搞过头了。虽然有研究表明这些心态能帮助弱势群体，但不能忽略现实里的系统性障碍，游戏爽归爽，别让人觉得所有问题都能靠个人努力解决。对于开发者来说，actionable tips 很简单：限制失败惩罚、明确沟通成长、多鼓励尝试、给多种通关路子、允许调整难度。归根结底，设计不仅仅是做数值平衡，更是做心理建设，让玩家带着成就感离开，下次还想回来接着肝。

- **Speaker:** Justin Gary (Stone Blade Entertainment)

### Content Summary
[TLDR]
混合构筑游戏用算法生成独特卡组，打破传统集换式卡牌的付费壁垒与同质化僵局。

[Background]
传统集换式卡牌（Trading Card Game）面临高昂门槛和同质化危机，核心体验沦为数值攀比。演讲者旨在分享如何通过“混合构筑”模式降低门槛并重启收集乐趣，适合想创新卡牌机制的开发者参考。

[Recaps]
这演讲的核心是搞个叫“混合构筑游戏”（Hybrid Deck Game）的新品类。以前玩传统的集换式卡牌（Trading Card Game），要么钱包爆炸成为“资金陷阱（Money Sink）”买不起卡，要么开包前就被剧透没惊喜，还得费心整理一堆纸片。像《万智牌》这种神作虽然强，但新手很难入坑，老玩家容易变成光囤卡不玩游戏。演讲者提出新路子：把卡组交给算法“程序化生成（Procedural Generation）”，每张卡都是独一无二的数码编号实体，既保留了动手配组的乐趣，又避免了全服通吃的“最优解”，直接打破付费壁垒，让你买一包就能跟土豪公平对局。

设计上怎么让人看得懂上万个变体？他们用了“形容词名词系统（Adjective Noun System）”，比如“装甲”属性自带效果，不管名词是啥兵种，玩家一看名就懂底数，这叫理解成本可控。再加上部分手工设计的“经典设计卡（Holistic Cards）”，保证套路熟悉，让程序生成的大堆杂鱼不至于太抽象。为了不让乱生成的卡烂出天际，他们还搞了“索取与提供机制（Seek & Provide Variable）”，比如召唤僵尸怪必须牌组里先有僵尸，防止出现逻辑崩坏的废牌，确保单半副卡组也有基础玩法的可行性，这点比之前的随机生成要严谨得多。

技术实现上，实体卡印二维码连线上账号，打线下赛也能进数字排行，解决社区活跃度不够的问题，这叫做“物理 - 数字整合（Physical-Digital Integration）”。最骚的是数字版能追踪你的卡组表现，赢了还能给卡组升级，甚至根据胜负写专属剧情故事，这就把“收藏”变成了“养成”。不过在平衡性上得小心，随机太强容易让玩家觉得“非酋”或无聊，所以得限制强度范围，别让大家只盯着最强数值去冲卡。在混合模式下，稀有度不像 TCG 那样决定强度上限，因为大家卡面都不同，更多是看组合效果。

最后提到未来方向，得想办法让玩家买了新系列不会觉得自己旧卡贬值，而是旧卡有了新用法，避免“边际效应递减”。毕竟完全随机也有风险，有人会为了凑完美卡组一直肝，这违背了休闲初衷。这种模式就是用“无法完美定制”换取“无限的新鲜感”，适合那些受够了一刀 996 的传统卡牌开发商参考，毕竟谁不想开局买一包就能体验新鲜内容，而不是被迫 chasing meta 呢？

Q&A 环节大家问怎么玩，她说不需要特殊准备，明确的规则本身就能缓解恐慌。如果想在其他游戏里借鉴这种设计，别光抄流程，要看机制是不是鼓励诚实。就像《灵魂拷问》 (Loaded Questions) 或者《真心话大冒险》 (Truth_Or_Dare) 那样，不管是玩笑还是严肃，只要能引导人暴露软肋，就是好设计。这大概就是游戏作为一种社会交互载体的终极意义吧。

这课适合想做开源贡献但怕踩坑的游戏厂法务和制作人。主要解决“员工下班写的代码算谁的”、“怎么送出去不侵权”以及“如何维护公司口碑又不泄密”的痛点。

[Recaps]
开源界的大佬们其实早就算过账，99% 的项目里都有开源成分。为啥大伙都用？主要是图省事又免费，还能靠人多力量大修 Bug（Linus 定律 (Linus's Law)）。对咱们做游戏的，直接用现成的**开源软件 (Open Source Software)**，能少造一堆没用的轮子，专注好玩的内容就行。不过记住，代码摆在那儿没用，关键是有没有合法的**许可证 (License)** 授权。

最头疼的还是版权归属。你的代码到底是你的还是老板的？**知识产权 (Intellectual Property)** 默认归写代码的人，但上班摸鱼写的属于公司。加州有个 2870 条款说了，只有你用私人设备、下班时间、而且跟公司业务完全无关时，才可能算你个人的。但这界限太模糊，所以大厂基本都要签**贡献协议 (Contribution Agreement)**。千万别把公司的**商业秘密 (Trade Secrets)** 当成礼物白送出去，否则法务能跟你急眼。

最后就是操作层面的小心思。想给开源社区送补丁？先把代码洗一遍，看看有没有混着别人的**第三方许可证 (Third Party License)**。还有得选是送**Copyleft (Copyleft)** 那种必须回馈的，还是选**宽松许可证 (Permissive License)**。公司和程序员之间也得平衡好面子，是谁的名义提的 PR，功劳记谁头上。最好拉上法务和业务一起定规矩，别今天送了明天就不管了，社区可是看长期饭票的。

[Background]

[Recaps]
主讲人 Mark 开篇就直击痛点：传统的专用游戏服务器 (Dedicated Game Server) 架构太脆弱，单台挂了全崩，IP 还容易暴露挨打，而且 UDP (UDP) 通信各家都有套自己的逻辑，缺乏行业标准，搞起来全是坑。想要规模化支撑这类高交互游戏，光靠硬撑肯定不行，得找新路子。

最实用的功能在于两者的深度集成。Quilkin 可以直接读取 K8s 里的 Agones 信息，自动识别哪些游戏实例被分配给了玩家 (Allocation)，并动态生成对应的端点 (Endpoints)。这意味着路由逻辑完全独立于游戏进程，后台想改规则或者禁掉某个玩家访问都无需重启服务。现场演示用 Xonotic 跑通流程，P99 延迟极低，证明这套架构不仅灵活还能大幅降低运维复杂度，算是目前后端治理的一股清流。

第三，大品类也没凉透。尽管总有人唱衰，但像《Genshin_Impact》和《Lost_Ark》这样的 大型多人在线角色扮演游戏 (MMORPG) 依然能把西方玩家吃得死死的。关键是欧美市场对品质的接受度变了，加上开箱 (Loot Boxes) 监管趋严，迫使厂商更注重数值透明和公平性。未来像《Apex_Legends_Mobile》的失利提醒我们，IP 延伸不是万能药，而像撤离类游戏 (Extraction Games) 这种新兴亚种正等着被资本收割。说到底，对于中小团队而言，与其在红海里死磕，不如找准利基市场 (Niche Market)，把在线运营 (Live Operations) 做成精品，这碗饭才吃得住。

[Recaps]

第二步是亮出法律底牌，吓唬住那些觉得“法无禁止即可为”的老哥。现在欧美都有硬性规定，像美国的**通讯和视频无障碍法案 (Communications and Video Accessibility Act)** 早就开始实施了，连《Pokemon_GO》这种大厂都吃过诉讼官司。别为了省点开发时间，结果被起诉赔个底掉，得不偿失。第三步是谈文化影响，反驳“无障碍破坏游戏体验”的谣言。参考《The_Last_Of_Us》这类大作，加入辅助功能不仅不削弱挑战，反而能提供“赋能感 (Enablement)”，让玩家更有代入感。Jameil 提到自己做的是**用户体验设计 (UX Design)**，本质上就需要对用户负责，无障碍正是最极致的同理心体现。

最后几个实操建议挺实在。别指望一口吃成胖子，遇到“预算不够”就别硬推全套，先抓核心体验。如果是视觉障碍多，就优化音效引导。还有，营销上别吹“完美无障碍”，容易引火烧身，就强调“具备某某特定功能”。总之，这事儿不是光靠情怀就能成的，得把数据、法规和实际案例堆上去，让资方明白这是刚需，自然就不卡你的脖子了。

[Background]
开发者内部测试容易受“知识诅咒”影响，反馈失真且成本高。本文分享如何通过流程优化，让内部团队模拟真实玩家视角，弥补预算不足时的测试缺口，适合 UX 及制作团队参考。

[Recaps]

主讲人是育碧无障碍专家团队负责人，也是亲身经历过的残障人士。针对业界常把无障碍简单化成增加菜单设置的误区，分享如何把公平性融入开发全流程，而非事后打补丁，适合所有游戏开发者阅读。

[Recaps]
首先得换个脑子，别觉得加了个无障碍选项就是万事大吉。演讲者直言，这其实是种“适配 (Accommodation)”，就像强行安排人走侧门，反而让玩家感觉自己是二等公民。真正的无障碍 (Accessibility) 应该是像正门一样人人平等的公平设计。我们要警惕过度的同情心，不能因为好意就让设计变得居高临下。得用“同情心 + 知识 (Compassion + Knowledge)"来指导核心设计 (Core Design)，而不是拍脑袋给方案。

最后别忘了过程很重要，但心态更重要。别迷信 Web Content Accessibility Guidelines (WCAG) 那些网页标准，游戏互动更复杂。哪怕是小团队也能干，找社区玩家做用户研究 (User Research)，关注他们的生活体验而不是直接听需求。就像《马里奥卡丁车》或《舞力全开》，把机制本身设计得包容，比塞一堆开关管用得多。记住，无障碍不是 QC 清单上的勾选任务，而是一种持续迭代的习惯。

### Content Summary
[TLDR]
别光信玩家嘴上的评测，用生物特征数据抓潜意识反应，才能给游戏调优和自适应设计提供最硬核的证据。

[Background]
现在的 QA 测试光靠问问卷，玩家容易装或者记不住，根本不知道“为什么难玩”。这次 GDC 邀请的是学术和大厂研发，专门聊聊怎么用电流、心跳这些生理指标，去客观验证 VR 和 AAA 大作里的真实玩家情绪。

[Recaps]
传统调查方法有个硬伤，就是只能听到玩家事后编的故事，没法捕捉瞬间的真实感受。**生物特征 (Biometrics)** 能直接读取潜意识，比如用**心变异性 (Heart Rate Variability)** 判断压力大不大，靠**眼动追踪 (Eye Tracking)** 分析注意力在哪，还能用**皮肤电反应 (Galvanic Skin Response)** 测手心出汗反映兴奋程度。有时候玩家觉得自己挺放松，其实心跳早就乱套了，这些数据能补上主观报告的漏洞。

工具方面已经没那么科幻了，Unity 里有现成插件能直连心率带，VR 头显本身也能塞传感器，省得挂一堆线影响体验。特别是在**扩展现实 (Extended Realities)** 环境里，结合头显自带的眼动追踪，能知道玩家具体盯着哪看，再对应情绪曲线，就能精确定位是哪个物体或场景让玩家产生了恐惧或喜爱，比笼统打分强多了。

Eidos 在《银河护卫队》里的实测最说明问题，他们把心跳、人脸表情和视频对上了时间点。结果发现有些战斗高潮玩家脸上没笑没怒，但皮肤电反应飙升明显，这种无意识的紧张感光靠采访是挖不出来的。当然也有坑，比如卡 BUG 时的惊吓表情得人工过滤，还得签隐私同意书，毕竟这是敏感的个人健康数据。

聊到最后大家关心的隐私和同步问题，这类数据确实比日志文件更敏感，得按 GDPR 走流程，确保用户授权。技术上难点在于信号延迟不同，比如皮肤电信号比视觉刺激慢好几秒，现在推 Lab Streaming Layer 这种协议就是为了统一时间轴。总的来说，生物识别不是要取代传统研究，而是作为一把标尺，帮你找到玩家自己都说不出来的体验瓶颈。
