## Running Supply Chains is Like a Massively Multiplayer Online Game
- **Speaker:** Michael Hugos (Center for Systems Innovation)
- **Duration:** 23 分钟
- **Category:** Game IT Summit
- **Video Page:** https://www.gdcvault.com/play/1015782
- **Slide Page:** https://www.gdcvault.com/play/1015476
- **Custom ID:** 1015782

### Overview


### Content Summary
[TLDR]
供应链本质是大型多人在线游戏，用透明数据与游戏化规则能彻底解决“牛鞭效应”。
[Background]
针对企业供应链信息滞后导致的牛鞭效应痛点，指出传统商务协作过于保守。适合关注效率的从业者，通过游戏化思维打破数据孤岛，实现多方协同降本增效。
[Recaps]
这老哥直接给供应链下了个新定义：它就是个大中型的多人在线角色扮演游戏 (MMORPG)。他讲自己当年给星巴克供红纸杯时遇到的坑，甲方要求 90 天内把库存砍掉一半，否则就换人。那时候大家都各自为战，信息不互通，典型的牛鞭效应 (Bullwhip Effect)，终端销量一点点变动传到工厂嘴里就变成长颈鹿脖子那么长。结果小仓管不敢决策，宁愿亏本空运也没货，场面一度非常尴尬。他也吐槽过商界其实很排斥“游戏”这个词，怕被觉得不严肃，但他坚持说互动模拟本质上就是游戏。

最后是怎么翻盘的？他把管理过程做成了一场游戏。以前全是 Excel 加邮件沟通，数据版本满天飞。后来他搞了个中央数据库，把所有环节的数据统一清洗后分发给各路人马。最骚的操作是搞了个实时积分榜，把完美订单率 (Perfect Order Rate) 当成绩，达标发绿星，低于 80% 挂黄脸。虽然听着土，但这招让所有人透明化了，谁也不许藏着掖着。本来是一堆互相算计的供应商，瞬间变成了同一个战壕的队友。

技术上他特别强调“简单即正义”。市面上 80% 的企业还在用传真和邮件管几千万规模的生意，真正的巨头占不了多少比例。所以他不做那种臃肿的系统，底层只封装了四个基本对象：设施、路线、车辆、库存。配合谷歌地图的 API，直接就能拉出来看物流走向。现在的 UI 甚至借鉴了即时战略 (Real-Time Strategy) 的设计，以后能直接在地图上跑模拟。

总结下来核心就一点：复杂的算法配不上垃圾数据，不如简单逻辑配准数据。他引用了经典的老话“垃圾进垃圾出 (Garbage In Garbage Out)”当头棒喝，指出大多数供应链还在用 Excel 和邮件，真正的巨头投入再多硬件也救不了烂数据。所以他主张简单逻辑配准数据，哪怕是小作坊也能跟上巨头的节奏。这不是什么高深理论，就是把企业协作当成一款联机游戏来运营，谁先建立信任和信息流，谁就能赢下整个市场。未来 UI 会更多参考游戏设计，让管理者像指挥即时战略一样轻松。

## More Than Fun: Designing Games With Purpose
- **Speaker:** Phil Stuart (Preloaded)
- **Duration:** 25 分钟
- **Category:** Games For Change
- **Video Page:** https://www.gdcvault.com/play/1015632
- **Slide Page:** https://www.gdcvault.com/play/1015394
- **Custom ID:** 1015632

### Overview


### Content Summary
[TLDR]
好游戏得有内核，Phil 强调让内容驱动设计，寓教于乐的核心是必须保证好玩。

[Background]
伦敦工作室 Preloaded 专接教育类单子。痛点是这类游戏要么太说教要么没趣。Phil 分享实战经验，教大家怎么把硬核知识塞进好玩的游戏里。

[Recaps]
Phil 这老哥说话很实在，他引用 Raph Koster 的话点破了个理：好作品都得围绕一个核心主题，主题和机制得像透镜一样聚焦那件事。Preloaded 虽然做的是非商业的《委托》 (Commission)，但他们认为最好的游戏也能是教育的。做《游戏设计》 (Game Design) 最忌讳的就是内容与玩法打架，得让玩法去体现内容本质。他们有个经典坐标，横轴是内容深度，纵轴是《游戏性》 (Gaminess)。很多同行做《教育游戏》 (Educational Games) 容易翻车，就是因为硬塞知识点，限制了玩家自由，结果数据掉到红线以下，根本不好玩。

为了解决这个问题，Phil 总结了四种构建思路。第一个是用《隐喻》 (Metaphor)，比如《WonderMind》拿爱丽丝梦游仙境当壳，把看不见的大脑神经元连通比作走森林小路，新手也能秒懂。第二个是《模拟》 (Simulation)，像《LaunchBall》，直接建个物理沙盘，玩懂了导电传热就能过关，这叫“通过玩耍掌握”。第三个是《抽象》 (Abstraction)，针对心理创伤这类敏感题材，把直白的说教藏进休闲规则里，降低戒心。第四个是《叙事》 (Narrative)，把史实包装进战棋里，靠真实感和剧情吸引人主动学。

最后给了几条实用建议：早点抓住内容里的闪光点并保持住；目标定多少就喂多少料，别贪多；内容是设计师的骨架，不是补丁；千万别忘记最终目标是让用户爽。这套逻辑不光适合小团队，大厂做 3A 也能参考，关键得跟客户和用户搞好关系，把反馈闭环跑起来。

## How Designing for Love Can Change the World
- **Speaker:** Scott Brodie, Martin Hollis, Chelsea Howe, Mitu Khandaker, Jane McGonigal, Michael Molinari, Jane Pinckard (Heart Shaped Games, Zoonami, Social Chocolate, The Tiniest Shark Ltd, Social Chocolate, Namco Bandai, UC Santa Cruz)
- **Duration:** 57 分钟
- **Category:** Games For Change
- **Video Page:** https://www.gdcvault.com/play/1015750
- **Slide Page:** https://www.gdcvault.com/play/1015467
- **Custom ID:** 1015750

### Overview


### Content Summary
[TLDR]
别再只造杀敌机器了，把爱放进玩法里，用互动对抗冷漠，才是游戏改变世界的正经路子。

[Background]
GDC 通常都在聊技术变现，这场演讲反其道而行，专门讨论“爱”。核心痛点是行业沉迷战争与零和博弈，忽视情感连接。适合所有想做出打动人心的游戏的开发者。

[Recaps]
主讲人首先提出了一个扎心观点：冷漠（Indifference）才是爱的对立面，而不是恨。游戏界长期被数据指标绑架，大家只盯着留存率（Retention）和日活跃用户数（DAU），而忽视了情绪本身的价值。设计师 Chelsea 分享了她关于“社会传染（Social Contagion）”的发现，即一个情绪平均能影响六个人。他们通过一个简单的网页谜题原型，让玩家在解锁科学原理的过程中体验到善意，结果带来了远超预期的社区互动。结论很简单：当两个共享积极情绪的人一起玩游戏时，爱就产生了。好的游戏就是传递爱的载体，你设计的不仅是规则，更是人与人之间的情感纽带。

接着，多位嘉宾从历史和体验层面剖析了现状。Martin 指出电子游戏几千年来基本都在演“零和博弈（Zero-Sum Games）”，即一方胜一方负，甚至进化出了现代战争的缩影。他呼吁未来应该有“爱之游戏（Love Games）”。Scott 则用自己的项目《Hero Generations》现身说法，他把个人生活中的两难抉择——追求事业 fame 还是家庭幸福——融入了游戏机制。他发现，当设计者把自己真实的脆弱感放进去，玩家才会产生共鸣。这种将现实经历抽象为规则的过程，比单纯模仿现有商业大作更有力量。

最后是关于具体实现与未来的探讨。Michael 的作品《The End of Us》证明了即使没有脸孔的星球，也能通过简单的 AI 行为逻辑（AI Behaviors）建立起跨越生死的深厚羁绊。Mitya 则建议把游戏当作探究爱情的实验室，利用可重玩性去模拟复杂的人际模型。虽然 Q&A 环节大家吐槽了风险投资（Venture Capital）不懂女性向游戏、主流市场仍偏保守，但共识很明显：独立游戏（Indie Studio）和游戏黑客松（Game Jam）是让这些大胆想法存活的空间。只要能让玩家感到被理解，哪怕是小众的题材，也有机会改变世界。

## Game Structured Hiveminds: Organizing People & Solving Problems with Fun
- **Speaker:** Evan Brown, Joe Edelman, Ben Sawyer, Jerome Waldispuhl (Entertainment Technology Center, Citizen Logistics, Digitalmill, McGill University)
- **Duration:** 59 分钟
- **Category:** Game IT Summit
- **Video Page:** https://www.gdcvault.com/play/1015785
- **Slide Page:** https://www.gdcvault.com/play/1015478
- **Custom ID:** 1015785

### Overview


### Content Summary
[TLDR]
游戏不该只为了玩，得变成能干活的生产力工具，让普通人利用碎片时间帮科学家、企业和 AI 解决实际问题。

[Background]
过去严肃游戏（Serious Games）部署太难像石油倒水，而游戏化（Gamification）又太肤浅。这场会想打通两者，探索游戏如何嵌入现代 IT 体系和真实生活场景，帮助开发者理解如何让游戏产生实际社会价值而不仅仅是消遣。

[Recaps]
主讲人本·索耶一上来就泼冷水说别纠结为什么要用游戏，而是思考怎么做。他批评传统严肃游戏像孤岛软件，跟企业的信息科技架构完全兼容不了；而单纯的游戏化往往只在屁股上挂俩金牌 badge，全是形式主义。他主张未来的方向是结合云计算（Cloud Computing）、移动端和开放数据，把游戏设计融入到大公司和个人的工作流程里，不管是处理供应链还是管理个人兴趣，都得让玩家感觉自然，而不是强行打断生活去玩游戏。

杰罗姆分享了他们的作品 Phylo，这是个把基因测序比对变成拼图游戏的典型例子。大家都知道生物学家要处理海量 DNA 序列，电脑算不准的时候人类眼力更好。这就是公民科学（Citizen Science）加具有目的性的游戏（Game with a Purpose），玩家打怪升级，科学家拿到了精准数据。项目上线后很多人匿名参与，证明不用非得逼着大家注册账号才能调动这种免费劳动力，而且现在还能在手机和平板上玩，随时随地贡献智慧。

乔伊带来了更落地的现实世界工具，他们公司叫市民物流（Citizen Logistics）。搞了个叫 Ground Crew 的系统，能像即时战略（Real-time Strategy）一样指挥街上的人发短信接任务，比如环保清理或者社区互助。还有个脚本语言 Cmo，能让不懂技术的人也编写现实活动流程，比如在展会上安排陌生人见面。这套逻辑就是把线上游戏机制搬到线下物理空间，连接同事、朋友甚至是路人，解决了现实中的社交和组织难题。

最后埃文介绍了怎么用廉价众包训练人工智能。他们团队太小预算有限，没法搞线下测试，就直接上了亚马逊的机械土耳其人（Amazon Mechanical Turk）平台。发了几个小游戏原型，比如迷宫（Labyrinth），给点钱让陌生人玩并记录行为数据。结果发现给小额激励金（Tipping）比干巴巴填问卷有效多了，玩家愿意反复挑战拿高分，最后靠这些数据喂出来的 AI 能 80% 预测玩家下一步动作。这就告诉我们，只要设计得当，游戏就是最好用的数据采集器。

## Game Mods as an IT Resource for Getting Things Done
- **Speaker:** Walt Scacchi (Center for Computer Games and Virtual Worlds, UC Irvine)
- **Duration:** 25 分钟
- **Category:** Game IT Summit
- **Video Page:** https://www.gdcvault.com/play/1015708
- **Slide Page:** https://www.gdcvault.com/play/1015442
- **Custom ID:** 1015708

### Overview


### Content Summary
[TLDR]
利用游戏模组技术快速构建企业流程原型，以低成本高互动方式解决员工培训与风险模拟难题。

[Background]
大型企业在 IT 部署时面临开发周期长、成本高的问题。演讲者展示如何借壳现成游戏进行二次开发，将复杂的业务流程转化为游戏机制，为教育和企业培训提供可持续的创新方案。

[Recaps]
大老板们想要的不是一时热乎的**游戏化 (Gamification)**表面文章，而是能真正落地的可持续方案。我们团队发现，与其从零开发一套笨重的企业软件，不如直接用现成的**游戏模组 (Mods)**来实现。比如跟奥兰治郡科学博物馆合作，他们把原本枯燥的科学展览变成带传感器的互动游戏，孩子们在里面做任务收集数据，这项目成功后直接带动了六千万美元的硬件改造投资，说明路子走对了。

最硬核的还是 Intel 半导体工厂的案例。芯片生产线每分钟停摆就损失百万，新员工穿防护服从那叫复杂，稍有不慎就会泄露像砷化镓这样的致命化学品。我们拿**虚幻竞技场 (Unreal Tournament)** 这种 FPS 游戏改模，把枪口换成化学传感器，把穿衣步骤变成闯关关卡。结果一个本科生就能在几个月内搞定，还能跟企业的老式数据库对接。这种用现成框架做原型的方法，让原本需要大量人力开发的培训系统变得又快又便宜。

要想在企业界玩转这个模式，有几个坑得注意。首先是**领域分析 (Domain Analysis)**，得先把生意逻辑翻译成游戏语言，搞清楚谁是玩家、流程咋跑。其次是**模组修改 (Modding)** 能力，别总想着重写代码，能改旧就改旧，节省时间。最后别偷懒，要是真要长期商用，得用商业授权的**软件开发工具包 (Software Development Kits)**，不然后期维护绝对会让你崩溃。总之，游戏不只是娱乐，理解业务逻辑后它就是高效的仿真器。

## Entertaining the Enterprise: Helping You Level Up & Conquer Work
- **Speaker:** Ian Bogost, Li-Te Cheng, Jennifer Michelstein, Alexander Moore (Georgia Institute of Technology, IBM, Microsoft Office Labs, Baydin, Inc.)
- **Duration:** 53 分钟
- **Category:** Game IT Summit
- **Video Page:** https://www.gdcvault.com/play/1015693
- **Slide Page:** https://www.gdcvault.com/play/1015432
- **Custom ID:** 1015693

### Overview


### Content Summary
[TLDR]
企业级游戏化不是让工作变好玩，而是通过游戏机制降低阻力，核心在于让工具更好用且不影响效率。

[Background]
大家总嫌企业培训枯燥、办公软件难用。这三位分享者演示了如何植入游戏化思维改造工具，让员工主动提高效率而非抵触，适合大厂内部工具及 B 端产品经理参考。

[Recaps]
微软团队在做办公游戏化 (Gamification) 时发现不能给用户太多选项，否则用户直接流失，这叫 (Reduce Choice)。原本设想分阶段给分培养习惯，结果用户觉得自己老拿满分有挫败感。后来改为一次性给足奖励加正向反馈 (Positive Feedback)，并保留开发组低估的趣味动画，效果大反转。这说明设计组得跟着实际测试出的乐趣走，别闭门造车。

IBM 研究员强调企业整合得看三方面：针对人的动机和文化，针对工作的产出度量，以及底层的控制技术栈 (Technology Stack)。他提醒别为了迎合客户把产品做成传统软件的翻版，失去趣味性；也别太激进用不兼容的内网技术。关键是找到平衡点，既能让系统跑通，又能保留设计初心，必要时甚至要跟甲方博弈，确保这玩意儿是个有趣的创新而非代码堆砌。

做邮箱游戏的初创公司更是经历过山车。起初界面丑但红屏警报能逼人干活，加了复杂剧情后用户嫌烦。最终明白核心是工具得先好用，于是砍掉花哨内容，只保留可视化的进度条和节省时间的统计 (Time Saved Graph)。“笑脸”情绪反馈比枯燥积分有效。他们还废掉了排行榜 (Leaderboard)，因易被刷数据机器人破坏。结论很明显：企业应用首先是靠谱工具，其次是游戏，本末倒置只会死得很惨。

## Battlestorm: Games as a Powerful Tool for Community Engagement
- **Speaker:** Jessica Goldfin, Scott Hoffer (Knight Foundation, Zynga New York)
- **Duration:** 30 分钟
- **Category:** Games For Change
- **Video Page:** https://www.gdcvault.com/play/1015803
- **Slide Page:** https://www.gdcvault.com/play/1016340
- **Custom ID:** 1015803

### Overview


### Content Summary
[TLDR]
非营利组织可通过资助专业游戏设计，将严肃议题转化为实体竞技体验，以此有效动员社区居民解决问题。
[Background]
卡特里娜飓风后公众防灾意愿低迷，NGO 通常缺乏游戏设计资金。本演讲分享骑士基金会如何投入重金，利用专业游戏设计动员青少年，提升社区韧性。
[Recaps]
骑士基金会觉得光砸钱不行，得靠好玩的东西把人吸引过来。他们花了五十来万，跟团队一起做了个叫 Battlestorm 的实体运动游戏。简单说就是类似躲避球和篮球结合，一方演居民拿物资跑分，另一方演台风拦截。这游戏主打**非对称对抗 (Asymmetrical Gameplay)**，把“带手电筒、收音机”这些防灾装备做成了游戏里的特殊技能，让大家边玩边学怎么备灾，而不是干巴巴上课。

做这玩意儿最难的是怎么让玩家说了算但又不能乱。他们找心理专家问能不能让孩子互相对抗，结果专家说不行，怕勾起创伤回忆，最后改成孩子联手打“真人台风队”（海军工程兵扮演的），这就有了大卫歌利亚般的戏剧感。过程中孩子们甚至自己改了标志设计，还琢磨怎么利用规则赢比赛，这说明他们真入戏了。虽然线上提交照片环节因为有人刷分失败了，线下活动效果却炸裂，孩子们回家跟爸妈讨论防灾的几率直接翻倍，甚至连红十字会都开始聊合作了。

这里头最大的经验就是别想着游戏是万能药，但绝对是好帮手。基金会的教训很实在：钱得花在刀刃上，比如前期多投点钱找专业**游戏设计 (Game Design)**，比后期改错强；还有评估不能只看报告，要像**敏捷评估 (Agile Assessment)** 那样随时调整。哪怕有些机制被玩家钻空子，只要核心体验爽，大家为了赢主动去研究规则，这就是好事。最后他们发现这不仅是游戏，更是社区重建的粘合剂，能真正帮人们走出灾难阴影。

- **Speaker:** Jan L. Plass (NYU / Games for Learning Institute)
- **Duration:** 30 分钟

### Content Summary
[TLDR]

[Background]
美国学生成绩下滑，学校搞不定个性化教学，游戏本可补位却常沦为枯燥课件。本文旨在分享如何用商业大作的逻辑重构教育游戏，解决“好玩不好学”的行业痛点。

[Recaps]

最后总结一下，这行要想干得长久，得靠专业分工。别搞那种老师拿着课本硬改代码的蠢事，那是自杀式开发。正确姿势是：教育专家先画好框框（你得掌握啥能力），游戏策划在里面想办法怎么玩得有意思。像《传送门》这种商业大作其实就是个好榜样，玩家在玩的过程中不知不觉就把逻辑和物理给学了。虽然网上有人吹嘘能搞潜意识教学或者全靠手机平板就行，但目前看还没啥神技，毕竟真正的知识迁移还得靠脑子自己想明白，光靠按按钮肯定不够劲。

- **Speaker:** Michael Kim, Nicole Lazzaro (Kairos Labs, XEODesign)
- **Duration:** 32 分钟
- **Category:** Games For Change
- **Video Page:** https://www.gdcvault.com/play/1015709
- **Slide Page:** 
- **Custom ID:** 1015709

### Overview


### Content Summary
[TLDR]
别光想着让用户坚持打卡，高手都利用游戏机制把玩法变成改造现实的“生态机械系统”，让乐趣驱动真实改变。

[Background]
传统企业健康项目用户留存极差，基本都在及格线徘徊。演讲者来自微软 Xbox 和知名游戏工作室，专门研究怎么用心理学搞定“长期行为”。他们想告诉 devs，别光做短期刺激，要设计能持续百日以上的习惯养成系统，甚至让游戏里的行为能反过来改变现实世界。

[Recaps]
干这行首先要懂点心理学底层逻辑，不能光凭感觉瞎搞。真正的成功标准很简单：行为改变游戏得让玩家坚持超过 100 天，而不是昙花一现。这里有个核心模型叫**福格行为模型 (Fogg Behavior Model)**，简单说就是成事儿得凑齐三样东西：**动机 (Motivation)**、**能力 (Ability)**和**提示 (Trigger)**。别总想着给玩家灌鸡汤提热情，最容易上手的是降低门槛（提高能力），比如每天只需一次点击。还有个关键点就是**提示 (Trigger)**，比如每天早上 7 点的邮件提醒，利用用户已有的生活节奏去带动新习惯，这才是王道。

第二块硬货是**即时反馈循环 (Timely AHA Feedback Loops)**。现在这事儿离不开**移动端 (Mobile)**，手机随时在手，推送通知就是最好的暗示。演讲里举了耐克跑步的例子，你在跑的时候耳机里能听到朋友的加油声，这就是实时的正向激励。还有瑞典那个测速彩票游戏，不超速就有机会分钱，把枯燥的规矩变成了有趣博弈。重点不是单纯记数据，而是要让玩家感受到行为带来的意义，否则很容易弃坑。

再往上走一层，就是看怎么让用户觉得有意义。专家提到了马丁·塞利格曼提出的**幸福五要素 (PERMA)**框架，其中人际关系和意义感最重要。就像戒烟互助会或者团队骑行队，大家在一起奋斗的感觉比拿个虚拟奖杯实在多了。设计师还得想想玩家想成为谁，别总把玩家当苦哈哈搬砖的蚂蚁，游戏应该是那只聪明的角色，帮玩家找到工作的意义，而不是强迫他们为了生存硬撑，**趣味 (Fun)**才是根本。

最后聊聊大愿景，未来的行为改变游戏不能只停留在“输入数据”上，得能“输出结果”。现在的趋势是做**生态机械系统 (Eco-Mechanica)**，比如新作《Tilt World》，玩家在屏幕里清理垃圾、种树，攒下的分数真会在马达加斯加种下真实的树木。这种让虚拟努力变成现实价值的闭环，才是下一代游戏的杀手锏，毕竟让系统变好玩，比逼用户变自律要管用得多。

欧洲市场不做本地化 (Localization) 就是送人头，数据证明这不仅是态度更是决定生死的关键。

[Background]
这场对话专门讲欧美发行难点，适合想出海的中国游戏厂看看，毕竟光靠英文版本早就行不通了，必须理清利益和风险点。

[Recaps]
数据是最硬的道理，尤其是移动端和社交游戏。一旦完成**本地化 (Localization)**，特定地区的下载量可能激增 30% 至 60%，**变现 (Monetization)**能力提升近四成，**投资回报率 (ROI)**非常可观。对于主机游戏来说，欧美核心玩家习惯买断制，要求像电影一样的全语音体验，不做到位很难卖出价钱，通常涉及 3A 级别的大作 (AAA Titles)。

欧洲不是单一市场，每个国家的**知识产权 (IP)**法律和文化口味都不尽相同。比如隐私法规、音乐授权都很敏感，所以光有翻译不行，必须找靠谱的**本地化供应商 (Vendors)**进行深度整合。像《星球大战旧共和国》这种 IP，连名字翻译都要跟几十年前的电影保持一致，否则就是侵权风险，必须小心合规雷区。

现在的策略已经从“做完再翻译”变成了“边开发边本地化”。参考影视工业的配音标准提高质量，同时利用自动化工具应对高频更新。有些公司尝试**社区本地化 (Community Localization)**，让用户协助翻译来降低成本并增强粘性，但这需要严格审核。未来竞争加剧，不仅要保证**下载内容 (DLC)**跟进，还要打通网站、APP 多端体验，防止因版权或质量差异导致市场割裂。

## Audio Localization Done Right: Simultaneous Scripting and Recording
- **Speaker:** Masaharu Shibayama, Hikaru Taniyama (Square Enix, Square Enix)
- **Duration:** 57 分钟
- **Category:** Localization Summit

### Overview


### Content Summary
[TLDR]
针对 AAA 游戏多语言同步发售难题，SE 通过自研 Moomuri 工具打通声画与翻译壁垒，实现高效协同。

[Background]
大项目多语言同步发售 (SimShip) 已成标配，但本地化常沦为“补丁”，与开发不同步导致资源浪费。SE 结合 FF13-2 实际痛点，分享如何通过定制工具打破部门墙，保障全球同步质量。

[Recaps]
这事儿的大背景就是现在很多大厂都在搞全球同步发售，但在实际落地里，音效组和翻译组经常是两张皮。SE 这边做 FF13-2 的时候踩了大坑，开发组里程碑总是飘忽不定，今天录好的词明天可能就删了或者位置变了，导致录音棚和外包翻译天天加班改文档，根本不知道上下文啥时候会变。这种信息孤岛最后搞得全员崩溃，口号叫“我受够了”（Moomuri），正好用来命名那个救命的工具，核心就是要把大家拉到一个频道上干活。

解决思路很简单粗暴，就是别再用邮件传文件了，得搞个统一的对话编辑工具 (Dialogue Editor)。这个叫 Moomuri 的工具把所有语言数据都存服务器共享，谁改了哪里一目了然。底层其实是用 XML 和二进制混合管理数据，利用 Subversion 这类代码库做后端支持多人同时操作。比如原本日文增加了台词，系统会自动标记变更，而不是靠人工去猜哪句变了。里面还带剧情查看器，能看到过场视频，甚至能把参考动作捕捉 (Motion Capture) 录像放进来，让翻译知道这说话的人是不是在打架还是聊天，避免语气翻错。

实操细节上，SE 把内部和外包分开对待。内部员工直接在工具里干活，能实时听语音对节奏；外包翻译权限不够就给导出 Excel，填完再导回来，这样既保护数据安全又兼顾效率。最关键的是状态追踪，每句话都有状态栏，是新增、删除还是修改，翻译确认了才能过关。虽然不能全自动识别所有变动，但至少保证了每个节点人都清楚，不用像以前那样对着满屏幕的文件头秃。

最后总结点挺实在：别把本地化 (Localization) 当成最后的修补工作，它得嵌入整个开发流程 (Workflow) 里，成为生产管线的一环。哪怕你没法像 SE 这么堆人堆钱，至少也要把沟通渠道打通，别让信息差拖慢进度。现在的工具还没做到全网页版支持远程办公，这也是未来要改进的方向，毕竟云协作才是大势所趋，大家还是得往“一个平台搞定所有事”的路上走。

- **Category:** Game IT Summit

### Overview


### Content Summary
[TLDR]
拒绝说教，用游戏化机制将青少年闲置物品互换转化为对抗快时尚的社交动力。

[Background]
面对开发成本高且难以触达“非玩家”的困境，Inensu 尝试打造轻社交产品，引导年轻群体改变消费习惯而非单纯宣传。

[Recaps]
这篇帖子主要聊聊 Inensu 工作室怎么靠**游戏化 (Gamification)** 把环保这事儿做得接地气。他们一开始研究才发现，虽然 kids 都喊着要环保，但对于**快时尚 (Fast Fashion)** 还是真上瘾。调研有个神转折：少年们嫌弃二手店掉价，但超喜欢跟闺蜜借衣服穿。这就抓到了痛点，直接把“借衣服”变成核心玩法，而不是在那硬讲大道理。

产品构建上，团队非常务实。基于**Facebook**做底层，主打本地熟人社交，本质是**共享消费 (Collaborative Consumption)** 理念，避免复杂的物流。拍照上传特别简单，能直接用摄像头或者同步脸书照片，搜索界面模仿 Google 图片，谁看谁都懂。手机端还有个**社交机制 (Social Mechanics)** 拉满的功能叫“时尚 SOS"，看到喜欢的别急着买，拍张照发群里问谁能借，这一招既省了钱，又在朋友圈里病毒式传播了。

最关键的还是激励体系咋设计。他们没用积分换优惠券这种俗套路子，因为这会诱导购物，跟初衷背道而驰。积分改成 Kudos，徽章也不按等级死磕，而是根据用户的风格标签配，名字还起成流行歌星名，比如 MIA、Rihanna 这种，这才对味。总之就是，别总想着教育用户，得顺着他们想装逼、想表达自我的天性去设计规则。
